# Changelog

## 1.0.0

### Native core

- Pure ESM TypeScript library with declarations and zero runtime dependencies: native frequency indexing, exact/prefix/Boolean/scalar-equality queries, exact totals and deterministic field-local `raveldex-bm25-v1` ranking.
- Incremental atomic mutations, coherent revisions, immutable input ownership, finite resource/work/deadline limits, FIFO execution, cooperative cancellation and explicit disposal.

### Optional search and interface capabilities

- Preserve inline/modal result focus inside authored Shadow DOM, dismiss dropdowns from owned controls without changing native Tab destinations, retain directory paging/Retry focus through loading and recovery, and refuse rich-card mounts if option capture destroys their controller. Browser starters reject invalid display titles and blank modal section headings before generating output or transferring an engine.

- Selected source, positions/original offsets, strict source/position/mixed phrases, numeric/set filters, exact conjunctive facets, numerical Inspector facts, original match ranges and bounded grapheme-safe snippets.
- Explicit bounded typo tolerance, dictionary-backed token suggestions and one-step directional synonyms; ordinary queries do not enable these automatically.
- Explicit English Porter 1980 analysis and code/identifier components with original-only strict phrases.
- Raw case-sensitive literal/infix predicates, ordered proximity over selected original positions, and a bounded Boolean/field/phrase/prefix query compiler. Ordered leaves explicitly refuse token-range/snippet projection.
- Revision-guarded whole-field record patches over complete selected source, using the existing atomic replacement path.
- Native DOM UI with separate CSS, composition-aware search, facets/pages, error/retry, Inspector and authored-content restoration. Optional final-word prefix mode completes partial words and is the ordinary demo default; exact-word and strict-phrase modes remain available. Integrations retain the exact-word default, and the application retains engine ownership.
- Separate `/addons/ui/inline` consumer foundation with core-only linked-title results, prefix default, idle/clear/submit behavior, captured message overrides and optional `/addons/ui/inline.css` theme properties. It preserves legacy UI defaults and borrows its engine. Inline/modal Load more appends finite native batches until all matches are shown, retaining earlier rows without switching to Next/Previous windows. The deprecated `maxRenderedResults` option remains validated for compatibility and no longer limits accumulation. Explicit native snippet/filter capabilities, coherent revision recovery and expanded theme properties are available. Complete browser/Astro starters provide explicit content, CSS recipes, installed-package builds, loading/retry and ownership-safe cleanup, with source downloads and a working inline gallery preview.

- Optional `/addons/sections` evidence and inline heading previews preserve native page totals/ranking, original grapheme-safe text and explicit omissions. Revision-bound source maps, serialized context requests, stale/refused-context states and a separate source-only Astro companion are available without changing existing static formats, core, snapshots or worker commands.

### Known limitations

- Lexical/vocabulary gaps and English overstemming remain; the original judged corpus is not a general relevance guarantee.
- The full core exceeds the unchanged 15 KiB gzip planning target. Recorded sizes depend on the selected graph, tooling and compression runtime; serialized bytes are not retained/peak heap measurements.
- Admitted collections can exceed whole-source operation budgets. Unknown worker/storage outcomes require reconciliation or explicit new-owner recovery, not assumed rollback or automatic retry.
- Native snapshots require exact qualified Node environments; browser/worker native state is unavailable. Astro supports static directory builds, not SSR, development watchers or content crawling.
- UI transport errors have generic presentation. Earlier VoiceOver interruptions retain an unconfirmed cause; accepted normal-typing observations do not establish all-reader support or a required VoiceOver setting.
