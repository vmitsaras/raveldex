Public API reference

Start with Raveldex adoption and installation, then choose a consumer interface and its capabilities, or use core with your own UI. This page lists exact imports; the developer Workbench is separately identified below. Every JavaScript entry uses ESM and includes TypeScript declarations. Use the public paths listed here rather than importing from dist/ or src/. CommonJS is not supported.

Export map

Add @vmitsaras/raveldex before each subpath below. For example, /addons/ui means @vmitsaras/raveldex/addons/ui; the root entry is just @vmitsaras/raveldex. Importing a factory makes it available to call but does not enable its feature. TypeScript types are removed at runtime.

Choose the cost you need

Core stores the information needed for word matching and ranking, plus your declared equality metadata. Choose extra data only when you need it:

  • A source provider keeps the original text of selected fields.
  • A position provider keeps token locations. Select offset fields separately if you need original character ranges.
  • Core alone keeps neither original text, positions nor offsets.

Pass the registrations in Configuration.addons when creating the engine. To change providers later, create a new engine and rebuild.

Filters and facets read existing core metadata without adding another metadata index. Request Inspector or original match evidence only for searches that need it. The UI uses an engine you own and a display list you provide.

Set up workers, snapshots and storage separately. Importing core makes no network request, accesses no DOM, creates no worker, opens no database and starts no timer or automatic indexing.

Runnable examples use these public entries. Read compatibility for host requirements and practical limits for matching and recovery behavior.

Separate static-build package

Install @vmitsaras/raveldex-astro separately to build search files during a static build and load them on demand. It needs the matching core version and, for its build hook, the optional Astro peer. It is not an export of the core package.

Complete search interfaces

The solution chooser links five presentations and eight installed browser/Astro projects. Compare the explicit data/capability, loading and CSS requirements before copying one. Starter adoption explains shared query/paging behavior, keyboard recovery and ownership. Core and the UI remain separately selected; images, sections, URL replay and workers require their own explicit choices.

Installation and evaluation routes

Use Getting started for installation, Core for records and queries, and UI and host integrations for browser controls, workers and storage. If you prefer to learn by running code, start with the example modules.

The separately installable @vmitsaras/raveldex-english uses the same analyzer policy as the convenience subpath; choose one factory import. See English installation. The Astro integration is a separate package; see static search and Astro.
