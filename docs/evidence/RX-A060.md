## Implemented contract

`/addons/literal` exports `createLiteral`, `LITERAL_POLICY = 'raw-substring-v1'` and readonly options/payload/evidence types. Only an explicit `literal` v1 query leaf requests raw case-sensitive substring matching. Preserve punctuation, whitespace, case and combining marks without normalization, tokenization, stemming, accent folding or locale rules. Empty needles reject; one leaf never crosses fields or array values. Fields default to enabled factory fields; explicit subsets are validated and sorted. Punctuation-only source and matches inside tokens are searchable without lexical candidates.

Pure literal predicates score **0**, ordered by native UTF-16 record ID with exact totals/pages. Mixed AND/OR/NOT retains existing successful lexical groups/native BM25, with no count/length/location bonus. Literal eligibility reads the same originals under basic, English and identifier analyzers. Ordinary strings, token groups/phrases and unrequested optional behavior remain unchanged.

Separate `extensions.literal` evidence selects bounded IDs/facts/ranges. It returns all compiled leaf descriptors plus document eligibility and every overlapping original UTF-16 range from successful positive literal paths. NOT and failed Boolean branches provide no ranges. These are actual source string spans, not invented token positions or normalized offsets. Code-point boundaries remain intact; a raw match can divide a grapheme, including matching a combining mark alone. No token-snippet or UI presentation integration is introduced.

Core adds the disjoint `sourcePredicate` handle under its existing leaf-refinement role, compiled to an existing zero-group predicate. Immutable preparation context exposes only declared source dependencies, schema, limits, analyzer, revision and payload; tests receive opaque IDs. All core documents are considered. Configuration requires the exact enabled source-field dependencies and rejects extras; source-free configurations fail rather than pretend to support literal search. The state reader checks declared capability names over trusted immutable participant state; this is not a hostile-plugin sandbox or projection of each provider's internal root.

Explicit existing source providers own original retention and atomic revisions. Literal adds no corpus participant, n-gram index, accelerator, vocabulary cache or codec. Bounded KMP tables/cursors/evidence exist only within the search. One registration budget covers all leaves and evidence; shared operation work/deadline/cancellation and output bounds remain stricter. Stop checks follow trusted cursor advancement before module charging or accepting completion. No runtime dependency was added and `package-lock.json` is unchanged.

## Failures, review and boundaries

Independent protocol inspection identified **R1**, a source-only contract gap: extra declared non-source dependencies were permitted by generic capability access. Registration now permits only the exact enabled source-field requirements; regression/probe refusals confirm it. This was a static finding plus an executed repaired guard, not a fabricated pre-repair first-party leak. Existing metadata/token/evidence protocols retain their own contracts. The shared runner now checks stops immediately after callback advancement, including completion, before validating a returned predicate or charging a module overflow.

These were harness defects fixed at their source, without loosening assertions or product policy. The independent runtime reviewer corrected an expected zero score for a record whose original body actually contained the positive lexical word, and retained their setup syntax failure.
