## Implemented scope and contract

`core/execution/engine.ts` implements the real internal `createRaveldex` factory and ordinary `Raveldex` methods. Creation validates configuration synchronously and builds an empty revision-0 frequency root. Operational calls own bounded options/data synchronously and convert failures into typed rejected promises. Already-aborted calls skip data; closing calls skip data and options. Every query/write enters the same FIFO with one running operation and at most the configured waiting count (default 32; zero permits idle work).

Requests capture query/options independently from execution-start root selection. `addMany` uses the mutation owner's one budget across every record/core/participant phase. Stops are checked at charged steps/phase boundaries and immediately before result/commit, including tiny/no-op operations. Monotonic deadlines begin before admission capture and include queue time. Direct mode lazily binds a monotonic clock/timer host and yields actual tasks. Closing cancels suspended staging/continuations, rejects waiters, unregisters listeners/timers and releases the owned root; repeated disposal shares its eventual promise. A committed mutation remains successful during later abort/disposal/cleanup.

The private `ExecutionOwner` accepts trusted fixture roots, transaction participants, host handles and optional counted-work metrics. The ordinary factory exposes none of those injections or a mutable root. Query shapes, results, mutation results, limits and error-code contracts are unchanged. No package root entry/export, public participant registration, add-on, worker, persistence, release or N5 work is introduced. Package/real-document qualification belongs to RX-1006.
