# RX-9801 — Continuous Load more

Status: implemented and verified locally on 2026-11-12. The owner explicitly
selected append-only Load more through every match, superseding the capped
inline/modal window contract. Existing unrelated demo/header work is preserved.

## Implementation and contract

- The shared inline presenter requests only the next native `pageSize` batch,
  with offset equal to the accumulated count. Appending retains earlier DOM
  nodes, IDs, order and exact totals. Inline/modal create no Next/Previous
  replacement controls or window-limit message.
- Load more becomes unavailable only at exhaustion; its focused terminal control
  remains guarded until focus leaves. Go to new results still focuses the first
  newly appended title. Query/filter/clear/retry, revision checks, stale-work
  suppression, section serialization and borrowed ownership retain their rules.
- `maxRenderedResults` and old paging-message keys remain validated compatibility
  inputs, explicitly deprecated/unused. Removed obsolete cap options from the
  site and complete starters. New accumulation remains user initiated and bounded
  by the existing 10,000 display records, aggregate display-data admission and
  1–100-hit request limits; this is no memory/latency qualification.
- Updated the [selected contract](../planning/LOAD_MORE_APPEND.md), API/localization
  and modal/search specifications, starter instructions and changelog. Historical
  evidence remains historical; directory/cards/Workbench paging is unchanged.
