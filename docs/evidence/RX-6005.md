Date: 2026-11-01. Local implementation and automated verification under the [frozen page/section contract](../specs/PAGE_SECTIONS.md). ## Implementation

- Added the optional `/addons/sections` factory and nine specified readonly types. Complete native positive ranges select the first qualifying source-ordered sections, with original grapheme-safe clipped excerpts, null oversized excerpts and scoped omissions. Native membership, page BM25 scores/ties, totals and paging remain authoritative.
- Extended only the private optional evidence capture/presentation seam. Existing match/snippet requests retain their validation and output. The new factory owns no retained participant, source cache or section map; ordinary unrequested search work and existing retained roots are unchanged in the measured case. Core, snapshot formats and worker protocol are unchanged.
- Added inline `pageSections`/`maxSectionPreviews`, synchronous owned structural capture, encoded heading links, explicit context states, strict response validation and optional messages. One context request is in flight, only new batches are projected and a batch commits atomically. Replacement, clear and destroy suppress late work; destroy releases owned maps/results and leaves the borrowed engine usable.
- Added separate Astro companion files, parallel builder/hook input and explicit uncached source-handle `loadSections`. Source/display/configuration/ID/build bindings, transient receiving source validation, public revision probes, cancellation and disposal are enforced. Native section loading refuses before companion I/O. Existing v1 envelopes and safe directory routes remain unchanged.

## Bounds and measured costs

Exact native structural tests accept 10,000 mapped pages, 16,384 total sections, 64/page and an exact 4 MiB owned map, and refuse the next value. Static public build/load accepts all 16,384 sections in a 1,813,326-byte asset; over-collection, over-page and multibyte UTF-8 overage refuse. Source/descriptor, provider, payload, work/output, segmentation, stream and URL boundaries are exercised through their relevant layers. Fixed-shape/depth and multiplicative ceilings can be unreachable independently of an earlier bound; the 45 fixture axes are not 45 independent whole-operation capacity promises.

The packed UI executes a 105-page corpus: the default 100-parent window has 300 previews, the next five pages have 15, all 105 IDs remain reachable, and at most one context call is in flight. The existing controls regression separately passes the 1,000-parent cap with exact 1,005-record continuation. The maximum 3,000-preview/720,000-excerpt-unit/96,000-mark ceilings follow from that parent limit and the enforced 3×240/32 section limits. A combined 1,000-parent section stress attempt was deliberately stopped after 97 seconds; it is **not a passing maximum-capacity or latency result**. The durable new regression uses the verified default window.

For the measured `red red` case, ordinary search charges 583 logical work units; section search charges 3,279, of which 2,555 belong to the section role. The section extension has 58 structure entries and 761 serialized UTF-8 bytes. The unrequested factory preserves ordinary work and the sole existing `source` retained root. Exact observed role/output limits pass, while one lower refuses; the explicit serialized byte ceiling refuses a larger Unicode response without publishing partial context. These are logical/output observations, not physical memory or throughput measurements.

Installed minified ESM graphs: core 69,483 bytes / 20,296 gzip; section entry 40,468 / 11,400; inline 33,138 / 10,898; inline CSS 6,277 bytes. The core graph contains no optional implementation. Inline imports UI, structural map validation and bounded data/error utilities, with no engine/provider implementation. Independent full-entry sizes overlap and must not be added as application totals. The preexisting core planning-target miss remains disclosed.

## Review and intermediate outcomes

Native and Astro implementation owners reviewed each other's source independently. A separate final reviewer found one P2: contradictory omission flags could create a false “more context” notice. The validator now rejects provably contradictory window/highlight flags, null excerpts lacking complete oversized accounting and oversized counters covering in-window matches. The real hostile-reply regression, valid lower-cap cases and eight independent follow-up assertions pass. No unresolved finding remains from that review.

Initial consumer fixtures used an invalid prefix query shape and omitted UTF-8 metadata on Unicode destination pages; both fixture errors were corrected without weakening product assertions. An initial sandboxed Chrome launch was blocked by the host environment and rerun with the required local-browser permissions. The first integration run passed 829 main tests but caught the newly added omission-flag regression in the earlier compiled UI; that failed run is preserved. A clean rebuild and the full corrected check then passed. Intermediate capacity fixture setup errors and the stopped large stress attempt are not passing evidence.
