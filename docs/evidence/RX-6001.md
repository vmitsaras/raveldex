# RX-6001 — Consumer inline foundation

Date: 2026-10-30. Implementation and scoped automated foundation verification are complete; local documentation and planning are synchronized. This is the bounded title/link foundation, not the later complete inline solution.

## Implemented boundary

- Additive `/addons/ui/inline` entry with `mountRaveldexInline`, readonly `InlineUIOptions`/`InlineUIHandle`/`InlineUIMessages` and `UIDocument`; separately selected `/addons/ui/inline.css`.
- Core-only borrowed engine and owned display projection. Default prefix mode, zero-query idle/empty state, clear/submit, bounded first window, exact native total/displayed count, plain-text message overrides and retry. No required source/snippet/facet/Inspector/worker/storage state.
- Existing `/addons/ui` export, exact default and Workbench behavior remain intact. A small shared ownership map prevents conflicting presets on the same root; data validation, query construction and result validation reuse existing helpers without importing provider/engine implementations into the UI entry.
- Initial public CSS properties/classes, strict options, safe navigation/text, independent roots, original-node restoration and borrowed-engine disposal rules are documented in [HOSTS](../api/HOSTS.md#inline-search-foundation) and the [frozen contract](../specs/SEARCH_SOLUTIONS.md#rx-6001-frozen-foundation-contract).
- No core/scorer/snapshot/static artifact schema, dependency, lockfile, version/private guard or remote state changes. Full paging/Load more, snippets/facets and complete browser/Astro starters remain RX-6002/6003.

## Review and failure handling

Two inherited-routing subagents had disjoint responsibilities: one authored only the three new installed test/fixture/type files; one independently reviewed runtime/lifecycle/packaging/accessibility source without editing. The parent owned runtime/build/public contracts, integration, evidence and final acceptance.

The reviewer found that registering ownership after `replaceChildren` allowed authored custom-element disconnect callbacks to mount a detached competing UI. Both presets now register before host mutation with guarded rollback. The reviewer also identified focus recovery as a synchronous reentry boundary: inline invalidation rechecks ticket/destroy state after focusing input. The final targeted tests directly exercise both fixes. The new search form is named independently for multiple search landmarks. Review was source/test inspection; it is not a human assistive-technology observation.

The first generated-site check caught internal task IDs in user-facing usage prose; those were removed and output rebuilt. A later concurrent site run completed public navigation/search/lifecycle/reflow assertions with zero page errors/bad requests but timed out during cleanup, so it is retained as a failed run rather than a pass. Only that runner and its identified children were terminated; the pre-existing user preview was left running. The unchanged site tests passed serially without relaxed assertions or timeouts. This supports a tooling/concurrent-cleanup limitation, not a proven search defect. The [initial prose failure](RX-6001-initial-site.log.gz) and [concurrent timeout](RX-6001-concurrent-site.log.gz) remain preserved.
