# RX-9105 — Search states and recovery messages

7 November 2026. Baseline HEAD `0d18463` plus accepted uncommitted RX-9104 changes. This slice preserves that work and its evidence. All changes remain local/uncommitted; no commit, push, remote issue mutation, deployment or publication occurred.

## Implemented

Inline/modal and dropdown text-only empty feedback identifies the submitted query and offers the appropriate editing or full-results route. Filtered inline/modal empties name the selected filters and suggest changing a filter or Clear search and filters. Directory/cards distinguish text-only, filtered and empty browse results; empty browse makes the existing Refresh results action available for explicit activation. No background refresh or automatic query was added.

Query previews are safe plain text, trimmed and bounded to 160 Unicode code points plus an ellipsis; input and engine queries remain unchanged. Context comes from the submitted request or committed directory snapshot, never a newer draft. New optional `noResultsFiltered` (inline/modal/directory) and `noResultsBrowse` (directory) slots retain old complete bundles. Existing `noResults` overrides cover new variants unless individually overridden, and overrides are captured.

Failures use understandable Retry search / Refresh results language. Existing `{code}` overrides and typed directory snapshot errors retain diagnostics. Revision-change recovery stays distinct. Composing/searching wording is aligned, dropdown Clear now says Clear search, and existing waiting/debounce/announcement timing is retained. Focus, native result links, exact totals/order/ranges, paging caps, composition, stale-response suppression, borrowed ownership and teardown are preserved. No engine, provider, query-construction, CSS, dependency or export-map change belongs to RX-9105.
