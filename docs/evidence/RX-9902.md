## Review, adverse outcomes and limits

One fresh read-only reviewer found three Important defects. Each had a failing
real-browser regression before one fix pass: overly narrow comparison columns,
download accessible names missing visible wording, and imprecise feature/recovery
links. All three now pass; no Critical finding remains. The original reviewed
captures are retained under `review-candidate/`.

One Minor test-hardening follow-up is deferred: the request assertion checks the
local path prefix without checking origin. Current URLs and the actual recorded
requests are local; it could miss a future external host reusing that path prefix.
The five current source/published hashes and request origins were independently
inspected. This is not a claim that the deferred assertion has been fixed.

Initial sandbox loopback binding was denied; the strict preview/browser checks
then ran with approved loopback access. A capture-only assumption initially
waited for nine rich results although the fixture has seven records; it was fixed
by waiting for the actual results. A final-capture attempt waited on an offscreen
lazy image; only that capture process was stopped, and the script now scrolls
images into view before decoding. The boundary comparison initially included the
Workbench's shell HTML as a runtime asset; the legitimate CSS-link change was
separated from its unchanged installed runtime assets. No product/test acceptance
requirement was relaxed for these evidence-tooling corrections.

Human AT/speech-input operation, physical input, actual 200%/400% zoom, Safari or
other real devices, owner visual acceptance, real Jekyll/hosted Pages and npm
publication are **Not run/unselected**. Headless input, axe, emulation and captures
do not establish those claims. RX-9904 still requires the owner's explicit
rendered-pilot response after the separate RX-9903 slice.
