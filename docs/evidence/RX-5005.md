# RX-5005 — Final-word prefix search in the demo

Owner request: enable option 1 as the demo default, retain exact-word and strict-phrase modes in Advanced settings, and verify results, highlights, filters and pagination in direct and worker execution.

## Implementation and boundaries

Home and the ordinary usage demo now select optional UI `mode: 'prefix'`. Earlier basic Unicode words remain exact; the final word uses the existing native prefix query from two normalized Unicode code points onward. Shorter endings retain exact-word semantics. Empty controls browse all records; punctuation-only input matches none. Trailing spaces or punctuation do not disable completion.

The UI preserves raw slices for native analysis and validation, including leading punctuation and malformed UTF-16. It keeps the engine's expansion/work limits, exact totals, scoring, selected-source snippets and Inspector query. There is no new search engine, side index, runtime dependency or core API/default change. Integrations omitting `mode` and the frozen qualification pilot retain exact-word search. Advanced settings keep exact words and strict adjacent phrases, input preservation, category/page reset, both representations and both execution hosts.

## Failures, corrections and review

Initial sandboxed browser commands were blocked by `listen EPERM` on localhost. The first repository run passed 784/786 tests and failed two browser-backed setup hooks for that environment reason. Verification was rerun with localhost/browser access.

Tests exposed two incorrect fixture expectations: changing from exact to phrase must preserve the current `source provider` input, rather than an earlier `source provide`; the fixture's `Atomic commits retain a coherent revision` contains the exact single-letter word `a`, so `red a` correctly returns that record. Both assertions were corrected. A successful focused prefix lifecycle regression verifies this exact single-letter match rather than treating it as a prefix.

Chrome 156.0.8078.74 completed several actual browser checks but the broader attempts hit teardown timeouts. These are retained as unsuccessful attempts, not counted as completed Chrome qualification. The installed Chromium runtime completed the successful runs. A separate preview start/stop probe exited normally in 3 ms; no speculative preview shutdown change was made.

A separate source/diff review by the implementing agent checked optional import boundaries, original input slices, exact earlier-word semantics, native refusals, reuse of one query for retrieval/snippets/Inspector and preservation of existing defaults. No external reviewer or subagent review is claimed. Existing dirty/untracked work was preserved.
