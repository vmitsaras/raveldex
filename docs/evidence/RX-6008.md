## Implementation and adoption

The existing inline and documentation-modal galleries now crosslink and explain the choice, complete browser/Astro source archives, exact source views, unpublished matching package tarballs, explicit data and optional capabilities. Each includes a reproducible edit → build → preview → behavior CSS walkthrough. Shared result properties target the inner `.raveldex-inline`; modal layout properties target `.raveldex-modal`. The actual published snippets are also exercised as browser cascade checks; those checks are distinct from the fresh copied-project edit/build tests.

No search surface, starter or engine was rebuilt as a substitute for the completed RX-6001–RX-6007 work. Qualification exposed and fixed application-wrapper defects:

- Both inline starters wrote authored loading status before publishing pending work. A custom-element disconnection callback could destroy the wrapper, let destruction settle, and still begin a loader afterward. Pending work now exists before those callbacks, and a destroyed wrapper does not load. Loading-status reentrant start shares that work. Failure-status callbacks cannot reveal Retry or overwrite closed feedback after teardown.
- In Playwright WebKit, first pointer activation may leave focus on BODY. Closing a loading dialog can leave focus in its closed shell. The ready modal then captured that hidden control as a programmatic opener. Both modal starters now capture trigger activation explicitly, preserve a useful programmatic opener with a trigger fallback, and conditionally restore owned loading focus before handoff/cancellation. They respect other focus owners, foreign modals and reentrant close/destroy/reopen callbacks. Core/UI runtime and its borrowed-engine contract are unchanged.

The native Chrome search field can consume the first Escape to clear a nonempty value; a subsequent Escape cancels the dialog. Guides explain this behavior and the visible Close search action. Native search-field editing and cancel handling are preserved.
