## Public contracts and ownership

`/addons/evidence` exports `createMatchEvidence` and readonly options/request/range/document/data types. Factory `{fields:{title:'source',body:'offsets'},id?,maxFacts?,maxRanges?,maxWorkUnits?,maxOutputEntries?}` declares explicit providers without retaining a new root. Request `extensions['match-evidence']={ids,fields?,maxFacts?,maxRanges?,expectedRevision?}` selects up to 128 unique IDs, including zero, at the execution-start revision. Fields default to all configured names and may explicitly select an empty projection. Expected revisions reject stale requests; no historical roots are retained.

`MatchEvidenceData` identifies `kind:'raveldex-match-evidence-v1'`, revision, selected fields, `scope:'successful-positive-token-occurrences'`, `complete:true`, and request-order documents `{id,eligibility,ranges}`. Eligibility is matched/excluded/absent; excluded/absent records supply no positive ranges. Each range `{field,valueIndex,position,start,end,term}` has exact original half-open UTF-16 coordinates and native normalized token identity. Field/value/position order is deterministic and duplicates are removed by occurrence. All matching alternatives in successful groups count as occurrence evidence, independently of the BM25 winner. Actual node paths exclude failed ancestors and every NOT subtree, including double NOT. Successful phrases include only tokens in complete per-value adjacent sequences, including repetition/overlap. Equality/predicates/all supply no lexical ranges.

Source strategy fully reanalyzes immutable selected originals. Offset strategy validates the selected position root's analyzer/revision/original-span field plus complete dense original occurrences; it needs no display strings. Small descriptors reject accessors, dense arrays/terms/positions/spans/counts are bounded and traversed with work charges. Trusted provider callbacks remain unsandboxed, as in the existing protocol.

`/addons/snippets` exports `createSnippetEvidence`, readonly snippet options/request/data/document/window/highlight/omission types. It composes the same private evidence builder with presentation under `extensions.snippets`, requiring explicit source for every configured field, including offset fields. Range-only imports exclude snippet/segmentation modules. Installing both factories is supported; requesting two evidence extensions in one operation, including Inspector, rejects INVALID_OPTIONS without resetting caps.

Snippet factory caps narrow only: maxSnippets 3 per document, maxCodeUnits 240 original UTF-16 units per window, maxHighlights 32 merged marks per window. Window `{field,valueIndex,start,end,text,highlights,omittedBefore,omittedAfter}` returns exactly `original.slice(start,end)`. Marks are relative and expanded to whole grapheme clusters, merging overlaps/adjacency; authoritative exact token coordinates remain separately in ranges. No normalized display text, ellipsis or markup is inserted. Source must be rendered as text plus explicit marks.

Each document reports `snippetOmissions:{unshownMatches,windowLimit,highlightLimit,matchTooLong,graphemeTooLong}`. unshownMatches counts original range occurrences not fully represented by any delivered mark. Oversized original tokens/enclosing graphemes remain exact ranges with explicit presentation counts. Base complete means complete selected ranges; display omissions are independent. Missing usable Intl.Segmenter fails requested snippets with the additive `UNSUPPORTED_ENVIRONMENT` code, including empty selections. Ordinary/range-only operations do not access it.

Snippet source lookups reject frozen record/field/value accessors without calling them, and each selected original slice is Unicode-checked and normalized only for comparison against the authoritative normalized term. Mismatched spelling or a bisected surrogate rejects INCOMPATIBLE_CAPABILITY; display text itself is never rewritten. This is a bounded check against selected first-party atomic data, not a guarantee against arbitrary forged external term maps.

Core changes only pass the already-analyzed immutable query tree to requested evidence, validate explicit per-field source/position/offset requirements and add the specified host-feature error. No scorer, second engine, public engine method, source/position retention or optional runtime import is added to core. Positive-path/range logic, Unicode/provider traversal, segmentation, clipping and deep ownership remain optional.

Complete request caps narrow only: 4,096 header-inclusive actual facts, 4,096 deduplicated ranges across every selected ID, 10,000,000 module work units, 16,384 output structural entries with stricter core ceilings, depth 16 and 262,144 aggregate original key/string UTF-16 units. Bounds are independent; a larger allowed fact/range count does not guarantee smaller output/work caps fit. Complete overflow rejects the whole requested operation and preserves the root. All projection traversals share ordinary operation/registration budgets and cancellation/deadline/disposal. Successful owned data remains stable after replacement, remove, clear and dispose.
