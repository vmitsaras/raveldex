## Adopted outcome and public contract

The owner selected RX-A050, then explicitly chose ordinary component matching with original-only strict phrases before runtime implementation. The [adopted policy](../specs/IDENTIFIER_ANALYSIS.md) and [installed public example/API](../api/IDENTIFIERS.md) define the exact behavior.

`/addons/identifiers` exports zero-option `createIdentifierAnalyzer()` and frozen `IDENTIFIER_ANALYZER = { id: 'code-identifiers-v1', environmentProfile: 'unqualified' }`. Explicit selection preserves complete canonical originals and indexes distinct camel/acronym/number/underscore components. Raw queries produce whole-name groups only: `fooBar` searches the whole name; `foo` and `foo bar` can match components. Native BM25 uses weight 1 and actual retained-term TF/DF/lengths, with no hidden exact-name bonus. Repeated canonical components retain their earliest span; a component identical to the whole is suppressed.

Original UTF-16 coordinates and field/value boundaries remain authoritative. Source/offset evidence labels original versus derived matches and exposes the component's actual range plus its full original identifier provenance. Components share the original ordinal; strict source/position/mixed phrases match originals only. `foo bar` is not a phrase inside `fooBar`. Tagged `raveldex-positions-v2` state distinguishes original counts from retained occurrences under the existing positions codec family and exact selected analyzer/module policy; dense v1 basic/English parsing stays strict.

The reserved `identifier-tokenizer` role is separate from the existing one-to-one transform. Other raw IDs and one-to-one handles impersonating `code-identifiers-v1` reject at configuration capture. Yielded steps, tokens and nested provenance are captured from own data descriptors into owned frozen data. Malformed UTF-16, accessors/symbols, invalid canonical spans, duplicate/out-of-order components and limits reject without publishing partial state. One module budget spans the operation, every value/provider and restored record; cancellation checks precede charging after callback advancement.

Import or registration alone leaves basic-v1 selected. English is a separate global selection; metadata and opaque IDs stay unchanged. Existing v1 typo/synonym/suggestion requests remain basic-only, including empty requests. Derived terms enlarge the explicitly selected core dictionary/postings/statistics; there is no hidden optional corpus side index/cache or automatically retained source/positions. No runtime dependency or UI/announcement change was added. `package-lock.json` is unchanged.

## Failures, decisions and independent review

The existing one-to-one seam could not implement identifiers honestly. The owner resolved ordinary component matching versus an explicit component-query capability; this was a specification decision, not a failed runtime test. Initial roadmap validation also correctly refused a `blocker` on `in_progress`; the pending decision used `needs_decision`, then `in_progress` after the owner's answer. Only RX-A050 was selected.

Independent runtime review found two mandatory defects before acceptance:

1. **R1:** arbitrary raw analyzer IDs could index core but selected positions chose the wrong representation and failed `INTERNAL_ERROR`. Capture now reserves the raw kind to the exact supported code ID and refuses mismatches with `INCOMPATIBLE_CAPABILITY`.
2. **R2:** frozen token objects could contain a changing getter, pass validation as `foobar`, then commit `forged`. Capture now inspects descriptors before values and owns frozen step/token/provenance data. The retained reproducer demonstrates the original defect; repaired probes/read-count regressions prove zero getter reads and no publication.

Both mandatory findings are resolved. Initial reproductions remain in `RX-A050-runtime-review-initial.*`. The first independent budget harness incorrectly expected a low-budget source export to succeed; the actual implementation correctly refused the complete operation. `RX-A050-runtime-review-probes-attempt1.json` preserves it; the corrected harness uses a generous donor with an independently lowered matching receiving budget header, and both export/restore budget refusals pass. No product workaround was added. The independent reference's absent-lookahead classification bug was corrected before production evaluation, without changing frozen labels. Review also corrected the documentation's description of private implementation symbols as public API symbols; the corpus/labels stayed unchanged.
