# RX-3001 — One-owner module-worker adapter

Date: 2026-10-08. Status: implementation present; final regression and independent review aggregation in progress.

## Implemented behavior and public contracts

Optional `/adapters/worker` exports `createWorkerRaveldex`, `WorkerAdapterError`, `WORKER_ERROR_CODES` and readonly client/receipt types. Optional `/adapters/worker/host` exports `serveRaveldexWorker` and host types. The application explicitly constructs a same-host module worker; importing core or either adapter entry does not construct workers or initialize host resources. The page and worker are separate ESM bundle entries. Zero runtime dependencies, private version `0.0.0`, existing compiler/bundler/browser tooling and lockfile are preserved.

`createWorkerRaveldex({worker, configuration, ownership: 'owned'|'external', sameHost: true, maxMessageBytes?, responseTimeoutMs?})` asynchronously returns a frozen bound ordinary-method facade, plus `reconcile` and `destroy`. The host creates exactly one complete native root/execution owner at validated initialization. No shards, fallback scorer, snapshots, persistence or automatic mutation retry exist. The complete schema, limits, implementation/protocol/model/analyzer and capabilities are checked in both handshake directions. First-party `execution.worker` is now true with an exact versioned `workerRegistration` identity containing complete normalized semantic options, including facet/fact/range/snippet caps. Trusted local worker handles are explicitly imported; executable values never cross transport. Custom direct-only registrations remain valid directly and fail worker selection.

The implemented analyzer profile remains `basic-v1` / `unqualified`. `sameHost: true` explicitly selects the page's own browser worker; fixture probes and a matching logical identity do not establish cross-host Unicode equivalence or native-snapshot portability.

Transport captures bounded immutable plain data without executing accessors. It validates sessions, increasing request IDs, supported operations, result shape/order/ties/UTF-16 IDs, mutation counters and typed errors. UTF-8 JSON envelope size includes keys and protocol/session/operation metadata: 8 MiB default/hard cap, narrowed to at least 1,024 bytes; client/host negotiate the stricter cap. Additional caps are 131,072 visited nodes, depth 64, 65,536 array elements, 256 code units per key and 64 pending requests/active host operations. Native queue/admission/work/data caps remain independently stricter. Synthetic abort control is attached after legitimate caller capture, preserving exact caller admission counts. Monotonic same-host admission time includes capture/transport before native FIFO execution.

The reply watchdog defaults to 65,000 ms, selectable from 1–120,000 ms. Native observed cancellation/deadline errors retain their core codes and class. A lost read reply is transport `TIMEOUT`; observed endpoint failure is `TERMINATED`. A dispatched mutation without a conclusive outcome is `OUTCOME_UNKNOWN` with its operation ID; a late known commit is successful. Each mutation promise carries a readonly session operation ID. A living owner exposes a bounded 256-receipt window: `pending`, `committed` with actual mutation result (including successful no-ops), `rejected` with sanitized error, or `expired`. Missing/expired receipts never prove rollback. Disposal settles requests, removes adapter timers/signal/worker listeners and terminates only owned workers; an acknowledgement timeout still performs cleanup. Recovery is explicit new-worker/source rebuild.

The documentation pilot offers direct/worker and source/positions selections, using the same current allowlisted corpus. Setup changes release the previous owner, preserve query text, reset facets/page and suppress stale mounts. The server serves the explicit worker artifact under its local CSP.
