33/33 before changes. Source inspection found a starter-specific recovery defect:
mounting the unsupported quick popup failed the entire owner initialization,
including its ordinary full-results inline page. The new copied installed-route

are absent, the controller explains that limitation and keeps this form/browse
route, without loading a pointless header-only owner. The real destination still
loads the same records and mounts the established inline presenter, preserving
the submitted raw query at root and subdirectory bases. The public dropdown API
continues to refuse unsupported hosts: no polyfill, implicit provider or alternate
engine was added. The opt-in expanded modal still shares the supported header's
owner and has no competing shortcut. Loading/empty/error indicators and full-results
link weight now have a clearer hierarchy using existing tokens/hooks.
