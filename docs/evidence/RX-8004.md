## Behavior

The private execution host now separates continuation dispatch from deadline timers. Explicit engine construction captures a usable `setImmediate`/`clearImmediate` pair where present, otherwise an optional `MessageChannel` constructor, with the captured zero-delay timer fallback. It imports no Node/DOM modules and initializes no host resources on core import. The engine captures those handles once; old deterministic hosts still use `schedule(callback, 0)`.

Every eighth continuation uses the timer path. This measured internal policy provides regular timer opportunities; it does not promise realtime bounds or universal fairness between task sources. Pending Node immediates stay referenced. Owned browser/worker ports are created lazily, reused within a burst and both closed when no owned messages remain, on cancellation or disposal. Token deletion and channel identity reject stale deliveries. Callback ownership is released before invocation. Disposal releases the host once, after active/queued engine work and its root are released. Deadline scheduling remains independent.

There are no public API, dependency, quantum, work-unit, query/scoring, capacity, FIFO or publication changes. The final stop-check/commit path and committed-receipt precedence are unchanged. Optional channel setup failure uses the timer fallback; scheduling/post failures retain the native typed failure path and recovery. Review found and repaired cleanup paths where listener removal or first-port closure could mask an outcome or skip second-port release; focused tests now exercise both complete and partial setup cleanup failures.

The strategy follows actual host contracts: [Node 24.21 timers](https://nodejs.org/download/release/v24.21.0/docs/api/timers.html#setimmediatecallback-args) document next-iteration immediates, referenced pending handles and timeout normalization; [HTML message ports](https://html.spec.whatwg.org/multipage/web-messaging.html#message-ports) enqueue tasks and enable their queue through `onmessage`; [event-loop processing](https://html.spec.whatwg.org/multipage/webappapis.html#event-loop-processing-model) gives no cross-task-source fairness guarantee. The implementation does not infer queued-message cancellation from port closure alone.
