## Contract and implementation

[Task manifest](../planning/roadmap.json), [adapter contract](../architecture/ADDONS_AND_ADAPTERS.md#snapshots-and-indexeddb), [core contract](../specs/CORE_CONTRACT.md), [ranking](../specs/RANKING.md), [execution](../specs/MUTATIONS_AND_EXECUTION.md).

The optional `/adapters/snapshots` entry exports `createSnapshots`, `createSnapshotRaveldex`, `currentNodeSnapshotEnvironment`, `SnapshotAdapterError`, fixed `SNAPSHOT_REASONS` and readonly types. Root core remains its frozen seven-method facade. Only private generic queued operations, owner/facade identity and complete prepared-root publication were added beneath the adapter; core imports no codec. First-party source/position manifests declare their codec versions. There are no new dependencies or lockfile changes.

`raveldex-source` and `raveldex-native`, each format version 1, identify `raveldex-json-v1` codec version 1, schema version, complete owned schema/limits/capabilities, analyzer, ranking model/implementation, frequency-directory-256 detail version and origin revision. A noncryptographic FNV-1a checksum covers the exact encoded body; it detects accidental damage and is not authentication. Owned resumable JSON rejects duplicate properties, malformed UTF-16, nonfinite numbers, invalid shapes and non-data/mutable/hidden state. Hard limits: 64 MiB complete UTF-8 JSON envelope, depth 64, 8,000,000 nodes, 262,144 decoded string units and 128-character numeric lexemes. `maxEncodedBytes` narrows the encoded cap, with a 1,024-byte minimum.

Source export requires original providers covering every indexed field, including an empty engine. IDs/metadata come from canonical core records and complete original arrays from selected same-revision providers; absent values and explicit empty arrays remain distinct. Restore rebuilds under the receiving analyzer and reports `reindexed: true` plus that descriptor. It may use private bounded record preparations but shares one complete restore work budget and cumulative per-participant budgets. Native export/restore validates actual dictionaries/hash directories/postings/reverse frequencies/field and corpus statistics, canonical metadata, selected sources, positions and offsets. Retained source is reanalyzed to establish its correspondence; normalized native terms are never fed through the raw tokenizer. Unknown side codecs or incompatible configurations fail with a specific reason.

Every operation uses ordinary admission/FIFO/deadline/cancellation. Restore stages all roots and commits one next local revision, including restoring empty state; origin revisions are metadata. Exhaustion rejects changing imports. Failure preserves exact old root identity and participant revisions. The last stop check is before publication; committed results cannot be revoked by a late signal read.

## Qualification and public contract

The default `basic-v1` profile remains `unqualified`, and ordinary owners reject native export/restore. A qualification cannot relabel an already indexed ordinary owner. The optional qualified factory creates its actual immutable descriptor from revision 0. `nativeQualification` is a trusted application declaration with a bounded profile ID, exact Node/V8/ICU/Unicode/platform/architecture and evidence references; the adapter independently matches the running environment and native imports require the same complete declaration. Merely filling those fields or pointing at an evidence filename does not execute tests or qualify arbitrary hosts. This record establishes the observed fixture/real-document scope on the exact local environment, not universal Unicode equivalence or cross-host/browser portability.

Source reindex accepts a different receiving profile while preserving the same supported basic analyzer ID, schema, limits and capability/codec contract. A changed profile can change semantics; only the observed local cases assert equality. Native snapshots can retain frequencies/positions/offsets without source; omitted original text is never invented. Structural bounds and reverse/statistical/ordinal coherence cannot authenticate source-free term provenance or plausible altered offsets/surrogate boundaries. Retained source supplies actual correspondence. Adapter attachment is limited to direct native owner identity; worker snapshot proxies and IndexedDB storage are outside this slice.

## Failures, classification and repairs

Source review found a post-publication stop check in the outer codec meter and per-record resets of participant work caps during source rebuild. Both were repaired before the first executable snapshot sweep; these are inspected implementation defects, not fabricated failed runs. Independent probes then observed committed restore success with a signal getter that would abort after publication, and cumulative participant-limit rejection preserving the exact old root.

The first focused snapshot sweep ran 24 tests: 11 Pass, 13 Fail. Qualified source/position phrase verifiers and range evidence still assumed the default unqualified profile; they now check the actual supported basic analyzer and same-revision provider headers. Restore also lacked the early abort check already used by ordinary query/mutation admission; it now follows that rule. Two fixtures were wrong: hashing `JSON.stringify(JSON.parse(encoded).body)` changes integer-key directory ordering instead of hashing original encoded body bytes, and an unknown integrity algorithm correctly means `UNSUPPORTED_CODEC`. Those fixtures were corrected without changing the integrity contract.

The second focused sweep ran 28 tests: 27 Pass, one fixture Fail. Its escaped unpaired UTF-16 late-stage failure was correctly rejected earlier by JSON decoding as `MALFORMED_SNAPSHOT`; a valid JSON record with wrongly typed metadata now targets the intended later staged-record rejection. Numeric token lexical bounds, complete-source length consistency and source-origin qualification shape checks were also reviewed and repaired.

The first broader check ran 402 tests: 401 Pass, one fixture Fail. After source export gained complete live-state validation, the cumulative-cap donor correctly hit its 40-unit provider ceiling during export before reaching restore. A 100-record independently chosen collision fixture with cap 4,000 now admits each donor write/export and refuses cumulative restore without changing limits. The initial incomplete cost run reached source10,000 work refusal and exited before producing a JSON report; its stdout is preserved, while the final sampler retains bounded rejections and continues. These are separate from the environment `listen EPERM` boundary. Historical focused/broader/cost logs are preserved as [initial focused](RX-3002-focused-initial.log), [second focused](RX-3002-focused-second.log), [initial broader](RX-3002-check-initial.log) and [initial cost](RX-3002-costs-initial.log).
