## Tooling and implementation choices

- Pin `typescript@7.0.2` as the sole direct development dependency, with its optional platform compiler binaries represented in the npm lockfile. The compiler supplies strict DOM-free checks, ESM output and declarations. No core runtime dependency or test framework was added. [TypeScript module documentation](https://www.typescriptlang.org/docs/handbook/modules/reference.html) describes the NodeNext/type-only import setup.
- Use Node's built-in `node:test` runner against emitted ESM; separately typecheck positive/negative contract fixtures.
- Keep helpers internal under `src/core/`. There is no root `src/index.ts`, package search export or success-returning placeholder. The planned `Raveldex` interface describes future Promise channels; these internal validators throw for their future engine caller to convert into rejections.
- Admission counts own data properties and array elements once, including an array's own length property. Bounds are checked before string scans. Captured structures are capped, but native `Reflect.ownKeys` enumerates/allocates a complete key list before its count is checked. On oversized rejected objects/arrays this primitive's work/allocation is not bounded by `maxAdmissionEntries`; no interruptibility, heap or latency guarantee is claimed for it. Record this native reflection cost in later admission qualification. Token normalization, small query group key sorting/serialization and metadata canonicalization are separately bounded primitives, not claimed as interruptible host work. A stricter aggregate cap independently constrains inputs even if a child cap is larger. Checkpoint quantum must fit both work budgets; minimum prefix length can only increase.
- Analyzer scan steps charge one original code point. Normalization steps additionally charge the bounded raw span length plus normalized output length. `work-v1` budget arithmetic exists, while execution/clock/checkpoint integration and other required work charges remain RX-1005 work. Consumers must exhaust content validation before publishing a root and release temporary source/occurrences in frequency-only mode.
- Default analyzer environment remains `unqualified`. No custom/qualified analyzer or add-on registration is implemented; selecting one fails explicitly. Host-supplied Unicode properties, NFKC and lowercase follow the [ECMAScript string specification](https://tc39.es/ecma262/multipage/text-processing.html#sec-string.prototype.normalize).
