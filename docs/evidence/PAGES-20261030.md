## Failures and corrections

- The first repository documentation check rejected project-root URLs in source Markdown as filesystem escapes. Source links now point to real repository files and are mapped to public routes during rendering; no check was weakened.
- The first browser test assumed result `href` values remained relative. The real UI deliberately resolves absolute URLs; the assertion now checks both same origin and the project contract path.
- An initial sandboxed preview was refused with localhost `EPERM`. Browser/server verification then ran with explicit execution access; this was an environment failure, not a product defect.
- Initial Jekyll setup tried a default user gem-cache directory, then encountered newer Ruby requirements in ffi, i18n and public_suffix. Installation was isolated under `/tmp`, with ffi 1.17.4, i18n 1.14.8 and public_suffix 5.1.1 for system Ruby. Jekyll 3.10.0 subsequently ran successfully. No repository dependency or system Ruby installation changed.
- Separate source/diff review found the runtime bundle's missing license delivery and narrow-table/footer readability issues; the final inventory includes MIT license text and the corrected minimal presentation. Review was performed as a separate author review pass, not attributed to another reviewer.
