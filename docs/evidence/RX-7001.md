## Implemented behavior

The optional `/addons/ui/dropdown` entry exports `mountRaveldexDropdown` and readonly options/handle/messages. The separate `/addons/ui/dropdown.css` styles a bounded title/link projection of the application's borrowed native engine. There is no second engine, suggestion service, snippet/section provider, persistence, automatic initialization or runtime dependency. The only change to an existing runtime source is the type-only shared mount-kind union; existing compiled core, legacy UI, inline and modal graphs are unchanged.

The editable combobox controls a native manual popover containing one grid column: actual rows, selected gridcells and native anchors. Input retains DOM focus during editing and arrow navigation. Stable active IDs reference only current visible cells. There is no automatic first selection or title substitution. Search, Clear, Retry and the ordinary full-results anchor remain outside the popup. Native Popover support is required and refusal occurs before authored DOM replacement. The application must configure a real full-results destination selecting the same content, analyzer and query mode. URLSearchParams carries the exact current raw field value, preserving unrelated parameters/hash. A complete destination starter is intentionally deferred to RX-7002; installed tests exercise an actual inline destination independently.

The default five-hit window is configurable from one through twenty, always offset zero with exact native totals. Prefix/text modes reuse the existing query builder and limits. Idle, composing, waiting/loading, results, no-results, typed refusal/error/retry, closed, clear and destroy states are explicit. Editing, composition, replacement/revision, close, native dismissal, outside interaction, removal/adoption and destroy invalidate obsolete active IDs and work. Explicit open/shortcut may reveal and focus the input; asynchronous search never steals focus. Clear preserves actual focus except when removing its currently focused owned recovery/result control, where guarded input recovery applies. Native result activation stays unintercepted.

Top-layer positioning escapes transformed overflow hosts, aligns with the input and leaves the whole control surface unobscured. It chooses above/below, constrains viewport height and scrolls the owned popup. If neither side fits a usable row, the popup collapses and reports the exact total with zero shown, a no-space explanation and the valid full-results link. This is distinct from no-results and engine failure. There is no resize-driven automatic reopening or hidden modal/engine handoff.

## Independent review and corrections

Read-only review inspected the concrete pattern, frozen public contract and lifecycle source, then ran independent browser probes. Confirmed repaired defects include lost early arrow intent; synchronous native `beforetoggle` dismissal and stale queued-event handling; obsolete feedback after a foreign modal closed the grid; focus loss when explicit Clear removed focused Retry/full-results/popup controls; suppressed composition exposing an obsolete handoff URL; and explicit open/shortcut leaving a newly focused input offscreen. Final installed suites and exact-source independent probes verify the fixes.

Two reentrant-clear/error-Tab concerns were identified in source and fixed before old-runtime reproduction; they are labeled source findings. A separate inference that composition remained stuck did not reproduce and did not justify a speculative change. Home/End divergence in a deliberately scrolling stress fixture also reproduced with plain native controls and no Raveldex listeners; a matched nonscrolling editing case restores native Home/End, while positioning/scrolling stays a separate workload. Native caret behavior was not overridden.

The raw archive retains failed intermediate runs and their exact identities. Harness corrections include actual visible shadow-host setup, correct public CSS names, at least a usable 44px visible portion for an oversized active cell, separate long-label no-space versus short-label dark-popup cases, observed Retry traversal rather than a hard-coded Tab ordinal, actual native clicked-button focus, and waiting for the actual new-page URL rather than initial `about:blank`. Intermediate passing reports are not substituted for the final source/harness identity.
