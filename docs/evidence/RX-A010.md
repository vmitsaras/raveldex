## Implementation and review boundaries

The reserved `term-expansion` role receives a narrow immutable current-revision dictionary context, without a mutable owner/core root. Core materializes weighted exact variants before existing retrieval/scoring/evidence. The add-on uses a specialized linear one-edit code-point matcher, independently checked with a full OSA matrix/source-derived candidates and native numerical expectations. No foreign engine, runtime dependency, source retention, extra dictionary/automaton or cross-search cache is added.

Review identified undercounted structural output and a missing post-expansion canonical-group check. Both now have focused regressions: ten exact groups cost 133 structural entries and exceed an admitted ceiling of 128; nine fit and recover. Ordinary exact plus typo versions of one raw word must still respect the final canonical-group cap. The real worker consumer exposed rejection of query-requested expansion output; client validation now admits only registered expansion keys explicitly present in the captured query, including nested Boolean leaves. Unrequested outputs remain disallowed. Prototype differences in transported owned data are compared as complete wire data, without changing production ownership.
