## Implemented

The separate `/addons/ui/modal` entry exports `mountRaveldexModal` and three readonly modal types. Its explicit `modal.css` selection includes shared inline CSS. A connected authored native button opens a native dialog with accessible heading, pinned search/close, contained feedback/results/facets and optional hints. The application supplies an already created borrowed engine; mount stays closed and makes no search. No loader, second engine, Inspector/Workbench embedding, framework dependency or implicit CSS import.

A small private inline host seam supplies layout, suspension/resume/focus and live native-modality checks without adding a public inline option/export. Close cancels debounce/main/context work and clears results while preserving query/filter values by default; reset is explicit. Reopen revalidates the first page and map revision. Closed search/clear cannot start hidden work. The same native page results and original anchored previews remain authoritative.

Native cancel/close, pointer-generation checks, actual opener restoration, coordinated opt-in shortcuts, trigger attribute ownership and per-document scroll tokens handle close/reopen/destroy and reentry. Destroy restores original Node objects and distinguishable owned attributes/styles, removes bindings and never disposes its borrowed owner. Unknown focused shadow-capable hosts are conservatively refused, including ordinary focused DIV/MAIN-like regions; captured root/trigger shadow trees remain usable. BODY is the ordinary no-focus fallback, so unknown body-attached/inactive external closed trees are not a global discovery promise. Applications coordinate those external modal lifecycles explicitly.

## Independent review and fixes

The runtime, CSS and browser workstreams had separate file ownership. CSS and final reviewers read the actual shared lifecycle source independently. Confirmed defects were fixed and then tested:

- Queued native close followed by same/cross-instance reopening could lose or prematurely restore scroll ownership; per-document owned tokens and old-session reconciliation fix both.
- Destroy could restore native prior focus rather than the recorded trigger opener; conditional actual-opener restoration now respects reentry and unrelated focus.
- Public search immediately after native closure or detachment could issue a hidden request; public control reconciliation pauses first.
- An already pending native reply could commit in the microtask gap before queued close cleanup; private live activity guards now cover execution, sequential context, commit/status/focus paths.
- Closed-shadow foreign dialogs could escape document/open-shadow inspection. Actual Chrome retargeted focus to the host while `:focus-within` was false; the final conservative gate uses the active opaque host rather than that unreliable pseudo-class, while preserving known owned trees.
- Long static title/query-label scroll regions failed keyboard accessibility. Static clamping retains complete native accessible names and avoids inaccessible scrollers/invisible Tab stops; footer hints are bounded likewise.

Independent final probes reconfirm late-reply suppression, custom and DIV foreign closed roots, and owned closed-root shortcut/input/opener behavior. Their executed stdin script and captured-output transcription are preserved with explicit provenance; the original independent process stdout was not saved as a raw file. The installed 26-case suite has original process logs for the same behavior. No remaining actionable review finding was reported within that scope.

Initial browser runs preserve fixture expectation corrections for native browser-chrome Tab stops, truthful removal of stale facet counts, actual `DISPOSED` feedback after worker loss, and the existing 256-unit facet-label cap. None was fixed by weakening product behavior. Confirmed a11y/shadow failures and their subsequent passing runs are preserved separately.

## Documentation pipeline repair

The new HTML setup example revealed a real audit defect: a regex counted escaped fenced `href="/guide/"` text as a live link. The audit now examines actual opening tags for links and fragment IDs. A focused regression proves that escaped examples create neither links nor fragment targets, while real base escapes/missing fragments still refuse, including quoted `>` attributes. No URL allowlist or exclusion was broadened. The failed initial generation and corrected check are preserved.
