## Behavior and conservative boundaries

Core now derives a query-local upper bound after complete query compilation, lexical expansion and capability preparation. Lexical groups borrow complete posting IDs read-only; AND intersects finite bounds and OR unions finite bounds. An unknown OR branch, NOT, browse and unindexed equality retain a universe upper bound. A selective lexical sibling can constrain a pure equality AND. Empty membership remains distinct from unknown/universe.

Opaque predicates preserve the whole document scan, including inside otherwise empty/failed branches. Compound queries containing source/position/mixed/proximity refinements also retain the whole scan. Those callbacks can report required consistency errors on documents excluded by another branch. A standalone refinement can use its own necessary lexical-group intersection, matching the verifier's existing lexical gate. This conservative choice preserves typed per-record errors rather than assuming callbacks are pure.

Candidate traversal uses the existing immutable document directory's native bucket/key order. It charges the hash/key traversal and creates temporary ordered candidate IDs without sorting the corpus or retaining another index. Explicitly requested Inspector records outside the bound receive actual predicate evaluation and node facts, in the original directory order, but contribute no totals, facets or page entries. Missing requested IDs remain appended in request order. Scores, complete totals, global corpus statistics and final UTF-16 tie order retain their existing implementation.

All bound/set/key work yields through the existing search budget and stop checks, under the private `candidates` phase. Bounds never mutate the expanded group sets used by evaluation. Sparse buckets can still contain many irrelevant keys under collisions; reduced evaluated-document counts are not identical to key visits or a proportional latency guarantee.
