## Implementation and public contracts

Explicit `/addons/positions` exports only `createPositionProvider({ fields, offsets?, id?, maxRetainedEntries?, maxWorkUnits? })`. Offsets default to `[]` and are a separately selected subset of position fields. `/addons/phrases/positions` exports `createPositionPhrases({ fields, id?, maxWorkUnits? })`; `/addons/phrases/mixed` exports `createPhrases({ fields: { title: 'source', body: 'positions' }, id?, maxWorkUnits? })`. Default registration IDs are `positions`, `position-phrases`, and `mixed-phrases`. Readonly options are additive; no ordinary facade method or result shape changes. Existing source factory/subpaths remain compatible and import no position modules. Root runtime exports remain three and the engine remains seven frozen methods. Internal store/verifier/roots remain package-private.

The provider retains selected field/value term occurrences, with original value indices represented by array coordinates and sorted ordinal positions. `positionLength: 1` describes basic-v1's one original token at each position, including normalized terms containing new punctuation/spaces; it implies no synonym graph, slop or proximity. Optional spans use the native analyzer's original half-open UTF-16 coordinates. Nonselected offset fields have no span keys. The root retains revision/analyzer, narrowed limits, selected fields, immutable incremental ID directories and logical counts, with no original display text or metadata. Every real mutation/noop, rollback, cancellation, clear and disposal follows the existing transaction/owner lifecycle.

Position and mixed refiners receive already-normalized ordered terms including repeats. They intersect sorted occurrences at distinct query offsets within one value, refine complete lexical candidates before scoring/page selection, and preserve successful canonical score groups and Boolean participation. All selected provider headers/candidate records are validated, including empty/no-candidate preparation and a second provider after a first match. Core generic validation requires a declared appropriate source/position participant per enabled consumer field; it imports no optional modules. No new external provider consistency, live install/migration, worker, snapshot, snippets or public occurrence getter is added.

## Costs and limits

The default ceiling is `maxDocuments × (1 + enabledFields × (1 + maxTextValuesPerField)) + maxCorpusTokens × (offsetFields.length ? 4 : 2)`, narrowed by core limits and an optional smaller provider cap. Occurrences and term code units also have separate core-derived caps. These are logical counts, not retained/peak heap. Source/position query work is not a physical speed claim.
