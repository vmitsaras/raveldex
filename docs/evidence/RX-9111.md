## Delivered contract and example

The [CMS lifecycle guide](../api/CMS_REFRESH.md) separates owner mutations, explicit queries and captured display/maps/options across all five surfaces. It documents committed directory state/presentation/URL ownership, explicit current-revision refresh at page one, query failure checks, unsupported inline/modal facet/window restoration and deliberate application focus handoff. Same-kind mount does not update options; card presentation does not replace metadata. A pending same-query dropdown flight must settle or be closed before the owner write so a later search does not reuse pre-write work.

The [complete copied module](../api/examples/cms-refresh.mjs) is a finite, opt-in document-tree walkthrough using public imports. It creates/owns an engine and directory/card view, queries filtered page two, unmounts the old map, changes indexed content/metadata, explicitly refreshes, checks ready status, and mounts fresh titles/excerpts over the same controller. It preserves presentation, demonstrates repeated mount retaining the current handle/map, restores focus only while it still owns the handoff, then destroys view/controller and awaits its owned engine's disposal. Two complete executions restore the same authored fallback Nodes. It is not a CMS synchronization service; a stable dedicated host, enabled external focus anchor and no competing application operations are explicit preconditions.

HOSTS and the examples index link to the recipe. Localization guidance now explicitly distinguishes composition deferral from cancellation. No runtime, CSS, declaration, engine/provider, dependency, build, export or public handle change is introduced.
