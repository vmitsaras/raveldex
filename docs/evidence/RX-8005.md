## Behavior and resource tradeoffs

Core lexical prefix expansion now seeks a per-field immutable AVL key index, then enumerates matching successors. Binary UTF-16 comparisons are resumably charged. Exact spelling, all selected fields, duplicate alternatives and canonical winning weights/variant keys retain the original add/scoring path; full results, scores, metadata and order remain unchanged. There is no synthetic prefix+'\uffff' upper bound that could omit suffixes at that boundary. Suggestions/typo add-on dictionary scans are unchanged.

The index stores one key-reference node per live field term, bounded by existing dictionary-entry limits. Construction and native restore build it; staged mutations path-copy only insertion/removal paths when a live term enters/leaves the dictionary. Posting-only changes share the existing tree. Rotations, path copies and compared UTF-16 units charge the existing operation budget. Clear/empty roots drop it. No query cache, dependencies, public options, caps or scoring changes are introduced. Ordinary lookup examines O(log V + K) tree nodes (including revisits), with additional compared-code-unit work. Retained/peak heap bytes are **Not measured**; node/reference counts are not heap bytes.

Near expansion limits, sorted encounter order can change which typed error appears first: group versus whole-query caps interact with pairs already contributed by other groups. A reduced-limit independent regression demonstrates this. The implementation therefore probes at most H+1 matching keys, where H is the smaller remaining group/query headroom. If K<=H, all additions fit regardless of duplicate pairs and ordinary ordered lookup is safe. Otherwise it discards provisional keys without add side effects and retains the exact previous hash-directory traversal for that prefix. Successful duplicate-heavy/near-cap queries can conservatively take this full scan too. This preserves adequate-budget expansion-error paths/limit/actual metadata, rather than claiming every prefix query is sublinear. The preliminary probe can add cost to refusal paths; work/deadline refusal cutoffs necessarily change with actual charged work.

Diagnostic invariants check frozen nodes, strict UTF-16 order, dictionary membership/cardinality, exact heights/balance and cycle/shared-child rejection. Native/source snapshot formats and native index-detail identity stay unchanged: export projects the old field wire shape and validates the **live** order tree; native restore rebuilds charged derived order from validated dictionary keys. It does not silently bless a corrupt live tree by reconstructing another one during export. Original normalized terms are never reanalyzed to build order.
