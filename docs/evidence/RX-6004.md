The contract deliberately distinguishes a legitimate page-only result, a visible context-only refusal, a stale-map warning requiring fresh metadata/remount, and a main/evidence race or malformed reply requiring whole-window recovery. It does not promise cryptographic map provenance, detection of a malicious shape-valid provider lying about completeness, or a mutation lock at Promise delivery.

## Current-source review and decisions

Three subagents had bounded responsibilities: read-only evidence/UI feasibility, read-only Astro compatibility, and disjoint ownership of handwritten fixtures. The parent wrote/integrated the contract, inspected source, checked native evidence and reviewed the result. No reviewer claimed tests they did not execute.

- `src/addons/evidence/{types,options,builder,providers}.ts` establishes complete-or-refusal ranges, successful positive path scope, original field/value coordinates, explicit source/offset roots and the optional presentation seam. Existing request parsing rejects the new descriptor keys; RX-6005 must extend only that private optional seam.
- `src/addons/snippets/snippets.ts` establishes bounded globally selected windows, exact source/grapheme checks and omissions. Those windows cannot discover all sections or enforce section boundaries. The contract selects a new optional section evidence projection instead of treating snippets as heading extraction.
- `src/addons/ui/{types,options,inline,render}.ts` establishes current captured display records/URLs, borrowed ownership, page reply consistency, stale suppression and existing whole-snippet-error behavior. The new page-only context policy is explicitly additive, not claimed current behavior.
- `integrations/astro/src/{common,build,client,index,types}.ts` establishes strict old option/envelope keys, directory-only paths, exact configuration/asset/ID joins and exclusive writer ownership. A separate companion preserves old readers. New section loading is source-only, validates a transient public source export and stamps the receiver revision, never the builder's origin revision.
- `src/core/execution/engine.ts` and public snapshot restore semantics preclude a generic read-lock/Promise-delivery freshness claim. Before/after probes observe revisions; every later main/map/evidence join still checks the stamp.

Review resolved preview-count interaction, grapheme-expanded window math, absent/excluded direct requests, trailing empty fragment delimiters, cross-owner provenance limits, output bytes versus UTF-16 counts, source-only versus native artifact identity, full companion ID coverage, source-validation access and URL validation timing. A builder checks its root-relative encoded path/fragment; UI capture checks the actual absolute URL including origin. No foreign engine, runtime dependency, core facade, snapshot format or worker command is required.
