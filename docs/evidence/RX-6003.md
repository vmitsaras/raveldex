# RX-6003 — Installed inline browser and Astro starters

Date: 2026-10-30. Implementation and automated verification complete; documentation and roadmap are synchronized. No commit, remote tracking mutation, push, package publication, tag, release or deployment is part of this slice.

## Delivered behavior

The [browser starter](../../examples/inline-browser/README.md) and [Astro starter](../../examples/inline-astro/README.md) are complete independent applications. Each includes explicit realistic page data, matching display records/destinations, optional source snippets and native string facets, separate inline CSS and small theme overrides, install/build/preview steps, replacement-data guidance and ownership-safe cleanup. Both use direct execution, three-hit batches and a six-hit visible window; no worker is selected. Existing library source, exports, runtime dependencies, artifact versions and qualification data are unchanged.

The browser explicitly loads seven guide records, creates a local owner and renders corresponding static pages. Its starter admits up to 1,000 entries, adding them in batches of 100; these are finite starter bounds, not speed/memory guarantees. Astro explicitly allowlists six pages and uses the existing source-artifact loader on Enable search. Complete title/body source is retained for snapshot reconstruction, while snippets request only body text. The same content supplies the actual page, index and display mapping.

Controllers deduplicate pending initialization, retain browse links during loading/failure, offer retry and keep uncommitted owners local. Destroy establishes a stable promise before host callbacks, aborts loading, destroys UI before disposing its owned engine/loader handle and waits for late owner cleanup. They do not accept borrowed owners; applications with externally owned engines use the public mount/destroy API. Pagehide disposes; persisted pageshow creates a fresh controller.

The [inline solution entry](../../site/Inline.astro) runs an unchanged browser starter built with an actual installed private core tarball. Its exact 20-file source allowlist supplies two complete archives and source views. Astro source uses escaped HTML views to avoid Jekyll interpreting its `---` header; parameter filenames use `param-slug`, avoiding Jekyll's reserved leading underscore. Archives retain the exact original paths/bytes. Existing Workbench and Jekyll exclusions remain intact.

## Review, corrections and limitations

Two implementation subagents owned disjoint starter/test paths. An independent read-only reviewer inspected source, lifecycle tests, public packaging and installed Jekyll implementation; the parent integrated, reviewed the resulting artifacts and ran repository/site/Jekyll checks. No remaining source blocker was found. Review corrected abandoned publication after synchronous mount callbacks, reentrant restoration losing the disposal wait, retry preceding failed-owner cleanup, incomplete Astro source registration, clean-cache resolution assumptions and Jekyll's underscore/frontmatter source handling. Parent review also aligned the Astro test's browser selection with the existing CI environment variable.

Initial source-configuration and test-selector failures, sandbox launch refusal and an early stale-generated-source refusal are preserved in the initial log. They are not reported as passing runs. No library workaround, foreign engine, weakened assertion, new runtime dependency or changed artifact contract was introduced.

Human screen readers/AT, physical IME/touch/on-screen keyboard, actual browser zoom, cross-browser/device qualification, memory/latency measurements, remote CI and hosted deployment were **not run** for these starters. Automated axe, headless keyboard and viewport observations do not establish those outcomes. First-wave qualification remains RX-6008. Next dependency-ready work is RX-6004's page/section contract; no later runtime is implemented here.
