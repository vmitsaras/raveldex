# RX-9501 — UI pilot port fallback

Status: implemented and verified locally. This maintenance task was selected by the owner's
reported `EADDRINUSE` failure on `127.0.0.1:4173`.

## Behavior and review

The UI pilot prefers 4173 or the explicit `--port`. Only `EADDRINUSE` on a
nonzero port triggers one retry with port 0, letting the operating system assign
a free port without a separate availability probe. It prints `server.address()`'s
actual port. Other errors, including a failed fallback, still reject startup.
Temporary startup listeners are removed on either success or final failure.
This uses the existing Node server and adds no dependency or public package API.
Node documents retrying after a listen error and OS allocation for port 0 in its
[server.listen reference](https://nodejs.org/api/net.html#serverlisten).

Diff review: both attempts keep the `127.0.0.1` host. File/method allowlisting,
security headers, artifact preparation, argument validation, `--no-serve` and
signal handlers are preserved. Tests start the actual CLI and fetch the printed
URL; they do not substitute an HTTP server implementation. The explicit-port
collision uses a concurrently running pilot, which remains usable after the
fallback pilot is stopped. Test cleanup stops only processes/sockets it owns.
