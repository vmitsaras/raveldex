# RX-9601 — Header documentation-search modal

Status: implemented and verified locally. The resulting appearance remains
available for owner review; no visual acceptance is inferred.

## Implementation

The shared header's Demo link is replaced by Search docs with a magnifier and
platform shortcut hint. On mobile the compact icon retains its accessible name.
The real installed `mountRaveldexModal` export supplies the native dialog,
search-as-you-type, keyboard/focus, result links and pagination. The application
owns its neutral theme, loading dialog, first-open data loading and engine
disposal. Popular guides provide useful destinations before a query is entered.
No package API, runtime dependency, core source or consumer starter changed.

The existing explicit five-guide/51-section corpus retains its original indexed
bodies, IDs and native prefix semantics. Category and overview text are safe
display projections via `textContent`, not snippets or replacements for indexed
source. Results point to the existing local guide headings. The old advanced
Workbench remains at `/demo/`; the header now demonstrates ordinary modal search
on every shared site page.

First open loads only the allowlisted public JSON, verifies its SHA-256 against
the bundle and indexes it with the installed core. Failed loads offer explicit
retry; mismatched bytes cannot initialize an owner. Close aborts/invalidate late
loads. Reopen reuses the ready index/query. The startup shortcut respects editable
fields, composition and other modals; after mounting the package owns shortcuts.
Pagehide destroys the UI and projection observer before releasing the engine;
bfcache reinitialization waits for that cleanup. No-JavaScript/unsupported native
dialog hosts keep an ordinary guide link.

## Review and adverse outcomes

The first generation refused a new top-level asset directory as unmanaged.
Generation had not published it; the assets were moved beneath the existing
`site-assets/` allowlist without widening that boundary. A subsequent test attempt
correctly refused the then-stale generated inputs. Final generation and tests
passed afterward.

Review found that first-open shortcut cancellation restored the trigger instead
of the actual previously focused link. A focused regression [failed](RX-9601/focus-red.txt)
before correction. Loading now captures the real opener and safely restores it;
focus callbacks cannot mount abandoned work. Final 29-test evidence includes the
corrected assertion. Other review checks covered installed imports, plain-text
projection, borrowed ownership, aborted-candidate disposal, duplicate listeners,
native link/focus behavior and unchanged public/core/dependency boundaries.

The user's preexisting preview process retained its old inventory and could not
serve newly added assets. A fresh preview was used; restarting `pages:preview`
is documented. The local inspection server remains available on port 50517.
No hosted deployment, publication, GitHub synchronization, commit/push, tag or
release occurred. All original demo and starter routes remain available.
