## Implemented

Only the shared default `countHint` changes at runtime. It explains that counts cover all current results matching the search and selected filters, rather than just the visible page. A result can match any selected choice in a group and must also match each other selected group. Adding a choice showing 0 alongside another choice in its group can expand results. The existing captured plain-text override, 512 UTF-16 unit bound, native details/fieldset/checkbox structure and status remain unchanged; no message key or public API is added.

[HOSTS](../api/HOSTS.md) and the [directory contract](../specs/DIRECTORY_VIEW.md) give an exclusive-type example: three Guides, then five results with the two Manuals also selected, then two results after selecting red in another group. Counts remain native, fully filtered and before paging. Unknown projected counts remain unavailable. Zero choices stay enabled; selected zero/unknown values remain checked and removable. Query handlers, Clear all's explicit browse, inert mount, composition, native focus, exact totals/pages and configured URL behavior are preserved.
