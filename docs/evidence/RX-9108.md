## Implemented and selected boundary

Source review found every library-owned consumer label/status/hint already customizable. The [native localization guide](../api/LOCALIZATION.md) now provides the full visible/assistive inventory, tokens, fallback/override precedence, number/grammar behavior and explicit capture/remount contract for all five surfaces. The [copyable German module](../api/examples/consumer-messages.de.mjs) includes every current key, a facet-aware inline variant, modal shell, shared directory/rich-layout messages and separate image failure text. `Required` public-type JSDoc and actual installed declaration-key equality catch missing optional translations. It is application data with no runtime imports, automatic locale selection or UI initialization.

Keep the existing explicit contract: omitted keys retain English defaults; explicit and old empty-message overrides keep precedence. UI language is separate from query analysis and authored content. Numbers use ordinary JavaScript decimal strings, exact total 1 selects singular result text, zero selects empty feedback, and all other positive totals use the existing many message. Other quantities can use count-neutral wording. No locale, formatter, plural engine, callback, message key or public field is introduced.

Language changes require deliberate destroy/remount and application-owned focus/state handoff. New inputs do not retain caret/composition. Directory/card views can preserve their live controller/snapshot without querying or destroying another borrower's work. Inline/dropdown start idle; modal keeps its ordinary close/open contract. HOSTS, the API-example index and the secondary migration appendix point to this native path. No runtime/CSS/declaration/dependency/build configuration changes are needed.
