## Implementation and contract

[Task manifest](../planning/roadmap.json), [storage contract](../architecture/ADDONS_AND_ADAPTERS.md#indexeddb-adapter-contract-rx-3003), [core](../specs/CORE_CONTRACT.md), [execution](../specs/MUTATIONS_AND_EXECUTION.md).

The optional `/adapters/indexeddb` public entry exports `createIndexedDBPersistence`, `IndexedDBAdapterError`, fixed codes and readonly types. Its frozen handle provides explicit `save`, `load`, `erase` and `dispose`, borrowing a trusted direct/worker snapshot handle. Import/construction starts no storage job, permission request, engine initialization or background save. No runtime dependency or lockfile change. IndexedDB has a separate ES2022+DOM compiler/build project; root core remains DOM-free and its seven public methods unchanged.

Dedicated database version 1 has `snapshots` and `metadata` stores with `namespace` key paths, no indexes/autoincrement. The exact canonical version-1 snapshot export prefix and metadata format must agree before full codec restore; stored JSON reformatting is a storage-artifact incompatibility, while portable snapshot parsing retains its general decoder. Each save creates an opaque UUID generation. Mandatory expected-generation CAS plus both row writes/deletions run in one transaction. Stale clients cannot overwrite newer saves or reuse erased tokens. Erase removes both rows with no namespace tombstone and preserves other namespaces; explicit null-token erase recovers orphan/corrupt metadata without a valid UUID. Erasure establishes absence at its commit point, not a permanent ban on later explicit saves.

Serialization, in-memory engine writes and database completion are separate. Save/erase succeed only after observed IndexedDB transaction completion, with strict durability requested; request success alone is insufficient. This is not tested physical power-loss/eviction durability. Load reads one coherent stored generation then invokes full atomic validated source restore. The selected generation is not a current-head lease, and a subsequent stale CAS rejects. Missing/corrupt/incompatible data never triggers silent overwrite, erase, partial participant restore or automatic retry.

Default open timeout is 5,000 ms (cap 30,000); complete action default 30,000 ms (cap 60,000), including queue time; 64 pending actions maximum. Full UTF-8 envelope size checks run outside active transactions, yielding every 16,384 units (one paired-surrogate boundary allowed), cap 64 MiB. Core codec work retains the unchanged complete work ceiling. Browser structured-clone/transaction primitives remain disclosed platform operations, not isolated heap/physical latency measurements. Blocked/late opens close safely, incompatible schemas are refused, version changes close owned connections, and stop/disposal settle pending work without disposing the borrowed engine or erasing durable data.

The separate optional worker snapshot client and host entries provide `createWorkerSnapshots` and `serveSnapshotRaveldexWorker`, reusing one complete owner/FIFO. Source-only browser snapshots preserve the existing unqualified analyzer boundary; native qualification remains exact declared Node scope. Wire cap stays 8 MiB; 64 pending requests and 256 receipts remain bounded. Dedicated snapshot restore receipts are separate from ordinary mutation receipts. Missing dispatched restore results remain unknown and carry operation identity for explicit reconciliation; observed committed delivery wins same-event late cancellation. Ordinary worker/core graphs exclude codec/storage implementations. The existing documentation UI remains explicitly in-memory; its README documents separate storage opt-in.

## Failure classification and repairs

Source inspection found a potentially 64 MiB synchronous UTF-8 loop inside active transaction callbacks; traversal now runs in checked host-task batches outside transactions. Snapshot restore stop fallback now permits already settled promise microtasks to deliver known committed/rejected outcomes before reporting unknown. Structural trusted handles that ignore stop also settle within the bounded fallback; the adapter does not claim to sandbox arbitrary callbacks. A private worker host callback seam initially leaked through the public host module mapping; the thin explicit public entry now exposes only its intended function/types. Metadata format/prefix correspondence and transaction staged-result guards were strengthened before final capture. These are inspected defects repaired before corresponding executable failure claims, not fabricated failed runs.

The four actual first-sweep failures were fixture issues: late-open close instrumentation attached after the close had already occurred; a cancellation prerequisite export used an artificially short two-second deadline; a bounded-wire fixture sent an oversized addMany before reaching its intended export; cleanup treated expected disposal timeout from an intentionally killed worker as unexpected. Fixtures now instrument before delivery, establish bounded prerequisites before the target stop, use separately admissible adds, and retain honest dead-host cleanup outcomes. No runtime cap was raised to conceal them.

Independent review raw history retains its own setup/extension instrumentation failures and a source-README identity drift during a historical package probe. Behavioral passes from that historical package are not substituted for final source/package alignment.

## Limitations and next

Physical quota exhaustion, crash/power-loss durability, browser eviction retention, isolated/peak browser memory, physical latency, cross-browser/device/AT/IME and remote CI are not inferred. Actual browser injections are identified separately from those unrun platform conditions. Source snapshots may hit their existing complete work or encoding ceilings; worker envelopes can be narrower. Native browser/worker snapshot qualification remains unsupported. Direct and worker recovery use original authoritative source with explicit receiving reindex.
