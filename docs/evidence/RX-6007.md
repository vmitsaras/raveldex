## Implemented

Two complete 11-file projects ship under `examples/modal-browser/` and `examples/modal-astro/`. Both include explicit workshop pages, actual heading IDs, one indexed record per page, original UTF-16 section maps, source-based section evidence, native string facets, modal CSS followed by theme CSS, authored browse navigation, installation/replacement instructions and cleanup. They import installed public packages; no private source or Workbench selectors are required.

Each application wrapper opens an authored native loading dialog on first activation. The wrapper creates and owns a new engine/loader candidate; the public modal still borrows its engine and has no loader callback. Repeated opens share the current attempt. Close invalidates before aborting, rapid reopen can create a new current attempt, and old completion/finalizers cannot replace it. Loading errors expose Retry. Close retains an initialized owner and preserves query/filter values by default; explicit reset clears them. Destroy removes the borrowed modal before disposing its owner, removes local bindings, waits for late candidates and has a stable idempotent promise. Direct borrowed owners remain the application's responsibility. The starter wrappers install no global shortcut.

The browser build hashes exact content bytes into its bundle and rejects a different generation before indexing. Astro builds the existing source/display artifacts and separate source-only section companion, then loads all three through the same receiving handle. Build/base/source/display/section identities remain strict. Both render headings from their indexing inputs, encode raw anchors once and retain authoritative native page totals/order/paging. Neither extracts HTML, crawls routes nor implements a sharded/lazy index.

The modal gallery links exact complete archives, text/escaped Astro source views, both guides and a real installed browser preview. It includes separate modal/inline CSS recipes. An explicit family inventory keeps inline and modal downloads separate. The preview height is bounded by the outer viewport; generated output and Jekyll exclusions remain allowlisted.

## Independent review and fixes

Browser and Astro implementations had disjoint file ownership. A separate read-only reviewer inspected both wrappers, static/source binding, gallery inventories and CSS guidance, then ran actual Chrome assertion probes using application source bundled with existing compiled Raveldex. Those probes are distinct from the fresh installed-consumer suites. Final probe source hashes match the reviewed wrappers; its eight assertion groups pass with no remaining actionable finding reported in that scope.

Confirmed fixes:

- Old close/abort callbacks could erase a newly reopened loading session. Generation checks now surround abort, native close/focus and current-attempt reconciliation; concurrent calls return the new current promise.
- Hiding a loading shell before a refused mount could make Retry unavailable. A current failed attempt retains or safely restores visible failure/retry presentation without claiming another modal.
- A persisted pageshow callback waiting for old teardown could initialize after a later pagehide. Navigation generations now suppress that stale restoration.
- Replacing authored status content could synchronously destroy the controller and then let old code reopen the loading dialog or write Retry. Attempts are published before those callbacks and live checks guard subsequent native/DOM work. Durable installed regressions verify no load, no zombie dialog, no late writes and exact owner disposal.
- Shared CSS properties on the outer modal could be overridden by the inner starter rule. The gallery recipe now targets the actual inline surface separately.

Initial failures remain preserved and classified: localhost sandbox `EPERM`; Astro's environment-specific preview daemon mode; encoded native facet option values versus displayed labels; default browser Clear label; an invalid object-form core query in a test probe; and the gallery's screenshot/iframe scroll and destination-load waits. Exact totals, target IDs, owner counts and real product assertions were retained. A generation performed while a wrapper source changed was correctly rejected by preview's stale-input check and regenerated after source freeze.

Reviewer probe provenance is explicit in the archive: one initial package-resolution error log was overwritten and is not claimed as raw evidence; an empty display ID was incorrectly assumed invalid in two early probes. Those were successful mounts rather than failed-mount cleanup evidence. Later probes use a refused `javascript:` URL. The final `.mjs`, raw stdout, source hashes and assertions are preserved verbatim.

## Scope and remaining limits

The public modal/inline/core APIs, providers, adapters, static formats, native scoring/results, existing starter sources and earlier evidence are unchanged. No runtime dependency, tool dependency, lockfile or version change. No commit, remote write, issue sync, publication, tag/release, visibility change or deployment.

An abort-ignoring trusted loader can keep destruction pending until it settles; a subsequently returned candidate is disposed. The wrappers accept newly owned candidates, not arbitrary borrowed application ownership. Native dialog, original-source evidence and applicable secure-context/browser capabilities remain required. Emulated viewports and automated interactions do not establish human AT, physical IME/touch/on-screen keyboard, actual zoom, other engines/devices, calibrated memory/latency or physical paint. The separate first-wave qualification task owns broader claims.
