## Public implementation

The separate private `@vmitsaras/raveldex-astro` exports default `raveldexAstro` from `.`, `buildStaticSearch` from `/build`, and `loadStaticSearch` from `/client`; build/client also export StaticSearchError and STATIC_SEARCH_ERROR_CODES. Readonly types include build/entry/artifact/manifest/descriptors, load/document options and owned handle, and Astro options. No root public entry or core method is added. Integration source is TypeScript compiled in a separate project. Existing Astro/Node types remain outside core's explicit no-DOM/no-Node ambient boundary.

The builder owns all allowlisted record/display data before the first await, initializes only explicit public native owners, exports source plus optional qualified native state, then disposes privately. Native/source failures refuse the whole build. The hook defers getEntries until real build completion, captures constant configuration/qualification, requires static directory output and exclusively creates `raveldex/`; content files use wx and manifest is last. Existing files/directories/symlinks are preserved. A real second-write EIO leaves partial unreferenced newly owned content and no manifest; deployment of failed output is excluded.

The client fetches only the explicitly requested manifest/selected snapshot, validates finite decoded UTF-8 bytes/hash/generation/configuration and public restore receipt, then re-exports public source to verify actual record IDs/count before exposing an owner. This additional codec pass can refuse work/encoding even after restore; no fast-native-load claim is made. SHA-256 detects corruption/mixed generations rather than authenticating a publisher. Display data loads explicitly, verifies ID identity/safe base URLs, and is never implicitly cached or mounted. Signals, per-read timeouts, disposal, noncooperative late responses and reentrant rejected promises preserve safe complete outcomes. Network limits apply to Fetch-decoded bytes; compressed wire Content-Length is not compared as decoded size. Native receives only existing exact-Node qualification, with no browser fallback or broadened portability.

The bounded first slice excludes SSR/dev-watch generation, arbitrary/encoded file-style routes, crawler/parser extraction, schema migration, a worker protocol, automatic UI/storage/network startup and publication. App callbacks/endpoints/publishers remain trusted. JSON/hash/ownership have bounded synchronous sections; response byte/advance caps and native work caps do not establish hard wall time, physical memory, copy peaks or paint latency.
