Status: implemented and verified locally. The owner selected N14 explicitly;

## Observed failures and implementation

An actual module-worker crash left the Workbench's outer message saying Search
is ready, with no useful owner-restart path. The corrected regression failed on
the saved pre-N14 application ([red](N14_UI/final/worker-crash-red.log)).
The application now distinguishes a refused read from an unusable owner, preserves
the original diagnostic code in Technical details, and keeps entered words.
Read timeouts/transport refusals allow explicit Search on the same worker; an
unusable adapter offers Retry loading guides or explicit This page selection.
There is no automatic execution switch, replacement engine or retry.

The observer ignores each aborted request as well as obsolete owners/generations.
Late errors after a newer query or Inspector dismissal cannot replace current
success. Restart keeps its unavailable action focused until native blur; it
cannot be activated repeatedly while pending. The native failure itself is
rethrown unchanged for the borrowed UI. Original indexing/ranking/offsets, public
APIs, optional providers, storage ownership and adapter code remain unchanged.

Recovery guidance now separates missing feature registrations, bounded queries,
loading cancellation, database availability/quota/version changes, namespace
CAS conflicts, direct snapshot reasons, worker mutation/restore receipts and
unconfirmed cache writes/restores. It explains that `load()` restores its receiver
and that some ambiguous writes have no operation ID or worker receipt. These are
application decisions for headless APIs, not invented adapter screens.
