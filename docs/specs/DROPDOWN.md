# Compact dropdown contract — RX-7001

The optional title/link search-result combobox implements [SS-11](SEARCH_SOLUTIONS.md#ss-11--compact-dropdown). RX-7001 owns the runtime slice; RX-7002 delivers the complete browser header/full-results project and gallery. Native page membership, ranking, exact totals and revision semantics stay authoritative. No additional engine, suggestions, facets, snippets, section maps, storage or automatic initialization.

## Public surface and capture

Entry `/addons/ui/dropdown` exports `mountRaveldexDropdown`, readonly `DropdownUIOptions`, `DropdownUIHandle`, `DropdownUIMessages` and `UIDocument`. CSS is the explicit `/addons/ui/dropdown.css`; JavaScript never imports it. Core, inline, modal and legacy semantics remain unchanged.

Options: required `root`, borrowed `engine`, captured `documents` and `fullResults: { url: string, queryParameter?: string }`; optional `maxResults` (default 5, integer 1..20), `debounceMs` (default 150, 0..2000), `mode` (`prefix` default or `text`), `shortcut` (false default, boolean) and partial plain-text `messages`. Reuse current display capture: at most 10,000 unique IDs, bounded safe HTTP(S)/no-credentials URLs, title limits and 4,000,000 aggregate UTF-16 units. Strictly capture own data properties before replacing authored DOM. New options/messages are likewise owned, validated and finite.

`fullResults.url` is an explicit safe HTTP(S)/no-credentials URL, at most 2,048 UTF-16 units, resolved at mount. `queryParameter` defaults to `q` and matches `[A-Za-z][A-Za-z0-9_-]{0,63}`. On a nonempty valid current field value, replace that parameter with the exact field value through URLSearchParams; preserve other parameters and hash. Never trim, normalize or complete the value for handoff. The destination must select the same mode/analyzer/content; a static mode parameter can be supplied in its configured URL. This entry does not implement the destination or serialize native queries. The link is hidden for idle/composing/malformed/oversized text; raw input remains visible and native refusal stays explicit. The new single-line API rejects programmatic CR/LF rather than silently joining words through input sanitization.

Handle: `search(text?: string): Promise<void>` sets optional raw single-line text and flushes debounce without moving focus; `open(): void` explicitly focuses the input and refreshes a nonempty query; `close(): void` cancels presentation and preserves input; `clear(): void` returns to idle without querying and preserves focus, except that hiding a currently focused owned Retry/full-results/popup-link control recovers focus to input; `destroy(): void` restores original Node objects, removes owned listeners/state and never disposes its borrowed engine. Calls after destroy do nothing. Same-kind duplicate mount returns the current handle; foreign UI ownership of the root refuses before mutation.

## One coherent popup

The [APG combobox pattern](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/) permits grid popups. [Listbox guidance](https://www.w3.org/WAI/ARIA/apg/patterns/listbox/) distinguishes option choice from links and other interactive content. Use a single-column grid so actual result links retain native semantics. APG is informative guidance, not universal interoperability evidence.

Use a labeled native text input with `role=combobox`, `aria-haspopup=grid`, `aria-autocomplete=list`, stable `aria-controls` and truthful `aria-expanded`. The controlled native manual popover is the grid; each actual hit is a row containing one gridcell and a real anchor with `tabindex=-1`. Stable per-mount/per-display-ID cell IDs avoid embedding raw IDs in DOM IDs. `aria-activedescendant` refers only to an existing visible current cell; only that cell has `aria-selected=true`. DOM focus stays on input during editing and virtual navigation. No automatic first selection, title insertion, vocabulary completion or fake result action rows. The grid describes only its finite rendered projection, not an invented virtual collection.

A separate ordinary full-results anchor is outside the popup/grid in normal Tab order. Search/clear/retry controls and polite feedback are also outside the popup. A full-results action is never counted as a native hit. All content uses safe text insertion. Results show actual order and exact total, requesting offset 0 and at most maxResults; no popup pagination or hidden accumulated results.

Use native `popover=manual` to escape overflow/transform clipping while retaining DOM/ARIA relationships. Require native showPopover/hidePopover and fail `UNSUPPORTED_ENVIRONMENT` before DOM changes when unavailable; no hidden fallback or new dependency. Manual popovers require explicit dismissal/instance coordination. Canceled/reentrant opening and externally closed native popovers must not leave stale expansion, active descendants or late publication. Ignore queued old toggle events that no longer describe the current native state. [Native popover behavior](https://developer.mozilla.org/en-US/docs/Web/API/Popover_API/Using) informs this boundary.

## Keys, focus and dismissal

RX-9106 adds optional captured `messages.keyboardHint`. The default visible paragraph explains Arrow Up/Down selection, Enter on a selected link versus Enter to search, Escape dismissal and ordinary Tab exit. A unique input `aria-describedby` reference exposes that same static text; it is outside live feedback and adds no key binding or shortcut. Translate it through the existing plain-text 512-unit capture. Old complete message bundles remain valid. Other native-list presets do not receive combobox instructions.

- Unmodified Down/Up enter first/last result, then clamp at boundaries. If results are not yet available, flush/reopen the current query and retain only explicit first/last navigation intent for its current reply; do not automatically activate ordinary search replies or issue repeated duplicate queries while loading.
- Unmodified Enter on a current active cell activates its actual anchor without rewriting input. With no active cell, native form submission flushes/reopens search. Modified input Enter/arrow combinations do not select or activate a hit. Actual anchors preserve native modified pointer activation/context menus.
- Left/Right/Home/End, deletion, printable and selection/editing keys clear virtual selection synchronously and retain native input behavior. Do not intercept platform editing/modifier shortcuts.
- Escape dismisses/cancels a current popup or pending presentation from any owned control and preserves query. If dismissal removes the focused result link, Escape restores editing focus before removal, with freshness checks around authored focus callbacks. Tab/Shift+Tab dismiss without preventing default, moving focus programmatically or forcing popup traversal. Native keyboard-navigation conventions/preferences still determine which ordinary links/buttons are sequential focus stops; do not change settings or add a Tab loop. Outside pointer/focus interactions cancel pending publication even when a programmatic search began with focus already outside. Pointer interactions inside known owned shadow roots remain inside.
- Composition begins by clearing active/current results and canceling pending presentation. Interim input/submit/navigation does not search or activate. Final composition schedules the actual committed field; duplicate final input must not create duplicate searches.
- No focus trap or automatic focus after an async reply. Open/shortcut is the explicit focus action. Clear preserves input/Search/Clear/external focus; when it removes the currently focused owned Retry/full-results/popup-link control, it conditionally recovers input focus before hiding it, with lifetime checks around focus callbacks. Retry may deliberately focus the input before hiding its own control, with lifetime checks around authored focus callbacks.

Close clears active IDs before rows, obsolete counts and busy state; reopening refreshes. Query, filterless result or revision replacement atomically clears virtual selection before DOM changes. Preserve idle, waiting, composing, loading, results, no-results, error/retry, closed and destroyed behavior. Use the same typed native-error boundary as other presets. Ignore old replies after edit/close/outside/removal/replacement/destroy, including native visibility/event microtask gaps. Uncooperative work can outlive UI cancellation but cannot publish. There is no synchronous current-revision getter or live mutation subscription: unannounced external mutations require refresh/reopen; do not add polling or search-on-every-link.

## Placement, styling and ownership

Position the owned top-layer popup using input-aligned width and the full control surface as a non-occluding anchor, with fixed viewport coordinates, constrained inline size, available block space and contained scrolling; choose above when below is insufficient. The normal-tab full-results link can share the form action row while remaining outside the popup/grid. If neither side leaves one usable control-height result row plus borders, collapse the popup and active ID, show the exact native total with zero visible results and the plain-text noSpace message, and keep the full-results link available. Do not label this no-results or an engine failure; do not automatically reopen until new user edit/open/navigation/explicit search. Reposition on relevant scrolling, resize and visual-viewport changes, keeping active cells visible without scrolling unrelated page content. Close when the anchor is outside the usable viewport. Narrow layouts retain the dropdown/full-results route; automatic modal handoff is outside this slice.

Classes: `.raveldex-dropdown` and scoped `__form`, `__label`, `__input`, `__submit`, `__clear`, `__status`, `__retry`, `__full-results`, `__popup`, `__row`, `__cell`, `__link`; `.is-active` on the active cell. JavaScript hooks use matching `data-raveldex-dropdown-*`; the cell has `data-raveldex-dropdown-result` containing the native ID. Public theme properties use `--raveldex-dropdown-*`; private geometry uses `--_left`, `--_top`, `--_width`, `--_max-height`. Theme controls cover colors/background/muted/accent/border/focus/active, font/text size, gap/padding, radius/border width, max width and popup max height. Retain visible focus, 44px controls, non-color active indication, long text, RTL, forced colors and reduced motion.

Only one owned dropdown popup per document is shown; opening another cancels the previous presentation without disposing any owner. Global Ctrl/Meta+K is opt-in and shares the existing document coordinator with modal: editing/composition/defaultPrevented/repeat/modifier and foreign modality guards remain. Known owned shadow ancestry is inspectable; unknown closed foreign modal/focus regions have the conservative boundary documented for modal, not a promise to discover all closed trees. Destroy/remount and abort/focus/native-toggle/authored DOM callbacks cannot erase a newer mount/session or register duplicate listeners.
