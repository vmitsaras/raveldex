RX-9101 · selected 7 November 2026 · governed by the [N11 scope](N11_UI_UX_POLISH.md) and [qualification amendment](../planning/SCOPED_QUALIFICATION_AND_IDENTITY_20261107.md).

This is the selected design and compatibility contract for subsequent N11 delivery. It does not claim that its visual changes or revised copy are already shipped. **Existing** means inspected source/test behavior at `038385b`; **Selected** means the direction to implement in the named N11 tasks. Test references are inspected coverage, not fresh test results or observed assistive-technology behavior.

## Product and selected direction

The primary user wants to find a useful document or resource, understand why it is relevant, and follow its native link. Integrators need the same experience in documentation, applications and catalogues without adopting a framework, developer workbench or foreign indexing model.

**Selected direction: Reading index.** Clear results, visible context, optional explanation. A restrained reading column, strong linked titles, quiet context and source excerpts form the identity. Controls occupy a compact, distinct search band; results use space and fine dividers rather than nested panels. Blue links, warm match marks and a separate focus outline continue the existing consumer family. The consumer component borrows its host font rather than reproducing the marketing site's oversized branding or lime call-to-action. No competitor screenshot, asset or layout is the reference.

One direction was considered and selected; no second exploration is needed for this slice. The decision builds on the existing readable consumer CSS and actual data contracts. RX-9107 applies it; RX-9112 reviews the implemented family.

| Attribute | Implementable consequence |
| --- | --- |
| Readable | Title first; body-sized excerpts; context smaller but fully legible; bounded line lengths and wrapping. |
| Contextual | Show existing source/section/category/breadcrumb data where supported; omit unavailable rows without inventing content. |
| Predictable | Stable controls and native links; retain each surface's existing query, paging and keyboard semantics. |
| Quiet | One configurable action accent; errors also use words; no default scores, Inspector, promotional illustrations or decorative badges. |
| Embeddable | Optional scoped CSS, inherited fonts, component overrides, independent roots, no global reset or downloaded assets. |

## Result hierarchy and representative content review

**Selected order:** linked title → available location/context → relevant excerpt → optional supporting metadata. Title and destination remain the primary action. A single result gets one reading group; its optional sub-sections remain subordinate native links. Never surface numeric scores/Inspector by default.

| Surface | Apply hierarchy within its existing capability |
| --- | --- |
| Inline | Title + optional original-source snippets **or** page/section context. No generic location row exists; do not derive one from URL text or add a field to satisfy the visual rule. |
| Modal | Same inline result expression within native dialog/search/body/footer regions. Preserve independent close action and scroll/viewport bounds. |
| Dropdown | Compact title-only native link. Keep exact total/full-results recovery separate from virtual current-item feedback. No snippets, facets, metadata or section expansion is selected. |
| Directory | Native ordered list of title links; counts and filter context belong to the controls/status, not invented result metadata. |
| Cards | Title first in the text group, then category/breadcrumb, authored excerpt and date/labeled fields. An explicitly enabled image frame precedes the title in actual DOM order; the title remains the primary native action. List/cards/grid change layout, not ranking or semantics. |

Representative reading specimens use authored repository content, not invented engine replies or comparator screenshots:

> **[Plan your first walking trip](../../examples/inline-browser/content.json)**  
> This **walking guide** helps you choose a route, check daylight hours and tell someone when you expect to return.

The title supplies the destination. The marked phrase represents a source match, not focus. There is no source label in this inline record's rendered contract. In an actual snippet, marks and ellipses must come from validated original offsets; this specimen is not a captured query response.

> **[Choose a walking map](../../examples/cards-browser/content.json)**  
> Outdoors › Planning  
> Find the right scale and symbols for your route.

The cards specimen makes breadcrumb/excerpt secondary to the title. Optional date/fields follow; a missing image leaves a complete result. For a documentation record with actual section context, display the supplied section title and its native anchor below its parent, not a fabricated breadcrumb. For an application with only `id/title/url`, the title-only result is complete. Long title, RTL context and an absent optional row must preserve this ordering rather than create empty placeholders. These specimens select typography/content roles; they do not add fields or promise the same rows on every surface.

Optional explanation means using existing snippet/section evidence and omission notices where configured, or explicit host-owned material outside the search component. Do not hide the main excerpt, essential recovery text or limits behind disclosure. This slice selects no new expandable explanation control, renderer callback, retained evidence map or Inspector dependency. RX-9109's [source-verified result-content decision](../api/RESULT_CONTENT.md) adopts keep-current: query-derived inline/modal context and authored rich-directory projection remain separate. It specifies the per-field matrix, native scenarios, strict basic projection, incompatible combinations and image ownership/privacy limits. Any additive display contract needs separate selection before implementation.

## Keyboard, pointer, focus and announcements

- Inline/modal/directory/cards use native forms, buttons, selects/checkboxes, disclosures and links. Preserve text editing, modified link activation, context menus and normal Tab order. Styling cards as a grid never adds ARIA grid semantics or arrow navigation.
- Dropdown keeps its existing combobox/grid pattern: clamped Arrow Up/Down selects a current item through `aria-activedescendant`; Enter follows its documented current-item/query behavior; modified editing keys remain native. Tab dismisses without trapping traversal. A pointer click, modified click or context menu still acts on a real anchor. RX-9106 writes guidance from these actual rules rather than sharing a generic hint with the modal.
- Native modal owns Tab containment, initial search focus, Escape/cancel and deliberate backdrop handling. Close restores the appropriate live opener without stealing focus from another owner or newer modal. Dropdown Escape from a disappearing focused link first recovers to its input. Filter-disclosure Escape/Close returns to its summary.
- When result replacement removes the focused result, recover to its search input, including supported shadow-root cases. Directory chip removal selects the next surviving chip, then previous, then input in DOM order. Inline/modal paging nodes remain stable across busy/unavailable/error states; a focused unavailable control stays visible and guarded until focus moves, when it may hide. Directory paging/retry keeps its existing persistence policy.
- Status text describes actual composing/searching/settled/empty/failure outcomes; a polite atomic region deduplicates unchanged messages. No per-keystroke total updates, unnecessary alerts or duplicated visible/hidden announcements are selected. Separate exact total from visible count/range and append feedback; do not announce appended hits as a replacement query. RX-9105/RX-9108 finalize copy/templates within existing overrides.

### RX-9104 pagination presentation contract

Keep the range summary outside the action navigation so a complete single batch needs no unavailable buttons. Hide unavailable unfocused actions; retain a focused unavailable action visibly with guarded `aria-disabled` until native focus has moved. Clear/replacement/error remove stale summaries and targets without hiding the currently focused action. Use the owning document/shadow tree's active element, and suppress deferred visibility work after teardown or modal suspension.

After a successful append, keep Load more focus and expose a native **Go to new results** button immediately after it. Tab then Enter/Space deliberately focuses the first newly appended native title link. Keep a single private reference, invalidate it with the presentation, and make no further mutations after its focus call because authored focus handlers may reenter. Do not alter host URL fragments, native result-link activation, query offsets, render caps or automatic focus policy.

Two optional captured message keys support this UI: `newResults` (button label) and `resultsAdded` (append status template supporting `{added}`, `{start}`, `{end}`, `{total}`, `{count}`). Existing complete original bundles remain valid and unspecified keys use English defaults. No new public handle method, engine capability, renderer or locale mechanism is selected. These additive text slots are part of this bounded delivery contract, not a generalized explanation/display API.

### RX-9105 search feedback contract

Empty feedback uses the submitted query or active filtering context, never a later draft. The `{query}` token is plain text, trimmed and limited to 160 Unicode code points plus an ellipsis for display only; the original input/query is unchanged. Inline/modal and dropdown identify a text-only no-match and offer editing/reset or the existing full-results route. Inline/modal filtered empties name selected filters and offer changing a filter or Clear search and filters. Directory/cards distinguish text-only, filtered and empty browse results; Refresh results is explicit and never automatic. Do not diagnose filtering as the sole cause without a separate unfiltered search.

Add optional captured `noResultsFiltered` to inline/modal and directory messages, and `noResultsBrowse` to directory messages. A supplied existing `noResults` override remains the fallback for all variants unless the corresponding new override is supplied, preserving existing translated bundles. `{query}` works in all empty templates. No new locale selection, diagnostics callback or required message field is introduced.

Default failures describe the available Retry search or Refresh results action without a code as the primary text. Existing `{code}` overrides and directory snapshot typed errors remain available for diagnostics. Revision changes remain distinct from empty/failure and require explicit retry. Align composing/searching language where applicable; retain the existing waiting/debounce announcements and per-surface browse/reset semantics. Keep one deduplicating polite atomic status region, no settlement focus movement and no automatic mount/idle/reset query. This copy work preserves cancellation, composition, stale-response suppression and teardown.

### RX-9106 keyboard guidance contract

No query, editing, active-descendant, composition, activation, dismissal, focus restoration or shortcut semantics change. Old complete message bundles remain valid. Test a populated modal search field against the same browser's plain native dialog/search input; record native behavior rather than impose a platform-wide Escape sequence.

### RX-9111 CMS refresh and captured-state lifecycle

The [CMS guide and copied installed walkthrough](../api/CMS_REFRESH.md) distinguish engine mutations, explicit UI/controller queries and captured display/maps/options. Directory `refresh()` keeps committed text/filters and accepts the current revision at page one; equivalent `restore()`/`update()` can be inert. Query Promise resolution is not a success receipt: inspect the ready result/error. Unmount a potentially incompatible old display map before owner writes/refresh, then mount the new map over the same compatible controller. Keep its URL binding and preserve card presentation explicitly when required.

Inline/modal/dropdown have no public query snapshot/getter, facet setter or result-window restoration API. A remount can explicitly restore app-owned text with the normal query contract, but exact hidden facet/window restoration is unsupported. Active composition defers inline/dropdown `search(text)`; it is not an IME cancellation method. New inputs do not inherit focus/caret/composition. CMS ordering and conditional focus handoff belong to the application, not to library stale-response guards.

The finite example is deliberately document-tree-only, owns/disposes its resources and runs without competing commands/host replacement. Other shadow integrations use their known focus scopes. Ordinary views remain borrowers; remount does not cancel a shared directory controller's pending work. Final cleanup remains view → optional URL binding → controller → owned engine after other borrowers finish. No background CMS subscription, live-map/state setter, engine change or query-policy extension is selected. See [acceptance evidence](../evidence/RX-9111.md).
