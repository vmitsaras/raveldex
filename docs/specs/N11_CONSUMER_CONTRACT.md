RX-9101 · selected 7 November 2026 · governed by the [N11 scope](N11_UI_UX_POLISH.md) and [qualification amendment](../planning/SCOPED_QUALIFICATION_AND_IDENTITY_20261107.md).

This is the selected design and compatibility contract for subsequent N11 delivery. It does not claim that its visual changes or revised copy are already shipped. **Existing** means inspected source/test behavior at `038385b`; **Selected** means the direction to implement in the named N11 tasks. Test references are inspected coverage, not fresh test results or observed assistive-technology behavior.

## Product and selected direction

The primary user wants to find a useful document or resource, understand why it is relevant, and follow its native link. Integrators need the same experience in documentation, applications and catalogues without adopting a framework, developer workbench or foreign indexing model.

**Selected direction: Reading index.** Clear results, visible context, optional explanation. A restrained reading column, strong linked titles, quiet context and source excerpts form the identity. Controls occupy a compact, distinct search band; results use space and fine dividers rather than nested panels. Blue links, warm match marks and a separate focus outline continue the existing consumer family. The consumer component borrows its host font rather than reproducing the marketing site's oversized branding or lime call-to-action. No competitor screenshot, asset or layout is the reference.

One direction was considered and selected; no second exploration is needed for this slice. The decision builds on the existing readable consumer CSS and actual data contracts. RX-9107 applies it; RX-9112 reviews the implemented family.

| Attribute | Implementable consequence |
| --- | --- |
| Readable | Title first; body-sized excerpts; context smaller but fully legible; bounded line lengths and wrapping. |
| Contextual | Show existing source/section/category/breadcrumb data where supported; omit unavailable rows without inventing content. |
| Predictable | Stable controls and native links; retain each surface's existing query, paging and keyboard semantics. |
| Quiet | One configurable action accent; errors also use words; no default scores, Inspector, promotional illustrations or decorative badges. |
| Embeddable | Optional scoped CSS, inherited fonts, component overrides, independent roots, no global reset or downloaded assets. |

## Result hierarchy and representative content review

**Selected order:** linked title → available location/context → relevant excerpt → optional supporting metadata. Title and destination remain the primary action. A single result gets one reading group; its optional sub-sections remain subordinate native links. Never surface numeric scores/Inspector by default.

| Surface | Apply hierarchy within its existing capability |
| --- | --- |
| Inline | Title + optional original-source snippets **or** page/section context. No generic location row exists; do not derive one from URL text or add a field to satisfy the visual rule. |
| Modal | Same inline result expression within native dialog/search/body/footer regions. Preserve independent close action and scroll/viewport bounds. |
| Dropdown | Compact title-only native link. Keep exact total/full-results recovery separate from virtual current-item feedback. No snippets, facets, metadata or section expansion is selected. |
| Directory | Native ordered list of title links; counts and filter context belong to the controls/status, not invented result metadata. |
| Cards | Title first, available breadcrumb/category as quiet context, authored excerpt, then date/labeled fields. Existing explicit image presentation may precede text visually while keeping the title/link identifiable. List/cards/grid change layout, not ranking or semantics. |

Representative reading specimens use authored repository content, not invented engine replies or comparator screenshots:

> **[Plan your first walking trip](../../examples/inline-browser/content.json)**  
> This **walking guide** helps you choose a route, check daylight hours and tell someone when you expect to return.

The title supplies the destination. The marked phrase represents a source match, not focus. There is no source label in this inline record's rendered contract. In an actual snippet, marks and ellipses must come from validated original offsets; this specimen is not a captured query response.

> **[Choose a walking map](../../examples/cards-browser/content.json)**  
> Outdoors › Planning  
> Find the right scale and symbols for your route.

The cards specimen makes breadcrumb/excerpt secondary to the title. Optional date/fields follow; a missing image leaves a complete result. For a documentation record with actual section context, display the supplied section title and its native anchor below its parent, not a fabricated breadcrumb. For an application with only `id/title/url`, the title-only result is complete. Long title, RTL context and an absent optional row must preserve this ordering rather than create empty placeholders. These specimens select typography/content roles; they do not add fields or promise the same rows on every surface.

Optional explanation means using existing snippet/section evidence and omission notices where configured, or explicit host-owned material outside the search component. Do not hide the main excerpt, essential recovery text or limits behind disclosure. This slice selects no new expandable explanation control, renderer callback, retained evidence map or Inspector dependency. RX-9109 can choose keep-current; any additive display contract needs separate selection before implementation.

## Keyboard, pointer, focus and announcements

- Inline/modal/directory/cards use native forms, buttons, selects/checkboxes, disclosures and links. Preserve text editing, modified link activation, context menus and normal Tab order. Styling cards as a grid never adds ARIA grid semantics or arrow navigation.
- Dropdown keeps its existing combobox/grid pattern: clamped Arrow Up/Down selects a current item through `aria-activedescendant`; Enter follows its documented current-item/query behavior; modified editing keys remain native. Tab dismisses without trapping traversal. A pointer click, modified click or context menu still acts on a real anchor. RX-9106 writes guidance from these actual rules rather than sharing a generic hint with the modal.
- Native modal owns Tab containment, initial search focus, Escape/cancel and deliberate backdrop handling. Close restores the appropriate live opener without stealing focus from another owner or newer modal. Dropdown Escape from a disappearing focused link first recovers to its input. Filter-disclosure Escape/Close returns to its summary.
- When result replacement removes the focused result, recover to its search input, including supported shadow-root cases. Directory chip removal selects the next surviving chip, then previous, then input in DOM order. Keep exposed paging/retry controls stable across busy, unavailable and error states.
- Status text describes actual composing/searching/settled/empty/failure outcomes; a polite atomic region deduplicates unchanged messages. No per-keystroke total updates, unnecessary alerts or duplicated visible/hidden announcements are selected. Separate exact total from visible count/range and append feedback; do not announce appended hits as a replacement query. RX-9105/RX-9108 finalize copy/templates within existing overrides.
