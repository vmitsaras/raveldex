# Directory query and URL state — RX-7003

The optional `/addons/ui/directory` entry supplies `createDirectory` and `connectDirectoryURL`, with readonly types. This remains the nonvisual foundation for SS-12; the separate [view/adoption contract](DIRECTORY_VIEW.md) owns RX-7004 checkbox/chip/mobile controls, complete browser/Astro starters and gallery. Core, ranking, existing UI and native filter/facet formats are unchanged. No renderer, engine creation, provider registration, storage, telemetry or search-history feature is added. Native session-history writes occur only through the explicitly connected URL binding below.

## In-memory controller

`createDirectory({ engine, groups?, pageSize?, mode? })` borrows an existing engine. Groups are `{ field, values, limit? }`: at most eight unique native string field names, up to 128 distinct allowed strings per field, at most 1,024 UTF-16 units per value and 65,536 aggregate configuration units. Empty string is a legitimate value. Configuration is captured before work and immutable; destroy/recreate to change it. Default page size is 20, integer 1..100; mode is prefix by default or text. There is no import-time or construction-time query/host discovery.

State is `{ text, filters, page }`, where filters contains all declared fields and readonly sorted selected strings; at most sixteen selected values per group and 8,192 aggregate selected units. Text retains its raw single-line value, at most 2,048 well-formed UTF-16 units. Whitespace-only input browses all records. Native text/prefix semantics combine with one native set-membership leaf per nonempty group (OR within a group), under AND across groups/text. Filters require their explicit registration; configured facet fields require the facet registration. Capabilities are never installed or omitted as a fallback.

The handle has `getSnapshot()`, `subscribe(listener)`, `update({ text?, filters? })`, `setPage(page)`, `restore(state)`, `refresh()` and `destroy()`. A supplied filters object replaces all groups; omitted groups become empty. Effective query/filter edits reset page to one; equivalent state retains its page. Restore is an explicitly validated external replay and can retain its page. Page numbers are one-based and bounded by the 10,000-document native ceiling and page size; requests use native offset/limit without accumulating hit pages. Refresh resets to page one and accepts a fresh revision. Equivalent ready/loading state is a no-op; repeated identical pending work shares its Promise. Capture errors throw before cancellation or notification; native operation failures become an error snapshot and operation Promises resolve.

Snapshots are deeply captured/frozen and expose status (`idle`, `loading`, `ready`, `error`, `stale`, `destroyed`), state, a change reason and only a current ready result. Results contain native revision/total/hits/scores, native conjunctive facet fields and selected-value count projections. A selected value absent from a complete bucket list has count zero; when native buckets are omitted, its unknown count is null. No invented zero or silent selection removal. Null/missing buckets can be reported natively but are not selectable strings in this first foundation.

Observers receive snapshots, not commands, and cannot cancel operations. No initial subscription callback; at most 64 distinct listeners, including any URL binding. Publish loading before query work, suppress stale/out-of-order completion, clear old presentation on state/revision changes and guard reentry around abort/observer callbacks. A newer notification stops delivery of its obsolete predecessor. Observer exceptions are isolated from transactions. Destroy cancels pending work, emits one destroyed snapshot, removes observers and never disposes the borrowed owner; later commands do nothing.

Paging within an existing query/filter result must retain its revision. A changed native revision clears hits/counts, resets page one and reports stale/REVISION_MISMATCH; explicit refresh recovers. No mutation polling/subscription. A same-revision out-of-range restored page recovers to page one with at most one additional query; a revision change during that recovery is stale, never mixed output. Reduced native limits and other explicit errors remain observable rather than being converted to empty results.

## Explicit browser URL binding

`connectDirectoryURL({ controller, host, parameters, history? })` takes an explicit structural browser host and explicit `{ query, page, filters: { field: parameterName } }` ownership. All names are unique, 1..64 characters matching `[A-Za-z][A-Za-z0-9_.-]*`, with exactly one mapping per configured group. Default history policy is replace; push is explicitly selectable for committed update/page actions. Importing or creating the in-memory controller never accesses location/history/events.

The returned binding has `getSnapshot()`, `read()`, `write()` and `destroy()`. Connect claims names/listens but does not read/query until `read()` is called. Read validates the current URL, canonicalizes owned values using replace and restores controller state. Popstate invokes read. Normal update/page changes follow the selected policy; refresh/recovery always replace. Ready/error status changes do not write. Replay never pushes and equivalent state does not loop. `write()` explicitly retries writing current in-memory state with replace; it does not discard it by rereading an older URL.

One binding per controller and one owner per host/parameter name. Overlap refuses before listeners, query or history mutation; disjoint instances share unrelated URL state. Destroy releases names/listeners/observer, leaves URL/state/history intact and does not destroy the controller. Controller destruction disconnects its binding. Reentrant history/observer/navigation callbacks cannot publish an older URL operation after a newer one.

Limits: current href at most 65,536 code units; owned encoded segments at most 16,384 units. Preserve pathname, raw unowned query segments/order/encoding and hash. Encode raw admitted text and repeated selected strings, omit empty query/unselected groups/page one. Strictly decode owned values; malformed UTF-8/percent/UTF-16, multiline/overlong query, duplicate query/page and invalid page reset that field. Unknown/duplicate filter values are dropped; excess group selections reset that group. Aggregate selected-value overflow clears all filters, retains admitted text and records a limit issue against the first group. Oversized owned encoding clears all owned state and records a query limit issue. Any admission correction resets page one and records bounded parameter/reason issues. Clean correction uses replace; it never rewrites unrelated parameters or history.state.

An unreadable/oversized whole URL or history-write failure leaves it unchanged and exposes an error through the binding snapshot. In-memory search remains usable. The binding does not silently truncate state, stringify another feature's history data, create a search-history store, or change route ownership. Callers inspect binding status and explicitly retry read/write. Read/write support HTTP(S) same-document URLs; no cross-origin navigation is implemented.

Native session-history behavior follows [pushState](https://developer.mozilla.org/en-US/docs/Web/API/History/pushState) and [popstate](https://developer.mozilla.org/en-US/docs/Web/API/Window/popstate_event): mutation and traversal are separate operations. Tests must exercise actual Back/Forward, not only synthetic events or a fake host.

## Acceptance evidence

Hand-derived and fixed-seed independent scans compare complete native membership, BM25 order/scores, own-filter facet counts and every page. Test zero/projected-out selections, revision/out-of-range races, missing capabilities, malformed results, abort/observer reentry and teardown. Fresh installed Node and real browser fixtures cover optional imports/types, explicit-disabled URL behavior, raw encoding/unrelated history state, invalid/stale URLs, Back/Forward during held work, disjoint/conflicting bindings and native write refusal. Run applicable regressions and the required full repository check; save actual commands/source/environment/review/limits before marking done. No human accessibility, physical-input, memory/latency or release qualification follows from this nonvisual slice.
