# Explicit record patch convenience — RX-A090

The owner explicitly selected RX-A090. `/addons/patch` exports `createPatch(engine)` and readonly `RecordPatch`, `RecordPatchSet`, `RecordPatchUnset`, and `Patches` types. A frozen borrowed handle exposes only `patch(request, options?): Promise<MutationResult>`. It requires a direct native owner; foreign facades and worker clients fail `MISSING_CAPABILITY`. It adds no ordinary engine method, participant, source retention, codec, schema migration, worker protocol, dependency, background work or UI behavior. Import and handle construction start no work. Engine disposal controls the borrowed handle.

`request` is `{ id, expectedRevision, set?, unset? }`. `expectedRevision` is a required nonnegative safe integer for the whole collection. At FIFO execution start it must equal the actual root revision, or the operation fails `REVISION_MISMATCH`. There is no retry/rebase, record-local revision, last-write-wins merge or optimistic read followed by a second queued replace. Even an unrelated committed write makes an older expected revision stale. Reads and mutations ahead of the patch retain ordinary FIFO order.

`set` is `{ text?: { [field]: string | readonly string[] }, metadata?: { [field]: Scalar | readonly Scalar[] } }`. `unset` is `{ text?: readonly string[], metadata?: readonly string[] }`. These address complete declared fields in their respective namespaces. There are no dotted/nested paths, array indices, append/splice, increments, JSON Merge Patch semantics or ID changes. A text scalar becomes the native one-value array; array assignment replaces the complete field value list. Empty strings/arrays are present values. Metadata `null` is an assigned value only for nullable fields, never deletion. Unset removes field presence; unsetting an already absent declared field is permitted. Omitted fields preserve their authoritative values. Unknown fields, duplicate unset names, set/unset overlap within a namespace, unknown keys, undefined, invalid types and malformed native data fail explicitly. At least one field action is required. A valid action, including setting the same value or unsetting an absent field, uses ordinary full-replacement semantics and commits one next revision with `replaced: 1`; it does not perform semantic equality suppression.

Patch and options use one synchronous native Admission budget and data-descriptor-only ownership capture before queueing; no user accessors are evaluated. Existing record/schema/array/string limits apply to assigned values, then to the fully assembled record. Unicode/content/analysis checks remain scheduled native mutation work. Admission/options failures use existing `RaveldexError` codes and fixed paths; malformed patch structure uses `INVALID_RECORD` (including a missing/invalid expected revision). No new error class or core error code is added.

At execution start, every schema text field must have an explicitly selected `raveldex-source-v1` provider at that exact revision and analyzer identity, even for a patch touching only metadata or one field. The selected record must exist in the core and each source directory. Missing coverage fails `MISSING_CAPABILITY`, stale provider roots `REVISION_MISMATCH`, incompatible roots `INCOMPATIBLE_CAPABILITY`, and absent core ID `ID_NOT_FOUND`. Validation order after admission is expected revision, complete source coverage, then record lookup. This deliberately refuses source-free/partial-source patching even if all text would be overwritten. Canonical metadata comes from the same immutable core record; source providers do not retain metadata. Missing text fields remain missing and explicit empty arrays remain present. Retained source text lengths must agree with the core record. Trusted provider implementations retain the existing trust boundary.

Composition reads only one record from the execution-start root, applies owned field actions and compiles a full replacement into the actual existing `MutationOwner.capture/execute('replace')` path. A narrow private execution seam keeps composition and replacement inside one admitted FIFO operation. It never reinitializes participants, creates a second engine or publishes a rebuilt root. All core and selected participant changes prepare privately and commit together. Source acquisition/composition and every yielded native replacement step share one complete `maxMutationWorkUnits` budget; native and participant caps remain stricter nested bounds. Source field/value/string traversal and metadata traversal are charged. Admission has its separate existing cap. No source/index cache or corpus scan is added. Logical work/bundle bytes are not heap/allocation/copy peaks.

Signal, admission-time deadline, queue capacity and engine disposal use the same native execution lifecycle as replace. Failed admission, stale revision, absent source/ID, invalid complete record, exhausted work, analyzer/participant failure, cancellation or deadline leave the exact previous core/participant root unchanged. Nested cursors close on failure. No stop check, work charge, yield or callback follows a completed native mutation cursor: its commit has already occurred. The handle does not support remote worker clients; applications may use full replacements through the existing worker API. No worker or snapshot format changes are included.

Verification compares patches with independently constructed complete records and source scans/native arithmetic; includes unset/null/empty/array cases, ownership/malformed inputs, source absence and stale roots, concurrent conflicts, selected participants, rollback and every observed cancellation suspension. Run installed and minified public consumers, public declarations, executable documentation and measured optional/core import graphs. Review the owner seam and resulting behavior independently. Publication and remote writes remain excluded. Static-build/Astro integration remains deferred.
