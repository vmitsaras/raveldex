# Explicit bounded query syntax — RX-A080

The explicitly selected optional slice adds `/addons/query-syntax`, `createQuerySyntax`, `QuerySyntaxError`, `QUERY_SYNTAX_ERROR_CODES` and `QUERY_SYNTAX_POLICY = 'explicit-boolean-fields-v1'`. It compiles to the existing public native Query tree, with no evaluator, scorer, index/participant, query rewrite in core, parser registration, host activity, UI change or runtime dependency. Ordinary engine string queries remain unchanged.

Factory `createQuerySyntax({ configuration, maxInputCodeUnits?, maxTokens?, maxDepth?, maxWorkUnits? })` captures the same validated Configuration used to create the destination engine, without initializing participants. It returns a frozen `QuerySyntaxParser` with synchronous `parse(input: string): Query`. The application supplies matching configuration; there is no engine introspection or liveness proof. The destination engine validates the returned raw tree again. Parser configuration changes require a new parser. Returned trees and arrays are owned/deep-frozen, with no mutable input references.

Grammar (explicit operators required): `or := and ('OR' and)*`; `and := unary ('AND' unary)*`; `unary := 'NOT' unary | primary`; `primary := WORD | WORD '*' | QUOTED | '(' or ')' | FIELD ':' primary`. NOT binds above AND above OR; NOT is right-associative. Same-level AND/OR chains form n-ary nodes; parentheses preserve nested Boolean structure. Field names are exact, case-sensitive declared text fields, never metadata. A field scope applies to its whole primary/group; nearest nested scope wins. Omitted fields select all schema text fields as in native queries. Whitespace may surround syntax tokens, including a field colon/prefix star. Adjacent operands without an operator are errors; there is no implicit AND or minus shorthand.

At operand position an unescaped WORD followed by colon takes field-scope precedence, including valid schema fields named AND/OR/NOT/XOR. Outside that field form, uppercase whole unescaped words AND/OR/NOT are operators. Other ordinary words, including uppercase words, are terms; fixed unsupported operator words XOR/NAND/NOR/NEAR/WITHIN are explicit UNSUPPORTED_OPERATOR errors when unescaped. Operator-like punctuation `! & | ~ ^ [ ] { } = < > ?` and a leading unescaped + or - are unsupported and reject. Bare words may include internal hyphens, dots, slashes and Unicode; they remain native text (which can analyze to multiple terms), not literal source predicates. Colon/parentheses/quotes/backslash/star delimit unescaped tokens. A single terminal star applies only to an unquoted WORD and produces a native exact-weight prefix group; embedded/repeated stars and star-only/quoted/group/field-scoped-group postfix stars fail. Quoted text produces the existing version-1 `phrases` leaf, not raw literal matching; installed capabilities and selected providers remain authoritative. Empty analyzed phrases retain native nonmatching behavior.

A backslash quotes the following complete Unicode code point literally in WORD or QUOTED text, including whitespace/operator letters. It is not a C/JSON escape: backslash-n becomes letter n. Any escaped character prevents that WORD from being recognized as an operator or field name. A trailing backslash is INVALID_ESCAPE. Quoted text uses double quotes; embedded double quotes/backslashes must be escaped. Unterminated quotes/groups fail, never become ordinary search. Well-formed Unicode is required throughout; malformed UTF-16 gets its exact offending code-unit span. Whitespace-only/empty input returns `{ kind: 'none' }`.

Default/max raw input is 2,048 UTF-16 units, syntax tokens 128, nesting 16, parse work 100,000; options only narrow and captured lower core input/depth limits apply. Every raw character scan, token/parser advance, node construction and native-analysis work step is charged. Token counting includes fields, colons, operators, parentheses, prefix stars and quoted/word operands; EOF is not a token. Nesting counts parenthesized groups, recursive field scopes and NOT; root nesting is zero. The generated native AST independently obeys captured maxQueryNodes/depth/strings/lexical/tokens/groups/variants and capability rules. Raw syntax limits do not replace native limits. Parsing is synchronous bounded work, not async cancellation; subsequent native search retains ordinary cancellation/deadline/work behavior. Configuration admission has the existing separate finite ceiling. Trusted implementation callbacks are not sandboxed.

Core capture/selected analysis validate the complete generated public tree; normalized output never replaces returned raw text. There is no second analyzer/evaluator or fallback. During parsing, native admission/capability/analysis failures become a fixed NATIVE_QUERY_ERROR diagnostic with the native error code (where available) and full expression span. Execution-only provider-field, revision and root checks run in the destination engine and retain ordinary native failures; parsing does not prepare live providers or prove their state. Diagnostic priority: a missing operand (including a standalone closing parenthesis or EOF immediately after an opener) uses EXPECTED_OPERAND; a closing parenthesis after a complete root expression uses UNEXPECTED_TOKEN; EOF after a valid grouped operand uses UNTERMINATED_GROUP over opener-to-EOF. An escaped WORD followed by colon is an invalid field attempt (UNKNOWN_FIELD), never a successful field scope. Syntax diagnostics have fixed codes/messages and half-open original UTF-16 `details.span: { start, end }`, including zero-width EOF spans. Error text/details never echo input, field values, analyzer exception messages, source, markup or arbitrary native paths; safe rendering still uses text APIs. The error object retains no source/query/cause. Factory option/configuration errors retain existing typed RaveldexError behavior.

Parse error codes are INVALID_INPUT, INVALID_UNICODE, UNEXPECTED_TOKEN, EXPECTED_OPERAND, EXPECTED_OPERATOR, UNKNOWN_FIELD, UNSUPPORTED_OPERATOR, UNTERMINATED_QUOTE, UNTERMINATED_GROUP, INVALID_ESCAPE, LIMIT_EXCEEDED, WORK_LIMIT_EXCEEDED and NATIVE_QUERY_ERROR. Readonly exported types are QuerySyntaxOptions, QuerySyntaxParser, QuerySyntaxErrorCode, QuerySyntaxSpan and QuerySyntaxErrorDetails. Parser policy is caller-side only; workers receive existing native AST envelopes and snapshots retain existing analyzer/capability identities, with no parser codec.

Verification uses handwritten exact trees/spans and generated expressions with independently constructed expected trees; compares complete native membership/scores/pages, reduced limits, selected analyzers, provider/phrase failures, mutations/restores and real worker messages. Preserve malformed/hostile/Unicode inputs, getter-free ownership and fixed diagnostics. Measure optional bundle graphs and bounded work separately from physical memory/copy peaks. Installed/minified public imports/declarations and the exact documentation example must run. Independent review and acceptance evidence precede done status. Metadata/literal/proximity/typo/synonym syntax, automatic UI/parser activation, wildcard-all, fuzzy/range syntax and a general language grammar are out of scope. No remote write or publication is authorized.
