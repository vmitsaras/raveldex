# Rich directory result presentation

Status: implemented by RX-7005, 2026-11-02, with scoped [acceptance evidence](../evidence/RX-7005.md). The [search-solutions contract](SEARCH_SOLUTIONS.md), [directory controller/URL contract](DIRECTORY.md), [base view contract](DIRECTORY_VIEW.md) and [implementation plan](../planning/SEARCH_SOLUTIONS_IMPLEMENTATION_PLAN.md) remain authoritative for native membership, ordering, totals, revision, paging, filters, ownership and URL behavior.

## Entry and explicit projection

`@vmitsaras/raveldex/addons/ui/directory/cards` exports `mountRaveldexDirectoryCards` and readonly card types. It is separate from `/addons/ui/directory/view`. Importing either entry does not discover a root, create an engine/controller, search, request images or inject CSS. Import `/addons/ui/directory.css` and `/addons/ui/directory-cards.css` explicitly for rich presentation. Core, providers, the nonvisual directory/URL entry, static artifact formats and earlier starter projects do not change.

Card options retain the required root, borrowed live controller, display documents and configured group labels of the base view. Each document has required `id`, `title`, `url` and optional declared plain-text `excerpt`, `category`, `breadcrumb` (ordered text parts), `date` (already localized text), `fields` (`{name,value}` pairs) and `image` (`{src,alt,width,height}`). The projection is supplied by the application; no arbitrary HTML/template/renderer callback, extractor, remote metadata discovery, automatic date parsing, commerce action or new sorting exists. Dates are text, without an invented machine-readable time value. Breadcrumb parts are descriptive text rather than invented navigable ancestors.

Capture is strict own-data admission before authored DOM is replaced, including images when their display starts disabled. At most 10,000 documents and 4,000,000 aggregate original string units are admitted. The rich-data admission budget is 300,000 work units. Existing ID/title/URL bounds are 256/1,024/2,048 UTF-16 units. Excerpts are at most 4,096; category/date 256 each. Breadcrumbs contain at most eight parts of 256. Named fields contain at most four pairs with unique names of 128 and values of 1,024. Optional empty strings omit their output; nonempty whitespace/control-only text refuses rather than providing an unreadable label. Nested getters, unknown keys, duplicate IDs and invalid bounded data refuse without replacing the authored root.

Image source strings are at most 2,048 units, resolved against the supplied root's document base at capture, with HTTP(S) and no credentials. Alternative text is required: the empty string deliberately means decorative, otherwise readable text at most 1,024 units. Intrinsic width and height are required integers 1..4,096. Result links retain the base HTTP(S)/no-credentials navigation boundary. Text is inserted with text nodes; metadata does not become HTML or executable URLs.

## Presentation and lifecycle

`presentation` is an optional partial `{layout,density,images}`. Layout is `list`, `cards` or `grid`; density is `compact` or `comfortable`; images is boolean. Defaults are `list`, `comfortable`, false. `imageUnavailable` optionally supplies readable localized failure text, at most 512 units, default `Image unavailable`.

The handle preserves `search`, `clear`, `destroy` and adds synchronous `setPresentation(partial)` plus `getPresentation()` returning the captured complete readonly presentation. A change validates before effects, updates the existing result presentation, and does not query, write history or alter native query, filters, selected choices, page, exact total, IDs or their order. Existing result link Nodes/focus survive layout/density/image changes. Query-driven replacement retains the base focus and draft/composition safeguards. Duplicate mounts of the same preset return the existing handle after admission; conflicting base/cards/other preset ownership refuses.

Results remain an ordered HTML list of list items and ordinary navigation links, with DOM order equal to native result order. Grid is CSS layout, without ARIA grid/cell roles or arrow-key selection. The supplied projection does not mutate the engine or provide a second result set. Missing optional metadata produces no empty heading or broken item. Long localized content wraps without truncating essential text. Named metadata uses description-list semantics; category/breadcrumb/date remain readable plain text.

Image elements and sources are created only when images are explicitly enabled, only for the displayed native page. They use authored dimensions/reserved aspect ratio, native lazy loading, asynchronous decoding and no-referrer policy. Native lazy-load timing/cache/reuse is browser-owned; enabling does not guarantee every image is immediately fetched, and disabling cannot undo a request already sent. Disabling removes image presentation and its callbacks without removing or recreating result links. Enabling again may make a new request; there is no automatic retry or alternate source.

A failed informative image retains readable failure text and its authored alternative meaning; a failed decorative image remains silent. The title/link and metadata remain usable. Late detached image events cannot change a newer page, destroyed view or foreign replacement. Per-page image listeners are removed when results are replaced; teardown is bounded and idempotent, restores authored Node identity when still owned, and never destroys/disposes the borrowed controller/engine.

## CSS and adoption

Rich styling uses `.raveldex-directory-cards` and component-scoped `__*` classes over the existing controls. Public properties cover card surface/border/radius/padding/gap, compact padding, minimum grid column width and image size/fit; internal properties remain private `--_` values. Layout preserves source order, has no masonry/dense reordering, and supports narrow/RTL, light/dark/forced colors, visible focus and static reduced-motion behavior. CSS is optional and cannot select images or change query state.

One complete browser project, `examples/cards-browser`, provides explicit metadata mapping, real resource routes and local authored image assets. Native layout/density/image controls demonstrate changing presentation without new queries. Images start off. Its content/configuration/CSS, loading and Retry, optional URL ownership, no-JavaScript browse links, owner disposal and page lifecycle follow the existing browser directory pattern. It does not require a new static artifact version. The gallery publishes exact allowlisted source downloads/archive, an actually installed preview and CSS recipes.

## Verification boundaries

Acceptance requires independent IDs/order/totals/pages across view changes, unchanged query/filter/selection/URL, strict unsafe/hostile/missing/long metadata admission/rendering, deliberate alternatives/dimensions and actual image request/failure observations. Installed copied-project root/subdirectory builds must demonstrate data/CSS edits, real destinations and cleanup. Browser interaction, emulated themes/reflow/axe, optional graph/CSS bytes and per-page DOM/image observations are separate evidence. Neither output bytes nor DOM counts establish retained/peak memory, paint/latency or universal capacity.

Human AT speech, physical IME/touch/mobile keyboards, real browser zoom, native Safari/device support and remote/hosted/release qualification require actual separately identified observations. Automated checks do not establish those claims. The browser image attributes and description-list semantics were checked against [MDN image documentation](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/img) and [MDN description lists](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/dl); repository/runtime evidence controls implementation claims.
