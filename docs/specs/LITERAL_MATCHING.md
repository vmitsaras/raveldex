# Explicit literal and infix matching — RX-A060

Status: adopted for the owner's October 29, 2026 explicit RX-A060 selection. This first bounded slice uses raw case-sensitive source substrings. No other optional feature or publication is activated.

## Semantic contract

`/addons/literal` exports `createLiteral`, `LITERAL_POLICY = 'raw-substring-v1'` and readonly payload/evidence types. Explicit registration requires enabled text fields and separately installed authoritative source providers for all of them. It never retains originals, positions, an n-gram index or a cache automatically. Importing core or this optional entry starts no host work.

Only an explicit query extension `{ kind: 'extension', capability: 'literal', version: 1, payload: { text, fields? } }` requests matching. Preserve text exactly, including punctuation, whitespace, case and combining marks; reject empty text rather than introducing a zero-width match-all. Compare well-formed original Unicode strings without normalization, lowercasing, tokenization, stemming or accent folding. A match may start/end inside a token and is therefore infix matching as well as literal matching. Slashes, dots, underscores and spaces are actual source characters, not query syntax or analyzer separators.

One leaf matches a document if its exact substring occurs in at least one original value of one selected field. It cannot join values or fields. Fields default to the factory's enabled fields; an explicit subset must be nonempty, unique and enabled. Canonical field order is UTF-16 ascending. Enclosing AND/OR/NOT uses existing complete Boolean semantics; separate AND leaves may match independent values/fields. Missing record fields/empty values are ordinary nonmatches; a missing authoritative source record or incompatible provider header is a typed consistency/capability failure, including before empty/failed branches.

Pure literal predicates contribute no lexical groups and score **0**, with native record-ID tie ordering and exact document totals/pages. A mixed lexical/literal query keeps only the existing successful lexical groups' native BM25. Literal occurrence count, length or position creates no hidden ranking bonus. Ordinary strings, exact/prefix groups, strict phrases, typo/synonyms/suggestions and all analyzers retain their contracts. Literal eligibility itself is the same under basic, English and identifier analysis because it reads originals.

## Unicode and evidence

Validate malformed UTF-16 through resumable work. Well-formed needles can match only at valid code-point boundaries in well-formed source. Report every overlapping occurrence when evidence is requested, with half-open original UTF-16 coordinates. `ababa` / `aba` has `[0,3)` and `[2,5)`; an emoji consumes two UTF-16 units. Canonically/compatibly equivalent spellings remain distinct (`café` versus `cafe` plus combining acute, `ﬃ` versus `ffi`, fullwidth versus ASCII). There is no caseless or locale equivalence.

These are code-point/string semantics, not grapheme matching: `cafe` can match the first four units of decomposed `café`, and a combining-mark needle can match the mark itself. Exact ranges may divide a grapheme. This slice does not feed such ranges into token-oriented snippet/position evidence or alter UI highlighting.

The same registration accepts `options.extensions.literal = { ids, maxRanges?, expectedRevision?, maxFacts? }` for bounded factual output. `LiteralEvidenceData` is `{ kind: 'raveldex-literal-evidence-v1', policy, revision, scope: 'successful-positive-literal-occurrences', complete: true, leaves, documents }`. Leaves are `{ path, text, fields }` for all compiled literal descriptors, including negative/failed branches. Each requested document is `{ id, eligibility, ranges }`; ranges `{ leaf, field, valueIndex, start, end }` refer only to successful positive literal paths in an actually matched document. NOT never supplies ranges; failed AND branches cannot donate ranges to a successful OR sibling. No token ordinal, normalized term or invented numerical contribution is emitted. Absent/excluded IDs have no ranges. Range bounds exhaust the complete operation rather than silently truncate output.

The existing one-evidence-request restriction remains; literal evidence and Inspector/token evidence cannot both request competing full traces in one search. Optional ordinary Inspector may independently report actual zero-group predicate facts and unchanged lexical arithmetic.

## Protocol, execution and costs

The new trusted `sourcePredicate` handle uses the existing leaf-refinement role, separately from metadata predicates and token-sequence refinements. Capture owns bounded payloads. Prepare receives immutable schema/limits/analyzer/revision/payload and access only to declared source requirements; test receives an opaque document ID. Core compiles this as an existing zero-group predicate and traverses every document. No mutable owner, scorer, postings root or host is passed. Only the exact configured source-field requirements are permitted; extra non-source dependencies reject. Every configured source requirement is checked at registration/prepare even if no document can match.

The source scan uses resumable bounded KMP (including overlaps) and no mandatory accelerator. Pure membership can stop after the first occurrence in a document; totals still qualify every document. Evidence separately enumerates all relevant occurrences for explicitly requested IDs. The immutable needle table/temporary source windows are operation-local; no registration/corpus cache survives the search. Source providers keep their existing transactional/source/native codecs. Add/replace/remove/clear/recovery become visible at one execution revision; snapshot/worker identities bind the exact options and policy. Native restore retains its exact-Node qualification boundary.

Factory options are `{ fields, id?, maxWorkUnits?, maxRanges?, maxOutputEntries? }`. Default ID/capability is `literal`; a custom registration ID does not rename the capability. Default maximum work is 10,000,000 work-v1 units, only narrowable; shared core query work/deadline/cancellation can be stricter. Default evidence maximum is 256 ranges, configurable within 1–1024; per-request caps can only narrow it. Output structural entries default to the existing 16,384 admission ceiling, only narrowable, with the reused factual-output 262,144 aggregate UTF-16 text ceiling. Evidence selects at most 128 IDs and 4,096 facts, further limited by core bounds. One registration work budget covers all query leaves, prepare/test/evidence cursors and aliases in one operation.

Raw literal text plus selected field strings is bounded by 2,048 UTF-16 units and the reduced core lexical ceiling. All source-predicate captured payload strings conservatively count toward the shared query lexical ceiling; all query strings still obey the existing total query limit. Source strings keep existing per-value/record/corpus bounds. Scanning, needle preparation, comparisons, copying, output and validation are charged, with stop checks after trusted cursor advancement before module charging. Work/output/capability/stop failures reject complete operations; no partial totals or incomplete-success mode exists.

Measure code graphs and actual query work separately from source retention, heap/allocation peaks, transport copies or physical latency. Any future n-gram acceleration needs equivalent complete results and measured justification; none is introduced here.
