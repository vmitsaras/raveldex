# Explicit static-build and Astro integration — RX-A100

## Optional page/section companion — RX-6005

The frozen [page/section contract](PAGE_SECTIONS.md#7-separate-optional-static-artifact) selects a separate version-1 companion for RX-6005. It is implemented as an optional parallel builder/hook input and explicit source-handle `loadSections` method. Existing manifest, display-record, safe directory-route and source/native snapshot formats below remain unchanged. The input is a separate optional map list; full-ID companion pages bind to build/base/configuration/source/display identity. Explicit source-handle section loading validates original ranges through a transient public source export and stamps the receiving revision; it does not use the builder's origin revision. Native handles refuse that optional operation while ordinary qualified-native loading/search remains valid. No automatic source retention, HTML extraction, extra initial fetch or weakening of current strict readers is authorized.

## Current implementation

The owner explicitly selected RX-A100. A separately installed private ESM package `@vmitsaras/raveldex-astro` exposes `.` (Node Astro integration), `/build` (explicit artifact builder), and `/client` (explicit browser/Node loader). It uses only existing public Raveldex imports. The root package, core source/public facade, analyzer/scorer, source/native codecs, UI and worker protocols remain unchanged. Astro is a pinned development tool for real consumer verification and an optional framework peer of the separate package; it is never a runtime dependency of core. No crawler, Markdown/HTML parser, inferred content discovery, framework initialization or network access is added to core. Importing any entry performs no I/O, indexing or fetch.

## Explicit content and generation

`buildStaticSearch({ configuration, entries, buildId, base?, nativeQualification? }): Promise<StaticArtifacts>` accepts an explicit readonly array of `{ record: RecordInput, title: string, path: string }`. `record.id` is the unique opaque ID; no URL/slug-derived implicit ID or undeclared fields are invented. Each path is an absolute safe same-site pathname, without authority/scheme, query, fragment, backslash, encoded separators, empty/dot/traversal segments; bounded ASCII path segments and a terminal slash are required in this first directory-output slice. `base` is `/` by default or the same safe pathname prefix. Result URLs concatenate this captured deployment base and path, independent of the current nested browser URL. The application selects published entries; excluded/draft pages may exist without becoming searchable. Extraction and rendering belong to the content application. IDs/title/URLs form separate display data; index text is exactly the supplied record text. Empty allowlists are valid; duplicate IDs and malformed data fail completely.

`buildId` is a required application generation token, `[A-Za-z0-9][A-Za-z0-9._-]{0,63}`. The application changes it for a new release/content generation. Each build is a complete private reconstruction using public addMany calls, then exports the existing `raveldex-source` snapshot. Complete explicit source providers for every schema text field are required; the adapter does not silently retain originals. The optional supplied exact-Node `NativeSnapshotQualification` constructs the existing qualified owner and additionally exports `raveldex-native`. Every engine is disposed after the build, including failure. Accepted record data is owned synchronously before the first await; native construction captures configuration/handles. Caller getters/toJSON are never invoked for record/display data; trusted implementation callbacks remain outside a hostile-code sandbox. Native record/schema/analysis/work/codec limits apply; source export can refuse a corpus built in batches.

`StaticArtifacts` is deeply frozen `{ manifest, files }`, where files maps safe basenames to JSON strings, including `manifest.json`. A version1 `raveldex-static-search` manifest contains buildId, normalized base, recordCount, configurationSha256, documentIdsSha256, and assets `{ source, documents, native? }`. Each descriptor is `{ file, bytes, sha256 }`; snapshot names are `source-<sha256>.json`/`native-<sha256>.json`, display names `documents-<sha256>.json`. The independently hashed documents envelope is `{ kind:'raveldex-static-documents', version:1, buildId, documents:[{id,title,url}] }`. Document ID identity hashes the sorted IDs, not titles. Assets are content addressed; manifest is the last build file. SHA-256 detects corrupt/mixed artifacts and is not sender authentication. The application must trust the endpoint/publisher.

The configuration identity hashes a canonical bounded subset of the actual public snapshot header: schemaVersion, schema, analyzer ID, ranking, ordered capability manifests, indexDetail and normalized limits. Source environmentProfile/nativeQualification/originRevision are deliberately excluded: source rebuilds use the receiving environment under the same analyzer ID; no cross-environment equality of Unicode results/scores is promised. Existing native restore still requires exact profile/environment/evidence/schema/capability/limits compatibility. Changing capabilities/analyzer/schema/limits requires matching receiver configuration and a fresh generation.

Finite adapter ceilings: 10,000 entries; 1,000,000 owned input structure entries/depth16; title1,024 UTF-16, path/base512, buildId64; 256KiB manifest/configuration identity JSON, configuration canonical depth16/16,384 entries; 4MiB display JSON; 64MiB each snapshot UTF-8. These only narrow native limits. Hashing, JSON parsing/stringification and ownership have bounded nonpreemptible host sections; no hard wall-time, allocation or peak-copy guarantee is made.

## Explicit runtime load

`loadStaticSearch({ manifestUrl, expectedBuildId, configuration, format?, nativeQualification?, fetch?, signal?, timeoutMs? }): Promise<LoadedStaticSearch>` defaults to source. The explicit absolute HTTP(S) manifest URL has no credentials/query/fragment and ends `/raveldex/manifest.json`. Its pathname must equal the captured manifest base plus `raveldex/manifest.json`, so a misplaced generation fails before any asset request. Asset requests resolve only safe manifest basenames in that same directory, forbid redirects and never discover URLs from document text. SHA-256 requires lazy WebCrypto SubtleCrypto (Node22+ or a secure browser context); unavailable crypto refuses explicitly. Fetch may be injected for host/testing; otherwise it is read only on an explicit load. There is no import-time request. Each response also has a 1,000,000 reader-advance cap, including zero-byte chunks. Finite streamed response reads enforce expected byte count and maximum before decoding fatal UTF-8, then verify SHA-256. Default request timeout30,000ms, selectable1–120,000ms, applies to each network read. Signals/cancellation and native restore retain their distinct typed outcomes. HTTP404/missing native asset, other fetch errors, malformed/incompatible data, stale expectedBuildId, byte/hash corruption and disposal fail explicitly with fixed safe diagnostics.

After manifest checks the loader creates a fresh private direct owner using matching configuration; an empty public source export supplies its canonical configuration identity. Fingerprints must match before restoring the selected hashed snapshot. The snapshot decoder validates its actual header/state independently. Before exposing the restored candidate, a complete public source re-export derives actual record IDs and checks both count and ID digest against the manifest. This adds a bounded public codec pass and may refuse encoding/work even after successful restore; the unpublished candidate is disposed on such failure. No private native-directory parsing or fast-native-load claim is introduced. Native loading uses supplied existing exact-Node qualification; browser-native loading refuses rather than falling back. A failed/cancelled/incompatible load disposes the unpublished owner. Loading never replaces an application-owned engine or silently retries. Successful load returns frozen `{ engine, manifest, loadDocuments, dispose }`; the application owns that handle and disposes it explicitly. Generation updates load a separate candidate, then the application swaps it after success and disposes the previous handle.

The initial load fetches only manifest and selected snapshot. `loadDocuments(options?)` explicitly fetches the separate display envelope, verifies build ID, count, unique IDs/ID digest, safe base-relative URLs and bounded data, then returns frozen UIDocument-compatible data. It does not mount UI or fetch source pages. Calls are not implicitly cached. Display data belongs to the immutable artifact generation; applications mutating the returned engine manage their own display changes. `dispose()` closes admission, aborts active display reads, and disposes the owned engine idempotently. No module cache/storage/worker/service-worker is created. Existing UI mounts only after the application chooses to load documents; its focus, composition, stale-response and teardown policy remain unchanged.

Public runtime exports are buildStaticSearch from `/build`; loadStaticSearch from `/client`; default integration from `.`. Shared StaticSearchError/STATIC_SEARCH_ERROR_CODES are exported by build/client. Fixed codes are INVALID_INPUT, INVALID_ARTIFACT, STALE_BUILD, INCOMPATIBLE_ARTIFACT, MISSING_ARTIFACT, INTEGRITY_MISMATCH, ASSET_LIMIT, FETCH_FAILED, CANCELLED, DISPOSED. Error messages never echo content/URLs/exception causes. Existing RaveldexError/SnapshotAdapterError failures remain typed and separate. Public readonly types describe entries, options, manifest/descriptors, artifacts, loaded handle and loadDocuments options; no private core type import is permitted.

## Astro hook and real consumer

The default `raveldexAstro({ configuration, getEntries, buildId, nativeQualification? })` factory captures trusted build callback/constant options without invoking them. `getEntries()` runs only at `astro:build:done`; config captures normalized base and requires static directory output. No dev-server/watch generation or SSR adapter is supplied. It writes under the reserved output `raveldex/` directory using exclusive creation: an existing namespace or symlink is refused without overwriting. Complete artifacts prepare first; content files are written with exclusive flags and manifest last. A write/build failure aborts the site build; a partial unreferenced fresh namespace may remain and must not be deployed. Deployment/atomic site replacement and old-generation retention are application concerns. Pages/assets outside that newly owned namespace are never modified.

Use the official [Astro integration hooks](https://docs.astro.build/en/reference/integrations-reference/) and [base-path contract](https://docs.astro.build/en/reference/configuration-reference/#base). The actual fixture uses the separately packed integration plus packed public core and pinned Astro7.3.2. Its explicit shared allowlist contains real Raveldex documentation prose and is rendered by genuine .astro pages. Test missing/stale/mixed/incompatible assets, full update/recovery, stream bounds, deadlines/cancellation/disposal, native exact-Node compatibility and browser refusal. Inspect actual root/core/client/build/hook graphs and peer/runtime dependencies; record bytes separately from physical heap/copy peaks.
