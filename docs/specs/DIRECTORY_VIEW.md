# Directory controls and installed adoption — RX-7004

This additive slice implements SS-12 controls over the frozen [directory state/URL contract](DIRECTORY.md). The nonvisual `/addons/ui/directory` entry and its ES2022-only declarations stay unchanged. The DOM-only `/addons/ui/directory/view` entry exports `mountRaveldexDirectory` and readonly view types; `/addons/ui/directory.css` is a separate explicit asset. No imports mount/discover a host, create an engine, install capabilities, fetch, write history or open storage.

## Borrowed view contract

Options are `{root, controller, documents, groups, debounceMs?, filtersOpen?, messages?}`. The controller must be a live `createDirectory` handle. Documents retain the existing `{id,title,url}` allowlist and 10,000-entry / 4,000,000 aggregate text-unit display bound; IDs/titles/raw URLs are bounded to 256/1,024/2,048 units. Only HTTP(S) URLs without credentials are admitted, resolved against the explicit root's document. Missing displayed IDs or impossible display totals refuse visibly rather than silently skipping results. A view borrows the controller; it never destroys it or its owner. The application destroys view, URL binding, controller, then its owned loader/engine.

Each `groups` item is `{field,label,values?:[{value,label}]}`. Supply exactly the controller's configured fields, once each. Value labels can map only distinct allowed strings; omitted labels use the raw string, with an explicit empty-string label. Group labels are at most 256 units, explicit value/message labels 512; text must be well-formed and contain more than whitespace/control characters. Default raw value labels retain the controller's 1,024-unit value bound; a nonempty whitespace/control-only value needs an explicit readable label. Configuration/caller arrays are captured before replacing authored content. Group/value/selection/page bounds remain RX-7003's bounds. Invalid options throw before replacing the root. There are no arbitrary HTML renderers.

`search(text?)` flushes the current controls, or validates an explicit raw text value before changing anything and preserves committed filters. Explicit text cancels draft composition; late composition events cannot revive it. `clear()` clears text and all groups, resets page one and browses all resources. `destroy()` is idempotent, clears debounce/listeners/observer, restores the original Node objects when its shell still owns the root, and leaves a foreign replacement intact. Later methods do nothing. Same-kind duplicate mount returns the existing handle; another preset cannot own the root. Controller destruction also destroys its view. Foreign-document adoption suspends view commands/presentation; teardown remains available. Focus reads only the supplied root's own document/shadow tree, including a caller-known closed root, without discovering unrelated opaque trees. A shadow-root caller supplies its own stylesheet inside that tree. Detached same-document roots may be explicitly prepared.

Mount reads the current snapshot but starts no query. The starter explicitly reads URL state or refreshes to start browsing. Public methods and observations remain the RX-7003 controller API; no CustomEvent contract, bus or shared global state is added. Pending/late results, aborted work, reentrant focus callbacks and controller recovery cannot overwrite a newer view draft/command or restore destroyed markup. Chip actions are delegated so repeated selection/removal does not retain an unbounded listener history.

## Controls, focus and status

RX-9105's [feedback contract](N11_CONSUMER_CONTRACT.md) distinguishes text-only, filtered and empty browse feedback. Optional `noResultsFiltered` and `noResultsBrowse` preserve old complete message bundles; an existing `noResults` override covers both unless individually overridden. Empty templates support the plain-text submitted `{query}` preview (160 Unicode code points plus an ellipsis); input and native queries remain complete. Default failures use friendly recovery text; typed controller errors and an `error` override with `{code}` retain diagnostics. Empty browse enables the existing Refresh results button for deliberate activation without polling or an automatic query. Cards share this behavior.

A labeled native search input, submit and Clear all form appear before a native `details` / `summary` filter disclosure. Each configured group is a `fieldset` / `legend` with persistent native checkboxes/labels and text counts. The disclosure defaults closed at all widths (`filtersOpen: true` explicitly opens it). No resize handler silently closes focused content. The Close filters button or Escape inside open filters closes and restores its summary focus. Native summary activation keeps native disclosure behavior; Tab follows the ordinary document order, with no trap.

Checkbox edits combine through the existing controller, with OR within a group and AND across groups/text. The shared visible `countHint` explains this without Boolean jargon: counts cover all current results matching the search and selected filters, not just the current page; any selected choice within a group may match, and each other selected group must also match. Adding a zero-current-count choice alongside another choice in its group can expand results. This captured plain-text override retains its 512-unit bound and is shared by base directory, list, cards and grid; reading or opening help starts no query.

Counts remain native conjunctive counts over the complete current qualifying set, including own selections. In the exclusive-type example, three Guides and two Manuals give Guide (3), Manual (0) after selecting Guide; selecting Manual as well expands to five results. Selecting a topic in another group then restricts those results to the topic. Complete missing buckets show zero, omitted counts show unavailable, and selected zero/omitted values stay checked/removable. Zero-count choices remain enabled. Native missing/null buckets are informational, not selectable values. No predicted/disjunctive counts, new filter logic or approximate totals are introduced.

Selected filters form a semantic list of named removal buttons. Stable checkboxes/chips preserve focus. Removing a focused or explicitly activated chip moves to its next surviving chip in DOM order, then previous, then the search input. Clear all retains its stable button. Query/selection edits reset page one; persistent Previous/Next buttons reach every native page, with exact page/range/total summaries. Unavailable actions use guarded aria-disabled and remain focusable. Once exposed, navigation and Retry stay visible through loading, refusal and recovery; stale page summaries are cleared and unavailable actions cannot submit duplicate work. Removed result focus recovers to the input, with freshness checked again after focus callbacks.

Input schedules work after 150ms by default (0..2,000 configurable). Draft input clears stale results/count presentation immediately. Composition defers both text and checkbox draft commits; provisional words are never queried. External state/URL replay wins over a pending draft/composition, while an older asynchronous page recovery cannot discard newer draft text. Late ignored-abort results remain suppressed by the controller; view teardown unsubscribes without cancelling another borrower's work.

One deliberate live status outside the busy results section reports waiting/composition/searching, exact current totals, empty recovery, native failure, stale revision and invalid selection bounds. Retry calls explicit refresh at page one; no silent capability installation. Loading clears old hits/counts, retains selections and keeps recovery controls operable. Programmatic/native checkbox-limit refusal restores the last admitted state with a visible explanation. Messages are captured plain text templates, at most 512 units; results/link titles are inserted with textContent, never HTML.

## Styling and installed delivery

Public CSS classes use `.raveldex-directory` / `.raveldex-directory__*`; `data-raveldex-directory-*` hooks are internal/test hooks, not alternative authored markup. Component public properties cover accent, background, color, muted, border, focus, button color, radius, gap and padding. Private properties use `--_`. Native checkbox focus, non-color unavailable state, wrapping long/RTL labels, dark/forced colors and static reduced-motion behavior are required. No card/grid, images, metadata projection, new sorting or numeric ranges are introduced; those remain later slices.

Deliver complete copied browser and Astro projects with explicit public resource records and real destinations, pinned existing tooling, root/subdirectory builds, required filters/facets, optional named URL ownership and authored browse fallbacks. Browser loading indexes the explicit records; Astro reuses the static allowlist/source loader and matching configuration rather than adding a crawler or artifact format. Their application wrappers deduplicate/cancel loading, dispose late owners, initialize one coherent controller/view/URL binding, recover initialization failures and stop on pagehide before rebuilding on persisted pageshow. A complete directory gallery supplies installed preview, exact allowlisted source/archive downloads and an edit/build/preview CSS recipe.
