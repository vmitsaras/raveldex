# Documentation search modal — RX-6006

Status: modal runtime implemented and locally verified in RX-6006, 2026-11-01. This completes the local API/lifecycle details of [SS-10](SEARCH_SOLUTIONS.md#ss-10--documentation-modal) without changing the frozen [page/section contract](PAGE_SECTIONS.md). RX-6007 adds first-open application wrappers and complete browser/Astro starters under the separate ownership rules below; the public modal continues to accept an already supplied borrowed owner and display data.

## Public surface and capture

Separate optional entry `/addons/ui/modal` exports only `mountRaveldexModal` at runtime, with readonly types `ModalUIOptions`, `ModalUIHandle`, `ModalUIMessages`. `/addons/ui/modal.css` is an explicit independent CSS selection that includes the existing inline stylesheet through a local CSS import. JavaScript never imports/injects CSS. No core, provider, worker, network, storage or framework initialization on import or mount; mount starts closed and performs no search.

`ModalUIOptions` includes the existing `InlineUIOptions` fields, including root, borrowed engine, owned documents, existing inline messages, optional facets/snippets/maps and their unchanged validation/limits. Additional properties are:

| Property | Contract |
| --- | --- |
| `trigger` | Required existing accessible native `HTMLButtonElement`, in the same document as root. Root/trigger must be connected at mount; trigger is outside root. Reject a trigger owned by another modal before changing either surface. |
| `resetOnClose?` | Boolean, default false. Preserve the current input and facet selections by default; true clears both on close. Results/counts/errors are discarded on every close. |
| `shortcut?` | Boolean, default false. Opt into the coordinated Ctrl+K or Meta+K binding, without Alt/Shift. |
| `keyboardHints?` | Boolean, default true. Show contextual footer hints; keyboard shortcuts still work when hints are hidden. |
| `modalMessages?` | Captured partial `ModalUIMessages`: `title`, `close`, `escapeHint`, `shortcutHint`. Plain nonblank strings, same 512-unit/Unicode/accessor rules as inline messages; reject extras. Defaults: “Search documentation”, “Close search”, “Esc to close”, “Ctrl/⌘ K”. |

Every option is synchronously captured and validated before replacing authored root nodes or changing the trigger. Use existing structural section capture and native deferred source validation. Root ownership is shared with legacy/inline: repeating a modal mount returns its frozen existing handle; a conflicting preset fails before replacement. Independent roots have unique dialog/label IDs. The implementation claims ownership before authored-node callbacks can reenter.

The frozen handle extends inline `search(text?)`, `clear()`, `destroy()` with `open(): void` and `close(): void`. Search while closed may replace the stored input but makes no native request and does not open. Clear works without opening. Open/close are idempotent. Methods after destroy are harmless no-ops. Invalid supplied search text still uses existing inline validation while the handle is alive. No public loader callback, owned-engine disposal, event bus or extra core API.

## Structure, focus and native interaction

RX-9106's default `escapeHint` makes Close search the reliable close action and notes that Escape may clear a focused native search field first. Visible hint IDs describe the search input; shortcut guidance/reference appears only with `shortcut:true`. `keyboardHints:false` omits footer and references without disabling an opted-in shortcut. The bounded footer is now a focusable, named scrollable group with an inset visible focus outline; long translations remain available through native keyboard scrolling rather than line clamps. This adds one deliberate help stop to native Tab traversal and changes no editing, dismissal or focus-restoration handlers.

The root owns a native `<dialog>` with an accessible heading, explicit close button, inline search form, a contained scroll body for feedback/results/navigation, and optional contextual footer hints. The header/close and search input stay reachable while results scroll. Use `.raveldex-modal`, `__header`, `__title`, `__close`, `__search`, `__body`, `__footer`, `__hint` classes; inline classes remain the inner presentation hooks. Heading-level metadata never selects arbitrary result heading elements.

Use `showModal()` and native modal focus containment, without an ARIA recreation, blanket Tab loop or global focus trap. The input is the initial autofocus target and is explicitly focused with preventScroll when needed. Native dialog support is required and checked before DOM replacement. Root/dialog adoption or detachment after mount prevents opening until usable in the captured document. A different native modal found in the document or active/known shadow trees blocks this instance from opening or claiming a shortcut. Root/trigger shadow trees are captured explicitly. Focus on an unknown opaque shadow-capable host is conservatively refused, including ordinary focusable `div`, `main`, `section` or similar page regions without an inspectable shadow root; a native trigger remains the reliable entry. The ordinary BODY/no-useful-focus fallback is exempt; an unknown body-attached closed tree cannot be distinguished from that fallback. This is not discovery of all externally concealed/inactive shadow trees. Applications coordinate uninspectable external modal lifecycles explicitly; the library never automatically closes an unrelated dialog.

Trigger activation records that trigger as actual opener. Programmatic/shortcut open records the current connected same-document focus target (falling back to the trigger when body/no useful opener is focused). Close restores the connected actual opener when focus belonged to this session; removal of the opener, another active modal or reentrant focus/close/destroy/open callbacks must not steal unrelated focus. Treat native queued close events from an older session as stale when a newer session is open.

Escape uses the native cancel event, routed through the same cancellation/cleanup path as explicit close. Preserve native search-field editing: a browser can consume the first Escape to clear a focused nonempty search field before a later Escape cancels the dialog. The visible close action remains available. Native close events also clean up an externally closed dialog. Set `closedby="closerequest"`; do not rely on newer automatic light-dismiss behavior. Deliberate backdrop dismissal requires primary-button down and up outside the dialog rectangle in the same open generation, followed by the matching outside click. Inside-to-outside or outside-to-inside drags, pointer cancel, another pointer, secondary buttons and old gestures do not dismiss. A native `dialog.close()` queues its close event: existing hidden feedback may remain until that event, but a late reply must not change it or begin further context work. Library `close()` suspends and clears synchronously. Keep ordinary link navigation and modifier behavior; result clicks are not intercepted to emulate routing.

Trigger changes are owned and reversible: button type, `aria-haspopup`, `aria-controls`, `aria-expanded` and optional `aria-keyshortcuts`. Restore exact previous values on destroy only when they still equal the last owned value, preserving distinguishable application changes. Never replace its authored children or label. Same-value external writes cannot be distinguished from the instance's own state.

## Presentation lifecycle and shortcuts

Use a private inline suspension seam, not a new public inline option. Pause before closing: invalidate the generation, clear debounce/composition state, abort the active main/context sequence, clear results/counts/retry and suppress any late DOM/status/focus writes. Preserve input/facet values unless reset was selected. Retain owned captured maps while the modal remains mounted; release them on destroy through the existing inline destroy path. Reopen resumes and reruns the ordinary first native page from current controls, including revision/map checks. An empty unfiltered query stays idle and makes no native request.

Shortcuts are opt-in per instance and coordinated per document with one owned keydown listener. Respect defaultPrevented, repeat, composition/229, Alt/Shift, editable controls/contenteditable and editable active/known shadow paths. Match only K with exactly one of Control/Meta. If an owned eligible modal is open, target it only; otherwise the first connected enabled opt-in registration wins deterministically. Repeated open does not issue duplicate queries. Unrelated/native dialogs, destroyed/disconnected roots and disabled triggers cannot claim a shortcut. Only a handled shortcut calls preventDefault; do not stop propagation. Destroy unregisters, releasing the document listener when the final opt-in instance leaves. No listener is installed for inline or shortcut-disabled modals.

While open, own only the page overflow changes required to contain scrolling; preserve preexisting inline values/priorities and restore only unchanged owned values. Preserve scroll coordinates by avoiding page positioning or scrollTo restoration. The native dialog/focus/scroll behavior remains browser-owned; no global touch/wheel suppression. Nested/unrelated application scroll writes with indistinguishable identical values are not an ownership-authentication guarantee.

Destroy closes/cancels without resurrecting a session, removes every owned local/global binding, restores trigger attributes/owned scroll state, destroys the inline surface and restores original root Node objects. Never dispose the borrowed engine. Generation/current checks must surround abort listeners, DOM disconnection, native close/focus and authored restoration callbacks. Failures during initial mount roll back only this attempted mount. A stale callback cannot delete a newly mounted instance's ownership entry.

## CSS, limits and verification

Reuse inline theme properties and add scoped `--raveldex-modal-*` public values for dialog layout/surface/backdrop/focus as needed; internal values use `--_`. Native hidden dialog styling must stay hidden. Use logical properties, safe-area space, bounded `dvh` with a `vh` fallback, a zero-minimum scroll body, contained overscroll, 44px close/control targets, visible focus, forced colors and reduced motion. No animation is required. At narrow/short emulated viewports, input/close stay reachable and long content scrolls inside the surface; no physical on-screen-keyboard or actual zoom claim follows from viewport emulation.

Native result, field/value/source/revision, DOM, work and section limits remain unchanged. Modal state consists of its captured options/current controls, one existing inline operation, owned listener/gesture/scroll records and root/trigger ancestor references; no retained alternate result/index representation. Ancestor inspection scales with authored DOM depth and document coordination with the number of registered instances; these are not calibrated memory/latency guarantees. ## Application starters — RX-6007

The complete [browser](../../examples/modal-browser/README.md) and [Astro](../../examples/modal-astro/README.md) projects keep first-open initialization outside the public UI. An authored native loading dialog opens immediately with an explicit cancel/close action and native Escape support. Only that attempt starts asset loading and a new owner. Concurrent opens share its pending work; close invalidates its generation before cancellation and rapid reopen may create a fresh attempt. A late candidate is disposed without mounting or reopening an abandoned view. Failed assets or mount validation retain a useful Retry route and normal browse navigation. No second search engine or success-returning loading facade is mounted.

Each local `createDocumentationSearch` wrapper returns `open`, `close` and an idempotent asynchronous `destroy`. Its `load` callback transfers a newly owned candidate; it does not accept an engine owned elsewhere. Once ready, the public modal borrows that candidate and retains the configured preserve/reset policy. Closing the ready modal cancels presentation while retaining its owner; destruction removes the UI before disposing that owner, and waits for pending late candidates. The entry scripts handle pagehide and back/forward-cache restoration. Application navigation must await destruction before removing/replacing a view. The loading wrappers install no global shortcut; the existing ready-owner modal's explicit shortcut option remains available to direct integrations.

Both projects calculate disjoint original UTF-16 section ranges from the same explicit authored strings used to render actual heading IDs. They index one native record per page and encode raw section anchors once. The browser build binds fetched content bytes to its compiled SHA-256 and creates the source/evidence/facet owner directly. Astro builds the existing source artifact and separate versioned companion, then explicitly loads source, display and sections through the same receiving handle with matching build/base identities. Neither integration extracts HTML, discovers routes, shards the index, changes a static format or changes core/provider state. Deploy each complete generation together; byte integrity is not publisher authentication or proof of separately deployed target-page content.

The [modal gallery](../../site/Modal.astro) uses an installed browser build and explicitly allowlisted complete source downloads. Styling uses the public modal/inline properties after the explicit package CSS, with starter CSS also covering loading/failure presentation. Private-tarball installation, source replacement, root/subdirectory builds, required add-ons, retry and borrowed-versus-owned cleanup are documented in the respective guides. Qualification claims require the separate RX-6007 evidence and later first-wave gate; this section does not establish human AT, physical-input, zoom or broad platform support.
