Compare solutions and requirements

Let visitors search a resource library, choose several filters, remove selected choices and reach every matching page. Copy a complete browser or Astro project, replace its explicit public records and adjust a few CSS properties.

Use this directory for persistent resource lists. Choose inline search for simple page results, the documentation modal for button-opened search or the compact header for a few quick page links.

Try the installed browser project

Search walking resource: seven pages match, three per page. Open Filter resources, choose Guides and Safety, then remove a selected chip or Clear all. Counts describe the current matching set, including each group's own selections. Choices within one group combine with OR; different groups and text combine with AND. A zero-count choice stays usable.

Change the appearance

  1. Copy, install, build and preview one complete project. In Astro, choose Enable directory first.
  2. Edit the existing .raveldex-directory rule in browser theme.css or Astro src/style.css, loaded after the package stylesheet:
.raveldex-directory {
  --raveldex-directory-accent: #145b45;
  --raveldex-directory-button-color: #fff;
  --raveldex-directory-radius: .75rem;
  --raveldex-directory-gap: 1.25rem;
}
  1. Stop preview, rebuild and restart it with the same deployment base. Reload to see the green accent, rounder corners and wider spacing. Update the matching dark-theme rule too.
  2. Search walking resource again: seven pages still match. Use Next page to reach every match, change filters, inspect Tab focus and follow a real resource link. Theme changes keep the same query, totals and native order.

Set background, color, muted, border, focus and button colors together when building another palette. See directory controls and styling for the component API.

Mobile filters and URL state

Filter resources is a native disclosure, closed initially at every width. Open/close it with the summary; Close filters or Escape inside it restores summary focus. Resizing keeps its current choice. Removing a focused chip moves to an adjacent chip or the search field; native checkboxes stay in place as counts change.

Both starters explicitly select URL synchronization and push for committed edits/pages. Back/Forward replays query, selections and page without new entries. Use replace for live edits in one entry, or turn URL state off in configuration for an in-memory directory. Unrelated parameters/hash survive. No local search-history store or telemetry is created. Empty searches browse all resources; no-results, initialization failure, native refusal and changed revisions have visible recovery.

Before adopting your own content and theme

Run the copied root/subdirectory build with changed data and CSS. Check every page, filter combinations, zero-result recovery, loading/Retry, Back/Forward, native links, long/RTL labels and dark/forced colors. Scripted keyboard/composition, selected axe and emulated layout results are distinct from human AT speech, physical IME/touch/on-screen keyboards, actual browser zoom, Safari/device support and hosted deployment. Follow starter adoption and local checks.
