Documentation search modal starters

Open search from a button, find a matching page and jump to the heading that contains the match. Copy a complete browser or Astro project, replace its explicit page content and adjust the CSS.

Use the modal for search behind a button. Choose inline search when the field and results should stay in the page.

For a compact field in an ordinary header, choose the dropdown header starter, with a real inline full-results destination.

Each project uses the native documentation modal and one indexed record per page. Optional source evidence and section maps provide anchored previews while native page totals, order and paging stay authoritative. These projects load a complete local index on first open; they do not crawl HTML or load index shards.

Try the browser starter

Select Search documentation, search bobbin and follow the threading preview to its actual heading. Try workshop to page through all six guides. Close during loading to cancel the attempt. Ordinary browse links work before loading and without JavaScript.

Choose a complete starter

Core and Astro packages are currently private and unpublished. Use the matching local package tarballs described in each guide. The browser starter uses pinned esbuild tooling; the Astro starter builds versioned source, display and section artifacts from an explicit allowlist.

Both projects need native dialog, Intl.Segmenter and Web Crypto over HTTPS or localhost. Supply public page records and exact original section text/ranges, with raw anchors that match real heading IDs. The same explicit content renders those targets in each starter. Sections require the selected source/section providers; the Topic filter requires its facet registration. Deploy each rebuilt set of pages and search assets together.

Change the appearance

  1. Copy and install one complete starter using its setup guide. Open search and try workshop before changing the CSS.
  2. Edit the existing rules in the browser's theme.css or Astro's src/style.css, loaded after the package's explicit modal.css. Set modal layout properties on the dialog and shared input/result properties on the inner inline surface:
.raveldex-modal {
  --raveldex-modal-max-width: 40rem;
  --raveldex-modal-radius: .75rem;
}
.raveldex-inline {
  --raveldex-inline-accent: #145b45;
  --raveldex-inline-gap: 1rem;
}
  1. Stop the preview, run npm run build in the copied project and restart its documented preview command with the same deployment base. Reload, open search and inspect the narrower surface, rounded corners and green accent.
  2. Search workshop: six pages still match and Load more shows all six. Search bobbin and follow its section link. Use Tab to inspect visible focus, close with Close search and reopen to check the preserved query.

The starter theme files also style the authored loading dialog. Keep loading, failure and ready states visually consistent. Check contrast and visible focus after changing colors. See modal options and CSS properties.

Some browsers clear a focused search field on the first Escape. Press Escape again or use Close search to dismiss the window.

The wrappers own newly created search engines and destroy the borrowed UI before disposing them. To use an engine owned elsewhere, mount the modal directly and keep disposal with that existing owner. Query preservation, reset policy, retry and close/destroy behavior are described in both guides.

Before using your own theme

Local automated Chrome checks cover installed examples, native dialog keyboard/focus behavior, scripted composition, first-open cancellation/retry, owner cleanup and emulated narrow/theme layouts. Human screen-reader speech, physical IME/touch/on-screen keyboards, actual browser zoom and other browser/device combinations need separate checks in your application. See starter adoption and local checks.
