How this example works

Present the same native directory results as a list, cards or a responsive grid. Add explicit excerpts, category/breadcrumb/date text, named fields and optional images. Copy the complete browser project, replace its public data and adjust a few CSS properties.

Choose the plain browser or Astro directory when titles and filters are enough. This rich browser project adds a separate display projection; no static artifact extension or framework is required.

Search walking resource: seven pages match. Choose Grid and Compact, then move through all three native result pages. Query, selected filters, exact total, current page and deterministic order stay the same. Check Show images to request illustrations for the current page. Images start off; the final resource deliberately demonstrates a missing image.

Setup and replacement-data guideDownload the complete starter
  1. In an empty directory, extract tar -xzf cards-browser.tar.gz --strip-components=1. Read the setup guide for deployment paths and preview commands.
  2. Install from that directory with npm install @vmitsaras/raveldex@1.0.0, then run npm run build and npm run preview to try the sample content.
  3. Replace the public records in content.json, keeping IDs and destination paths stable. The guide explains the fields and any matching heading anchors. Rebuild after editing.
  4. Change theme.css using the theme recipe below. Rebuild, restart the preview and check search, links and keyboard focus with your own content.

Change the appearance

  1. Copy, install, build and preview the complete project. Its List/Comfortable layout starts with images off.
  2. Edit the existing component rules in theme.css, loaded after directory.css and directory-cards.css:
.raveldex-directory {
  --raveldex-directory-accent: #145b45;
  --raveldex-directory-button-color: #fff;
  --raveldex-directory-radius: .75rem;
  --raveldex-directory-card-min-width: 17rem;
  --raveldex-directory-card-gap: 1.25rem;
  --raveldex-directory-card-radius: 1rem;
}
  1. Stop preview, rebuild and restart with the same deployment base. Reload to see the green accent, rounder cards and wider spacing. Change the matching dark-theme rule too.
  2. Search again, choose Grid/Compact, inspect Tab focus and visit a real result. Presentation controls change no query/filter/page state or native order.

Map only the display data you need

The loader explicitly maps title/link plus optional excerpt, category, breadcrumb segments, authored localized date, named text fields and image information. The native index still uses title/body and the configured format/topics. Missing display metadata leaves readable title links. Strings stay literal text; no HTML template callback is accepted.

Each image declares a safe URL, explicit alternative and dimensions. Informative images describe their content; a repeated decorative illustration deliberately uses an empty alternative. The two local examples reserve 640×360 space. Images use native lazy loading and no-referrer policy. Failed images keep the text/link usable and do not retry automatically. Disabling images removes presentation; it does not promise cancellation of an already started browser request.

Before adopting your own data and theme

Build at root and a subdirectory with edited title/body/metadata/CSS. Check all native pages, filters/chips, Back/Forward, List/Cards/Grid and both density choices, images off/on/broken, keyboard reading order, no-JavaScript browsing, long/RTL text, narrow/dark/forced-colors and reduced motion. This is a semantic list styled with CSS, without interactive ARIA grid behavior, commerce actions or displayed-page sorting.

Scripted browser, selected axe and emulated layout checks remain distinct from human AT speech, physical input, real browser zoom, Safari/device support and deployment. Follow the starter adoption checks in your target application.
