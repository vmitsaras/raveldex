Runnable API examples

Copy these modules into an ESM application where you installed Raveldex. They use public imports and show small, complete integrations. Most functions create and dispose their own example engine and return results you can inspect. The UI recipe instead returns a handle you dispose when removing the component. Errors are passed back to your application.

Module Invocation / environment
inline.mjs await createInlineSearch(root) on an HTTP(S) page; core-only consumer search with explicit prefix mode. Import /addons/ui/inline.css separately; call returned dispose() when removing it.
consumer-messages.de.mjs Data-only complete German bundles: copy locally and use german.inline, inlineWithFilters, modal, dropdown, directory and imageUnavailable as described in the localization guide. Imports do not mount or select a locale.
cms-refresh.mjs await runCMSRefreshExample(root, externalButton) on an HTTP(S) page with a dedicated document-tree host. Finite owned directory update/remount/focus walkthrough; restores authored Nodes and disposes its engine before returning. Import card CSS separately; read the preconditions and state limits.
core.mjs await runCoreExample() in Node; one record and exact result.
addons.mjs await runAddonsExample() in Node with usable Intl.Segmenter; phrases, filters/facets, Inspector, diagnostics, ranges/snippets and source/position/mixed parity.
snapshots.mjs await runSnapshotsExample(applicationQualification) in the application’s exactly declared Node environment. The application must supply its own NativeSnapshotQualification evidence; version detection alone is insufficient.
migration.mjs await runMigrationExample(bytes) with the companion’s canonical public source-export Uint8Array; conversion/rebuild only.
ui.mjs Developer Workbench: await createSearchUI(root) on an HTTP(S) page, with its existing exact-word default and optional Inspector. Import /addons/ui/styles.css separately; call returned dispose() when removing it.
browser.mjs await runBrowserExample(document.querySelector('#example-root')) on an HTTP(S) page with a dedicated empty fixture storage namespace and usable IndexedDB/Intl.Segmenter. Mounts, searches and destroys UI; explicitly saves, loads and erases its example namespace.
worker.mjs, worker-host.mjs Bundle/serve the host as a module-worker URL, then await runWorkerExample(workerURL) in the browser; mutation and source-restore receipt reconciliation.

For a first run, copy core.mjs beside your application’s package.json, then run this command from that directory:

node --input-type=module -e "import('./core.mjs').then(async ({ runCoreExample }) => console.log(await runCoreExample()))"

It prints an object with revision 1, total 1 and one hit with ID guide:updates. The engine has already been disposed when the function returns.

Browser recipes

For a visitor-facing interface, use inline.mjs and the consumer setup, or choose a complete modal/dropdown/directory/cards project from the solution chooser. A connected root must exist before calling the recipe; keep ordinary browse links outside it. This small recipe assumes the page retains the root until initialization returns; use the complete starter controller for cancellable loading, removal during initialization and retry.

The browser example expects a real root such as <main id="example-root"></main>. It uses adapter-owned database raveldex-candidate-example and namespace equal to the root ID; the initial save explicitly expects that namespace to be empty. Successful completion erases its rows, then disposes its borrowed resources. A failed run may leave a saved fixture generation: inspect/recover that generation or select a fresh explicit fixture namespace before rerunning. No general application data is erased automatically. Load the CSS separately; the JavaScript module does not inject styling.

When an example refuses work

Use the recovery choices when connecting these recipes to your own status and actions. Keep a browse route available. A missing provider needs a setup change; it is not repaired by retrying the same request. Prefix, phrase, suggestion and structured-filter requests retain their declared analyzer/provider/size limits. Do not reinterpret an invalid request as ordinary text or a successful empty result.

The storage example disposes its example resources even on failure. It does not leave a working search mounted if a save/load failed. QUOTA_EXCEEDED or UNAVAILABLE can be explained as “The search cache could not be saved in this browser”; offer existing browse links or a separately initialized in-memory interface. Do not imply that such an interface was created by the failed recipe. Inspect a surviving saved generation before rerunning the fixture; never delete a namespace automatically to make the example succeed.

The worker example shows successful receipt reconciliation. If a mutation or restore instead reports OUTCOME_UNKNOWN, retain operationId and consult the surviving owner’s appropriate receipt API before destroying that owner or repeating work. pending and expired cannot settle the outcome. If the owner is already gone, rebuild from authoritative records. The recipe’s finally releases its example-owned worker; it does not retain a worker for later reconciliation.
