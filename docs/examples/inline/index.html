# Inline search for a browser site

Copy this complete starter to add a search form, original-text snippets, a type filter and complete result paging. It uses native Raveldex in the browser's main thread and a small explicit guide allowlist. There is no worker, crawler, server API or diagnostic selector. The rendered pages remain usable without JavaScript.

## Install and run

Use Node 22 or later and npm. Extract the complete starter into an empty directory with `tar -xzf inline-browser.tar.gz --strip-components=1`, then enter that directory. From a source checkout, you can instead copy the complete `examples/inline-browser/` folder to a new project.

Install Raveldex and the starter's pinned build tooling, then build and preview:

```sh
npm install @vmitsaras/raveldex@1.0.0
npm run build
npm run preview -- --port 4176
```

Keep the generated `package-lock.json` and use `npm ci` for subsequent installs. To test a local Raveldex build, substitute its core tarball path for the package name in the install command.

Open `http://127.0.0.1:4176/`. Search `walking guide`: there are seven matches, with three initially visible. Load more shows six; selecting it again appends the seventh while keeping the earlier results displayed. Choose Guide to narrow to five pages. A search such as `weather` shows original text with highlighted matches; following its title opens the actual guide page. Ctrl+C stops this preview.

## Deploy under a subdirectory

Use the same base for the build and preview:

```sh
RAVELDEX_INLINE_BASE=/help/ npm run build
RAVELDEX_INLINE_BASE=/help/ npm run preview -- --port 4176
```

Open `http://127.0.0.1:4176/help/`. The base must begin and end with `/`. Deploy the contents of `dist/` under that path. The build places all script, stylesheet, data and browse/result links under that base. The loader resolves `content.json` relative to the bundled module rather than assuming the site root. Do not change the base without rebuilding.

## Replace the sample content

Edit `content.json`, then rebuild. Each entry has a unique `id`, a plain-text `title` and `body`, a string `category` and a unique local `/guides/slug/` path. Titles must contain non-whitespace text, be well-formed UTF-16 and fit within 1,024 UTF-16 units; invalid titles are refused before replacing generated pages or creating a loaded search owner. This starter allows up to 1,000 explicit entries and adds them in batches of 100. Those are starter bounds, not a capacity or speed guarantee. `build.mjs` creates the corresponding browse list and static guide pages, escaping text rather than treating it as HTML. Do not put secrets in this public file or in indexed text.

`load.mjs` maps the same entries to `{ id, text: { title, body }, metadata: { category } }` search records and `{ id, title, url }` display records. If you index existing pages instead, supply their real canonical URLs and preserve the relationship between IDs, original source text and display records. This starter does not extract HTML or invent section anchors. Keep the authored browse links available while data loads and when it fails.

The engine explicitly registers `createSourceProvider({ fields: ['body'] })`, `createSnippetEvidence({ fields: { body: 'source' } })` and `createFacets({ fields: ['category'] })`. Title and body are indexed; only body source is retained for snippets. Equality filtering is native core behavior, so the structured-filter add-on is unnecessary. To use only title/link search, remove the snippet/facet options in `controller.mjs` and their corresponding optional registrations/schema metadata in `load.mjs`.

## Change a few CSS values

`main.mjs` imports the optional `inline.css` first and `theme.css` second. Change the scoped public properties in `theme.css`, then rebuild:

```css
.raveldex-inline {
  --raveldex-inline-accent: #294e82;
  --raveldex-inline-gap: 1.25rem;
  --raveldex-inline-radius: .65rem;
}
```

These affect links/controls, spacing and corner shape without editing generated markup. Check text/focus contrast after changing colors. `controller.mjs` sets the batch size and plain-text labels. Its legacy `maxRenderedResults` option is accepted but no longer limits appends; omit that option in new integrations. The default final-word prefix mode lets `walk` find `walking`; earlier words remain exact.

## Loading, retry and disposal

`main.mjs` explicitly starts a controller. The controller deduplicates concurrent starts, announces loading, leaves browse links available and exposes Retry loading search after a data or initialization failure. Test recovery locally by blocking `content.json`, then unblocking it and selecting Retry loading search. Data fetches use an AbortSignal; an owner created after destruction is disposed before it can mount.

`createInlineSearch` accepts a `load(signal)` callback that transfers a **newly owned** `{ engine, documents, dispose }` object. It destroys the borrowed UI before disposing that owner, including on initialization failure and late completion. Do not return an engine owned elsewhere in your application. To integrate with an existing borrowed engine, mount `mountRaveldexInline` directly, call its `destroy()` when the view ends, and leave engine disposal to its existing owner.

Call and await `controller.destroy()` before removing the integration in your own navigation system. It is idempotent, removes its Retry listener, aborts loading and waits for any late owner to be released. This page calls destruction on `pagehide` and creates a fresh controller on a back/forward-cache `pageshow`. No global debug API is exposed. The inline preset separately handles stale searches and revision-safe retry after initialization.

The headless checks exercise installed bytes, navigation, failure/delay/retry and teardown. They do not establish human screen-reader, physical input, actual zoom, broad browser support or large-data performance qualification.

import { build } from 'esbuild';
import { readFile, writeFile, mkdir, rm, copyFile } from 'node:fs/promises';
import { fileURLToPath } from 'node:url';
import { dirname, join } from 'node:path';

const root = fileURLToPath(new URL('./', import.meta.url));
const output = join(root, 'dist');
const base = process.env.RAVELDEX_INLINE_BASE ?? '/';
if (!/^\/(?:[A-Za-z0-9_-]+\/)*$/.test(base)) throw new Error('Base must be / or a slash-terminated local path such as /help/');
const entries = JSON.parse(await readFile(join(root, 'content.json'), 'utf8'));
if (!Array.isArray(entries) || entries.length > 1000) throw new Error('Expected up to 1000 guide records');
const escape = text => String(text).replaceAll('&', '&amp;').replaceAll('<', '&lt;').replaceAll('>', '&gt;').replaceAll('"', '&quot;').replaceAll("'", '&#39;');
const seen = new Set(), paths = new Set();
for (const entry of entries) {
  if (!entry || !['id', 'title', 'body', 'category', 'path'].every(key => typeof entry[key] === 'string')
    || !entry.title.trim() || entry.title.length > 1024 || !entry.title.isWellFormed()
    || !entry.id || seen.has(entry.id) || paths.has(entry.path) || !/^\/guides\/[a-z0-9-]+\/$/.test(entry.path)) throw new Error('Invalid or duplicate guide');
  seen.add(entry.id); paths.add(entry.path);
}
await rm(output, { recursive: true, force: true }); // Only this starter's generated output.
await mkdir(output, { recursive: true });
const bundle = await build({ absWorkingDir: root, entryPoints: ['main.mjs'], outfile: join(output, 'assets/main.js'),
  bundle: true, platform: 'browser', format: 'esm', target: 'es2022', minify: true,
  treeShaking: true, legalComments: 'none', metafile: true, logLevel: 'silent' });
await writeFile(join(root, 'build-meta.json'), JSON.stringify(bundle.metafile, null, 2) + '\n');
const links = entries.map(entry => `<li><a href="${escape(base + entry.path.slice(1))}">${escape(entry.title)}</a></li>`).join('\n');
const index = await readFile(join(root, 'index.html'), 'utf8');
await writeFile(join(output, 'index.html'), index.replaceAll('{{BASE}}', base).replace('{{BROWSE_LINKS}}', links));
await copyFile(join(root, 'content.json'), join(output, 'content.json'));
for (const entry of entries) {
  const file = join(output, entry.path.slice(1), 'index.html');
  await mkdir(dirname(file), { recursive: true });
  await writeFile(file, `<!doctype html><html lang="en"><head><meta charset="utf-8"><meta name="viewport" content="width=device-width,initial-scale=1"><title>${escape(entry.title)}</title><link rel="stylesheet" href="${escape(base)}assets/main.css"></head><body><main><p><a href="${escape(base)}">Search and browse all guides</a></p><p class="eyebrow">${escape(entry.category)}</p><h1>${escape(entry.title)}</h1><p>${escape(entry.body)}</p></main></body></html>`);
}
console.log(`Built ${entries.length} explicit guides at ${base}. Serve dist under that same base.`);

import { createServer } from 'node:http';
import { readFile, stat } from 'node:fs/promises';
import { dirname, extname, resolve, join } from 'node:path';
import { fileURLToPath } from 'node:url';

const root = resolve(dirname(fileURLToPath(import.meta.url)), 'dist');
const base = process.env.RAVELDEX_INLINE_BASE ?? '/';
if (!/^\/(?:[A-Za-z0-9_-]+\/)*$/.test(base)) throw new Error('Invalid deployment base');
const args = process.argv.slice(2), port = Number(args.length === 2 && args[0] === '--port' ? args[1] : args.length === 0 ? 4176 : NaN);
if (!Number.isInteger(port) || port < 1 || port > 65535) throw new Error('Use --port 4176');
const mime = { '.html': 'text/html; charset=utf-8', '.json': 'application/json; charset=utf-8', '.js': 'text/javascript; charset=utf-8', '.css': 'text/css; charset=utf-8' };
const server = createServer(async (request, response) => {
  try {
    const pathname = new URL(request.url, 'http://localhost').pathname;
    if (!pathname.startsWith(base)) { response.writeHead(404).end(); return; }
    let file = resolve(root, decodeURIComponent(pathname.slice(base.length)));
    if (file !== root && !file.startsWith(root + '/')) { response.writeHead(403).end(); return; }
    if ((await stat(file)).isDirectory()) file = join(file, 'index.html');
    const bytes = await readFile(file);
    response.writeHead(200, { 'content-type': mime[extname(file)] ?? 'application/octet-stream', 'cache-control': 'no-store' }).end(bytes);
  } catch { response.writeHead(404).end(); }
});
server.listen(port, '127.0.0.1', () => console.log(`Open http://127.0.0.1:${port}${base} — Ctrl+C stops this preview.`));

import '@vmitsaras/raveldex/addons/ui/inline.css';
import './theme.css';
import { createInlineSearch } from './controller.mjs';
import { loadGuides } from './load.mjs';

const root = document.querySelector('[data-search-root]');
const status = document.querySelector('[data-search-status]');
const retry = document.querySelector('[data-search-retry]');
let search;
function openSearch() {
  search = createInlineSearch({ root, status, retry,
    load: signal => loadGuides(new URL('../content.json', import.meta.url), signal) });
  void search.start();
}
openSearch();
window.addEventListener('pagehide', () => { void search.destroy(); });
// A back/forward-cache restore needs a fresh owned engine after pagehide cleanup.
window.addEventListener('pageshow', event => { if (event.persisted) openSearch(); });
controller.mjs

import { mountRaveldexInline } from '@vmitsaras/raveldex/addons/ui/inline';

// Application lifecycle, separate from the UI's borrowed-engine contract.
// `load` transfers one newly created owner to this controller. Never return an
// application-owned/borrowed engine: this controller will dispose its owner.
export function createInlineSearch({ root, status, retry, load }) {
  let owner, ui, pending, abort, ended = false;
  function say(text) { status.textContent = text; }
  function start() {
    if (ended || owner) return Promise.resolve();
    if (pending) return pending;
    abort = new AbortController();
    // Publish the work before authored DOM callbacks can start or destroy it.
    pending = Promise.resolve().then(async () => {
      let candidate, mounted, failed = false;
      try {
        if (ended) return;
        retry.hidden = true;
        say('Loading search. You can browse the guides while it loads.');
        if (ended) return;
        candidate = await load(abort.signal);
        if (ended) return;
        mounted = mountRaveldexInline({ root, engine: candidate.engine, documents: candidate.documents,
          pageSize: 3,
          facets: [{ field: 'category', label: 'Type of guide' }], snippetFields: ['body'],
          messages: { label: 'Search walking guides', placeholder: 'Try weather or map',
            idle: 'Enter a word, then choose a type of guide to narrow the matches.',
            facetSummary: 'Guide types: {total} · Not shown: {omitted}' } });
        // Replacing authored custom elements can synchronously destroy the view.
        if (ended) return;
        owner = candidate; candidate = undefined;
        ui = mounted; mounted = undefined;
        say('Search is ready.');
      } catch { failed = true;
      } finally {
        mounted?.destroy();
        if (candidate) await candidate.dispose();
        pending = undefined;
        if (failed && !ended) {
          say('Search could not load. Browse the guides below or try loading again.');
          if (!ended) retry.hidden = false;
        }
      }
    });
    return pending;
  }
  function onRetry() { void start(); }
  retry.addEventListener('click', onRetry);
  let disposal;
  function destroy() {
    if (ended) return disposal;
    ended = true;
    // Publish the one disposal promise before abort/DOM callbacks can reenter.
    let resolveDisposal, rejectDisposal;
    disposal = new Promise((resolve, reject) => { resolveDisposal = resolve; rejectDisposal = reject; });
    const previous = owner, previousUI = ui, work = pending;
    owner = undefined; ui = undefined;
    abort?.abort(); retry.removeEventListener('click', onRetry);
    previousUI?.destroy(); retry.hidden = true;
    say('Search is closed. Browse the guides below.');
    // Late owners are disposed in start() before pending settles.
    Promise.all([work, Promise.resolve().then(() => previous?.dispose())]).then(() => resolveDisposal(), rejectDisposal);
    return disposal;
  }
  return Object.freeze({ start, destroy });
}
load.mjs

import { createRaveldex } from '@vmitsaras/raveldex';
import { createSourceProvider } from '@vmitsaras/raveldex/addons/phrases/source';
import { createSnippetEvidence } from '@vmitsaras/raveldex/addons/snippets';
import { createFacets } from '@vmitsaras/raveldex/addons/facets';

export async function loadGuides(contentUrl, signal) {
  const response = await fetch(contentUrl, { signal, cache: 'no-cache' });
  if (!response.ok) throw new Error('Guide data is unavailable');
  const entries = await response.json();
  if (!Array.isArray(entries) || entries.length > 1000) throw new Error('Expected up to 1000 explicit guide records');
  const seen = new Set();
  for (const entry of entries) {
    if (!entry || !['id', 'title', 'body', 'category', 'path'].every(key => typeof entry[key] === 'string')
      || !entry.title.trim() || entry.title.length > 1024 || !entry.title.isWellFormed()
      || !entry.id || seen.has(entry.id) || !/^\/guides\/[a-z0-9-]+\/$/.test(entry.path)) throw new Error('Invalid guide record');
    seen.add(entry.id);
  }
  signal.throwIfAborted();
  const engine = createRaveldex({
    schema: { text: { title: { boost: 2 }, body: {} }, metadata: { category: { type: 'string' } } },
    addons: [createSourceProvider({ fields: ['body'] }),
      createSnippetEvidence({ fields: { body: 'source' }, maxSnippets: 1, maxCodeUnits: 180 }),
      createFacets({ fields: ['category'] })],
  });
  try {
    // addMany is finite. Split larger allowlists into documented bounded batches.
    for (let offset = 0; offset < entries.length; offset += 100) {
      await engine.addMany(entries.slice(offset, offset + 100).map(entry => ({ id: entry.id,
        text: { title: entry.title, body: entry.body }, metadata: { category: entry.category } })), { signal });
    }
    signal.throwIfAborted();
    // content.json lives at the deployment base, beside the search page.
    const base = new URL('./', contentUrl);
    const documents = entries.map(entry => ({ id: entry.id, title: entry.title, url: new URL(entry.path.slice(1), base).href }));
    return { engine, documents, dispose: () => engine.dispose() };
  } catch (error) { await engine.dispose(); throw error; }
}

# Inline search starter for Astro

This complete starter builds six workshop guide pages and an optional inline search. It uses the installed Astro adapter's explicit allowlist and source-artifact loader. Search starts when a visitor selects **Enable search**; the ordinary page links work before loading and without JavaScript.

## Copy and install

Use Node 24 and npm. Extract the complete starter into an empty directory with `tar -xzf inline-astro.tar.gz --strip-components=1`, then enter it. From a source checkout, copy the entire `examples/inline-astro/` folder into a new project instead.

```sh
export RAVELDEX_INLINE_ASTRO="$(pwd -P)"
npm --prefix "$RAVELDEX_INLINE_ASTRO" install @vmitsaras/raveldex@1.0.0 @vmitsaras/raveldex-astro@1.0.0
```

The starter pins Astro `7.3.2`. Keep the generated `package-lock.json` and use `npm ci` afterward. To test local changes, substitute matching core and Astro tarball paths in the install command. Keep `RAVELDEX_INLINE_ASTRO` set for the build and preview commands below.

## Build and preview

```sh
ASTRO_TELEMETRY_DISABLED=1 npm --prefix "$RAVELDEX_INLINE_ASTRO" run build
ASTRO_TELEMETRY_DISABLED=1 npm --prefix "$RAVELDEX_INLINE_ASTRO" run preview -- --host 127.0.0.1 --port 4321
```

Open the HTTP URL Astro prints. The preview runs in the foreground; use Ctrl+C to stop this preview before rebuilding. Keep another existing server running if the port is occupied and choose another port. Do not open the generated HTML with a `file:` URL: the loader fetches same-origin assets.

Choose **Enable search**, type `workshop` and select **Search**. Three results appear first; **Load more** shows the remaining matches. While those results are displayed, choose **Tools** in the Topic filter to narrow them to two tool pages. The filter choices come from the current search results. Select a result title to open its actual static page. **Clear search and filters** resets both the words and topic. No Workbench controls or developer diagnostics are included.

The build writes `dist/raveldex/manifest.json` plus integrity-checked source and display files. The client loads all source data once on demand, then its display mapping. This is a complete local index, not a lazy or sharded index. It uses direct browser execution; no worker file is required.

## Use a subdirectory

Stop the preview, then rebuild and preview with the same changed base:

```sh
RAVELDEX_ASTRO_BASE=/help/ ASTRO_TELEMETRY_DISABLED=1 npm --prefix "$RAVELDEX_INLINE_ASTRO" run build
RAVELDEX_ASTRO_BASE=/help/ ASTRO_TELEMETRY_DISABLED=1 npm --prefix "$RAVELDEX_INLINE_ASTRO" run preview -- --host 127.0.0.1 --port 4321
```

Open `http://127.0.0.1:4321/help/` (or the actual port reported). Astro resolves scripts and CSS using its base; the loader's manifest URL and generated result URLs use that same base. Deploy the complete new `dist/` together. An old HTML page paired with a different build's manifest is rejected rather than displaying mixed data.

## Replace the content

Edit `content.json`: each entry has a unique route-safe `slug`, a display/search `title`, one string `category` and original plain-text `body`. The same entry renders the page, creates its indexed record and supplies its display title and URL. Change `buildId` whenever deploying changed content or configuration, then rebuild. This example intentionally indexes only those entries; it never extracts HTML or automatically crawls routes. Do not put private material in the allowlist or generated artifacts.

`configuration.mjs` explicitly declares title/body search fields and category metadata. The title has boost 2. It registers original title and body storage with `createSourceProvider`, source-based `createSnippetEvidence` and `createFacets` for category counts. Static source snapshots require original values for every declared text field, including title. `src/search.mjs` requests only `body` snippets and that native string facet. Retain the same configuration for both build and restore. To adopt only title/link search, remove the snippet/facet UI options and their registrations together, while retaining the complete source provider required by static reconstruction.

## Change the appearance

The package stylesheet is imported separately in `src/main.mjs`. Change the scoped public properties in `src/style.css`; no runtime or DOM changes are required. For example:

```css
.raveldex-inline {
  --raveldex-inline-accent: #563c83;
  --raveldex-inline-focus: #874a00;
  --raveldex-inline-radius: .75rem;
}
```

Rebuild, enable search and inspect the new link/control color and corner radius. Keep text, focus and highlight contrast usable when changing colors. The [inline API guide](https://github.com/vmitsaras/raveldex/blob/main/docs/api/HOSTS.md#inline-result-pages-filters-and-snippets) lists the other supported messages and style properties. The starter uses prefix matching, three hits per batch and at most six rendered hits; configure these in `src/search.mjs` for your own dataset.

## Loading, retry and cleanup

The wrapper displays a loading message while the manifest, source snapshot and display mapping load. Guide links remain usable. Asset failure leaves those links and a **Retry search** button; retry creates a new candidate and never reuses partial state. Concurrent `start()` calls share the same pending initialization.

`createInlineSearch()` in `src/search.mjs` returns `start()` and `destroy()`. The wrapper owns only the loader handle it creates: the inline UI borrows its engine, and teardown destroys the UI before disposing that owned handle. It accepts no borrowed application engine. `destroy()` removes its click listener, aborts initialization, restores the authored search fallback and returns a promise that settles after any late candidate is disposed. Call and await it before removing or replacing the search host in a client-side route integration; this starter uses ordinary static navigation.

`src/main.mjs` disposes on `pagehide` and recreates the wrapper when a document is restored from the browser's back/forward cache. The page contains browse links and useful text without JavaScript; a script-loading failure leaves that fallback intact. No package publication, deployment, telemetry or browser storage is part of this starter.

src/search.mjs

import { loadStaticSearch } from '@vmitsaras/raveldex-astro/client';
import { mountRaveldexInline } from '@vmitsaras/raveldex/addons/ui/inline';
import { configuration } from '../configuration.mjs';

/** This application wrapper owns only the handle returned by its loader.
 * Calling destroy waits for late initialization and disposes that owned handle.
 * It never accepts or disposes an application's borrowed engine. */
export function createInlineSearch({ root, status, button, manifestUrl, buildId, load = loadStaticSearch }) {
  const lifetime = new AbortController();
  let owned, ui, pending, destroyed = false, disposal;
  const say = text => { status.textContent = text; };
  function start() {
    if (destroyed || ui) return Promise.resolve();
    if (pending) return pending;
    let failed = false;
    // Publish the work before authored DOM callbacks can start or destroy it.
    pending = Promise.resolve().then(async () => {
      let candidate, mounted;
      try {
        if (destroyed) return;
        button.disabled = true;
        say('Loading search. You can keep using the guide links below.');
        if (destroyed) return;
        candidate = await load({ manifestUrl, expectedBuildId: buildId,
          configuration: configuration(), signal: lifetime.signal });
        if (destroyed) return;
        const documents = await candidate.loadDocuments({ signal: lifetime.signal });
        if (destroyed) return;
        mounted = mountRaveldexInline({ root, engine: candidate.engine, documents,
          pageSize: 3, snippetFields: ['body'],
          facets: [{ field: 'category', label: 'Topic' }],
          messages: { label: 'Search the workshop guide', placeholder: 'Try booking or tools', clear: 'Clear search and filters',
            idle: 'Search the workshop guide, then choose a topic to narrow the results.',
            facetSummary: 'Topics: {total} · Not shown: {omitted}' } });
        if (destroyed) return;
        ui = mounted; mounted = undefined;
        owned = candidate; candidate = undefined;
        button.hidden = true;
        say('Search is ready. Enter a word, then narrow results by topic.');
      } catch {
        failed = true;
      } finally {
        mounted?.destroy();
        await candidate?.dispose();
      }
    }).finally(() => {
      pending = undefined;
      if (failed && !destroyed) {
        button.disabled = false;
        button.textContent = 'Retry search';
        if (!destroyed) say('Search could not load. Retry, or use the guide links below.');
      }
    });
    return pending;
  }
  function destroy() {
    if (disposal) return disposal;
    let finish, fail;
    disposal = new Promise((resolve, reject) => { finish = resolve; fail = reject; });
    destroyed = true;
    const mounted = ui, previous = owned, inFlight = pending;
    ui = undefined; owned = undefined;
    lifetime.abort();
    button.removeEventListener('click', start);
    mounted?.destroy();
    // Await a loader even when its host ignores abort; its late handle is owned
    // locally and the pending initializer's finally block releases it.
    Promise.all([inFlight, previous?.dispose()]).then(() => finish(), fail);
    button.hidden = true;
    say('Search is closed. Use the guide links below.');
    return disposal;
  }
  button.addEventListener('click', start);
  button.hidden = false; button.disabled = false; button.textContent = 'Enable search';
  say('Search is optional. Enable it, or browse the guide below.');
  return Object.freeze({ start, destroy });
}

How this example works

Add a search field, highlighted excerpts, topic filters and more results to an ordinary page. Start with a complete browser or Astro project, replace its explicit guide records and adjust a few CSS properties.

Use inline search when results belong in the page. For search that opens from a button, choose the documentation modal.

For a header field with a few page links and a complete results route, choose the compact header starter.

These starters use the optional inline interface with direct execution, source snippets and string facets. They keep one result per supplied page and exact matching totals. They do not crawl HTML.

For a resource library with checkbox groups, selected chips, complete native pages and optional URL replay, use the faceted directory.

Try walking guide, choose a type of guide to narrow the matches, and follow a result to its complete page. The guide links also work without JavaScript. This preview runs the installed browser starter shown below.

Snippets need Intl.Segmenter. Astro also needs Web Crypto over HTTPS or localhost.

Data and browser requirements

Use Node 24 and npm for the documented setup. The browser project uses esbuild 0.28.2; the Astro project uses Astro 7.3.2 and the existing static search loader. Serve the built output over HTTP or HTTPS. Each guide covers package installation, changed deployment bases, loading failures, retry and cleanup.

Supply an explicit list of public pages with stable IDs, titles, URLs and original text; the starter guides show the exact records to replace. Both examples select source snippets and a string topic facet. Their snippets require Intl.Segmenter; the Astro artifact loader also requires Web Crypto over HTTPS or localhost. Title/link-only integrations can omit snippets and facets by removing their matching UI options and registrations together.

Change the appearance

  1. Copy and install one complete starter using its setup guide. Run it once and search the sample content before changing the CSS.
  2. Edit the existing .raveldex-inline rule in the browser's theme.css or Astro's src/style.css. Those files load after the package stylesheet. Use these values for the accent, corners and result spacing:
.raveldex-inline {
  --raveldex-inline-accent: #145b45;
  --raveldex-inline-radius: .75rem;
  --raveldex-inline-gap: 1.25rem;
}
  1. Stop the preview, run npm run build in the copied project and restart its documented preview command with the same deployment base. Reload the page; the accent is green, corners are rounder and result spacing is wider.
  2. Search walking guide in the browser starter or workshop in Astro. Totals remain seven and six pages respectively. Use Tab to inspect visible focus, then Load more and follow a result. The CSS changes appearance without changing search data or behavior.

For a dark surface, set background, color, muted, border, focus and highlight colors together. Keep visible focus and sufficient contrast when replacing those colors. See inline options and theme properties for the supported controls.

Before using your own theme

Local automated Chrome checks cover installed examples, keyboard events, scripted composition, loading/retry, teardown, CSS overrides and emulated narrow/theme layouts. Human screen-reader speech, physical IME/touch/on-screen keyboards, actual browser zoom and other browser/device combinations need separate checks in your application.
