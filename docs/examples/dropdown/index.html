Plain browser header

Setup and replacement-data guide · Download the complete starter

  1. In an empty directory, extract tar -xzf dropdown-browser.tar.gz --strip-components=1. Read the setup guide for deployment paths and preview commands.
  2. Install from that directory with npm install @vmitsaras/raveldex@1.0.0, then run npm run build and npm run preview to try the sample content.
  3. Replace the public records in content.json, keeping IDs and destination paths stable. The guide explains the fields and any matching heading anchors. Rebuild after editing.
  4. Change theme.css using the theme recipe below. Rebuild, restart the preview and check search, links and keyboard focus with your own content.

Change the appearance

  1. Copy, install, build and preview the complete project using its guide. Search the sample records before changing them.
  2. Edit the existing .raveldex-dropdown rule in theme.css, loaded after the package styles. Change the accent, corners and spacing:
.raveldex-dropdown {
  --raveldex-dropdown-accent: #145b45;
  --raveldex-dropdown-radius: .75rem;
  --raveldex-dropdown-gap: .75rem;
}
  1. Stop the preview, run npm run build in the copied project and restart its documented preview command with the same deployment base. Reload to see the green accent, rounder corners and wider spacing.
  2. Search walking guide again. Seven pages still match; the compact window still shows up to three. Follow See all results, check the unchanged query, load the other pages and follow a real guide link. Use Tab to inspect visible focus.

Set the background, text, muted, border, focus and active-result colors together for dark themes. The full-results page uses --raveldex-inline-* properties. See dropdown options and styling.

Narrow headers and an optional larger search

The native top-layer popup can escape an overflow-clipped header. Controls wrap at narrow widths. When the viewport cannot fit a usable result row, the exact total and full-results link stay available; this does not turn into a false no-results state. Nothing automatically opens another search surface.

For an explicit larger-search button, set modalHandoff: true in configuration.mjs, rebuild and use Open expanded search. It transfers the current header query into the existing native modal, sharing the page's owner, records and prefix mode. It adds no competing global shortcut or second engine. The default is false. The supplied build includes the modal code and explicit stylesheet so this switch can be tried without changing imports; its setup guide explains that cost and how the surfaces share ownership.

Keep the complete results route and browse links usable before loading, after a loading failure and without JavaScript. Rebuild and deploy the pages, content and assets together when changing the base or records.

Before using your own theme

Installed-consumer checks and the acceptance record describe the tested browser, lifecycle and emulated layout scope. Human screen-reader speech, physical IME/touch/on-screen keyboards, actual browser zoom and other browser/device combinations need separate checks in your application. See starter adoption and local checks. Playwright WebKit observations do not establish Safari support.
