## Construction and compatibility

A single unpublished `CoreDelta` retains its staged documents, field/term caches and postings across individually captured adds. Prospective dictionary entries are tracked as live counts and checked with all other state caps before that record's participants. One final charged seal constructs immutable directories and prefix order. This retains payload encounter order rather than introducing a sort.

Only the exact immutable registrations returned by the source/positions factories receive a private WeakMap factory. Normal descriptor/role/method capture transfers that proof to its captured registration; codec strings, equal methods and spread/wrapped registrations confer no proof. The first-party sessions reuse their existing source/occurrence retention helpers and one private directory stage, enforce every record's counters/caps/revisions, and seal once. Core and positions still analyze separately through the same operation-scoped runner; no token fusion or analyzer-purity assumption exists.

Other accepted registrations run their captured, bound public callbacks once per record with frozen singleton records, empty removed IDs, `add` kind and successive private revisions. Their state is not dropped or fabricated. Observable cursor `return()` remains attempted on success and failure and cleanup errors cannot replace the first outcome. Generic callbacks may still refuse under unchanged cumulative limits.

Record mutation and participant invocation meters remain local. The outer restore meter includes codec, analysis, construction, participant work, core/sidecar finalization and precommit. Each participant's cumulative meter spans all adds and its final seal; the final seal also has a local allowance and shares the outer meter. No final validation is moved outside the bounded operation. The existing authoritative root remains visible until one publication at receiver revision plus one. Worker/storage receipt protocols are unchanged.

## Measurements

Use the RX-8007 frozen installed archive as the untouched before package and a freshly packed changed runtime as after. The same current harness runs each side serially, with actual 1k/10k adversarial source and positions/offsets configurations. Node uses two ordinary fresh processes and one separate diagnostic process per size/profile. Chrome uses separate actual direct/module-worker realms, one ordinary and one diagnostic case per cell. The default operation deadline remains 60s, the separate forced-deadline probe 1ms, worker messages8MiB and responses 65s. Recorded typed refusals, cancellation, uncertainty and unavailable cases remain explicit.

Normal wall and Node process CPU exclude metadata, hash and postcondition work. Intrusive diagnostic runs label actual nested budgets, count actual yielded work/copies/produced tokens and collect bounded scalar stage/coexistence summaries. First-party intermediate sidecar observations are explicitly unsealed; they are not invented published roots. No historical roots are retained. Node unforced process samples include harness, inputs, donor and receiver and are neither retained nor continuous peak/exclusive-engine heap. Phase-event history is capped 128, phase samples occur once per label, and memory samples are capped 128. Browser CPU/heap are unmeasured.

Every successful restore is checked outside timing against the complete public source export with both checksums verified and only origin revision/integrity value normalized. Every all-query page is enumerated, including exact zero scores and ordinal ID ties; selected lexical/prefix/phrase pages preserve actual totals/scores/order. Separate diagnostic postconditions compare every core/reverse/dictionary/posting/statistic and source/position/offset datum, validate directory placement/sizes and AVL membership/heights/balance, and normalize only known root/sidecar revisions. Donor versus receiver encounter-order digests are reported separately because donor batch encounter order can differ from the source payload. Focused tests compare full native/source state against a sequential rebuild in that exact payload order and independently replay BM25/Inspector arithmetic.

Package inventories, harness hashes, actual browser assets and frozen workload hashes are retained. Collection guards require normal/diagnostic package and staged harness identities to remain stable. Failed exploratory attempts are kept separately and are not mixed into official before/after timings. Small sample medians are descriptive; no p95, universal platform speedup, physical-input/paint, screen-reader or publication claim follows.
