# RX-8009 — Paired native benchmark method

The [N9 contract](../specs/N9_PERFORMANCE_RECOVERY.md) owns this task. This is a benchmark/verification slice; it preserves the accepted, uncommitted RX-8008 runtime. No runtime optimization, cap, dependency, ranking identity, public API, publication or remote tracking change is part of it.

## Artifact comparisons

Every variant is a separate real offline installation of its actual archived private package. The untouched baseline is the verified RX-8001 `919c9ed` archive. Subsequent real archives represent candidate planning, continuation scheduling, ordered prefix seek, query-local ranking statistics and the combined bulk-restore candidate. The freshly built combined artifact must match every member of the accepted RX-8008 closing archive. All variants have the identical default limit module.

Adjacent pairs estimate **conditional incremental effects**, with preceding changes held in place: baseline→planning, planning→scheduling, scheduling→prefix, prefix→ranking, ranking→bulk. RX-8007 and RX-8006 runtime/declaration/CSS bytes are identical, so the ranking artifact is also the genuine pre-bulk runtime. Baseline→combined estimates the total observed change. These are not standalone-from-baseline effects or additive attribution. No surgical hybrid is manufactured from overlapping engine/search/delta/snapshot modules.

## Frozen workload and Node matrix

Inputs remain the nine RX-8002 family×size workloads: real-document excerpts, high-cardinality controls and adversarial multi-value controls, each at 100/1,000/10,000 admitted records. Thirty-four technical-document sections are repeated; they are not ten thousand independent real documents. Literal membership labels, vocabulary and source/schema/query/judgment hashes are checked against the frozen inventory.

The combined pair covers all nine cells. Each intermediate stage additionally runs all three adversarial sizes. This produces thirty stage/family/size cells and 96 fresh Node children:

- Adversarial100: three ordinary owners×forty measured calls/query after two discarded warmups; one separate diagnostic owner. Each query has 120 ordinary observations.
- Other cells: two ordinary owners×two calls/query, separately labeled first call for that query and repeated call on the same owner; one diagnostic owner. First call does not mean machine/filesystem cold start.
- Each owner builds through admitted batches of256, then measures the same eight lexical/Boolean/filter/prefix/source-phrase queries and separate source export/restore operations. A restore receiver contains one real prior record. Source export refusal makes restore **Not run**, with no invented latency or receipt. Known restore failures preserve exact prior source/revision and query observations. Successful restore checks complete source content/checksums, revision and removal of prior records outside timing.

All operation deadlines remain60s and all native work/admission/retention caps remain unchanged. Ordinary monotonic wall and process CPU user/system are separate raw measurements. Imports, fixture generation, expected-result checks, hashes and postconditions remain outside windows. Diagnostic copies alone receive the reviewed observer; actual candidates/evaluations/scorings, dictionary/posting visits, emitted work/steps/yields and restore phases are separate from ordinary latency. Diagnostics do not establish retained/peak heap. Owner/cell/variant order reverses on alternating rounds. Task-owned builds, tests and other measurements are held during serial collection; ordinary desktop/OS activity remains uncontrolled.

## Quantiles, errors and comparison rules

p50 and p95 are empirical nearest-rank order statistics. p95 is reported only for at least100 actual observations in the same labeled outcome/timing cell; other cells explicitly say **Not estimated**. Repeated calls across three fresh owners remain correlated and are not population/device tails. Build/export/restore samples have their actual small counts. Normal and diagnostic rows never pool.

Every raw refusal, cancellation, unknown or unavailable outcome remains visible. Completion-failure rates include intentional expansion-cap controls; they are not uncaught-error or reliability-defect rates. Summaries retain outcome denominators and failure rates; Not-run records have zero actual attempts and no measured times. Refusal times do not enter successful latency quantiles. A known work/deadline error versus success is an explicit capacity finding, not exact-success parity or an equal-work speedup ratio. Unknown transport observations never prove rollback. Any unexpected nonresource error or numerical/order/facet/trace mismatch fails comparison. If any actual successful reference exists, all other successes must match it; an earlier warmup refusal cannot hide later score drift.

## Selected actual browser/worker matrix

Each of the five adjacent intervention pairs and the combined pair uses headless installed Chrome at the frozen adversarial 100 size, with source retention and source phrases. Common, rare, narrow-prefix and source-phrase queries run in both actual direct and real module-worker execution. Three ordinary fresh owners×forty calls after two warmups yield120 observations/query/cell; one separate intrusive owner supplies same-realm work/yield diagnostics. Variant and execution order rotate. Full public pagination outside timing verifies each selected query. Ordinary/staged package inventories, verifier/harness source and executed app/worker/HTML bytes are guarded. Browser CPU and heap are **Not measured**. A recorded0ms quantile reflects the browser timer floor, not zero engine work; derived speed ratios are omitted when either quantile is zero. No Node/browser subtraction, physical-input/paint or larger-worker-query tail claim follows.

## Separate complete semantic lane

Full pagination at large sizes runs on the same installed implementations through their public facades, with a private deterministic queued host that drains continuations without real timer delay. This lane retains native data/work/admission limits and explicitly does not test elapsed deadlines or ordinary-host performance. Its results are not latency samples. Each of the thirty stage/family/size cells gets a fresh process. Every successful query captures all pages, exact membership against literal labels, global score/tie order, totals and revisions. Required resource refusals stay incomplete captures/findings; successful prefixes before refusal are not discarded or silently accepted as complete.

Selected Inspector/facet requests compare complete numerical and decision facts, independently replay BM25 arithmetic and retain actual resource work separately. Only known protocol revision headers and explicitly selected `Inspector.resources.searchWorkUnits` may normalize; user metadata named `revision` is data. Complete core/reverse/postings/statistics and source/position protocol contents compare canonically. The baseline has no derived `field.order`: it is marked absent, never fabricated. A present ordered tree must independently satisfy membership/order/height/balance. Derived tree shape is not wire data. Small literal source/positions/offsets/mixed/Unicode and later-mutation cases supply additional representation checks.

The installed independent source/policy/hand-score oracle, focused lifecycle checks, full repository/private-candidate verification and generated-site browser checks remain separate gates. A green benchmark does not imply remote CI, publication, general relevance, representative traffic, retained memory or universal speedup.
