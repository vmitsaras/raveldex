# RX-8007 — Bounded atomic source-rebuild contract for RX-8008

Status: source-reviewed proposal, 4 November 2026. Inspected source starts at committed `645ffbb0c72be7d4015f5af1270d869307e53be3`. This document diagnoses current code and constrains RX-8008; it implements no builder, changes no limit, and supplies no successful 10k-restore claim. Actual reproduction outcomes and environment/artifact identities belong to the [RX-8007 evidence](../evidence/RX-8007.md). Ordinary implementation choices inside these constraints do not require another approval gate.

## Current source facts

The [snapshot adapter](../../src/adapters/snapshots/snapshots.ts) runs one queued adapter operation against the execution-start root. Its `metered` wrapper charges the complete restore cursor to one `maxMutationWorkUnits` budget. The codec currently performs separate resumable UTF-8/decode, integrity, compatibility, staging and precommit phases. Decoder limits, duplicate-key checks and integrity are independent of whether the corpus can be admitted or rebuilt; an admitted producer does not establish that one whole restore fits the work/deadline budget.

`preparedSource` currently creates an empty private `MutationOwner`, shares one receiving `AnalysisRunner`, and loops through every decoded record with `owner.capture('add', record)` followed by `owner.execute(...)`. Each successful private add advances an intermediate private revision. Only after the complete private rebuild does `restoreCursor` rebase the core and all participant headers to the receiver's previous revision plus one and publish once. The original receiver remains authoritative throughout preparation. Successful empty restore is also a new local revision; origin revision is provenance, not the receiving revision.

The [mutation coordinator](../../src/core/mutations/owner.ts) validates/captures an individual record, prepares its reverse-frequency document, creates a new `CoreDelta`, finishes/seals its directories, invokes every participant and publishes another private root for every source record. [`DirectoryStage`](../../src/core/index/staging.ts) copies the original directory's occupied bucket pointers on first write, copies each touched bucket once per transaction, then enumerates/freezes touched buckets again at finish. The per-transaction cache prevents duplicate copies within one add; creating a new transaction for each record repeats these operations as the private corpus grows. Common-term postings, document/dictionary directories and each sidecar directory all participate. Ordered prefix-key maintenance is also charged when live terms first appear; it must remain coherent in a bulk path.

[Source retention](../../src/addons/phrases/store.ts) preserves selected original strings through its own staged directory. [Position retention](../../src/addons/positions/store.ts) calls the selected analysis runner again for each selected value to construct occurrences, optional offsets and its counters, then stages/seals its own directory. Sharing one runner scopes optional-analyzer work to the whole restore; it is not a token-result cache, so core and positions still perform separate analyses. Retaining source does not itself tokenize it.

There are several nested ceilings, not one freely resettable budget:

- The complete restore has one outer mutation-work budget, including codec work before staging.
- Every private add still has its own mutation budget.
- The snapshot wrapper holds one cumulative budget per participant over the whole rebuild, while the mutation coordinator also checks each participant invocation's local ceiling.
- Optional analyzer transform/tokenizer work has one operation-scoped runner budget, reused by core and provider reanalysis. Record/corpus, dictionary/posting, retained-source/position/offset and encoded-data limits remain separate.

The [initial-construction primitive](../../src/core/index/construction.ts) already owns mutable builders and seals at completion, but explicitly rejects configurations with capabilities. It is not currently a drop-in source/positions restore builder. Passing an empty capability set to make it accept selected add-ons, or rebuilding sidecars later without the original budgets, would omit behavior rather than repair the restore.

A `WORK_LIMIT_EXCEEDED` may happen in an inner budget before its failed step is emitted, or in the outer meter before emission. Emitted work therefore need not equal the numeric ceiling. A phase label at settlement and last emitted count cannot alone identify which nested charge rejected. `DEADLINE_EXCEEDED` is a separate elapsed-time outcome checked cooperatively by the host; it is not interchangeable with work refusal. A worker reply/storage observation may remain `Unknown` even when a later query observes the old root. A later query does not retroactively change the original receipt.

## Required replacement behavior

The RX-8008 objective is to remove repeated private reconstruction overhead while preserving the admitted source contract. It must not raise, bypass, reset or silently omit an existing ceiling to make a representative collection pass.

1. **Keep codec and admission semantics.** Preserve resumable decode, Unicode/UTF-8 validation, integrity, compatibility headers, complete-source requirement, participant codec checks, duplicate-ID/record validation and typed error mapping. Capture/validate records under the existing individual admission bounds; do not feed all records through public `addMany` or increase its batch/admission ceiling. A complete payload may contain up to `maxDocuments`, but this is not permission for one unbounded native operation.
2. **Own one unpublished reconstruction.** Begin from an empty private core and selected participant state. Reuse transaction-local native builders/caches across admitted records where this avoids repeated directory/posting/sealing work. Charge actual ID/text/metadata analysis, counts, dictionary/posting updates, prefix order, sidecar construction and final sealing. New owned loops must yield under the existing scheduler; native operations remain bounded by admitted data and require explicit cost accounting. A bounded number of native Map or allocation operations is not a hard constant-time or physical-paint guarantee.
3. **Preserve exact state.** Produce the same receiving-analyzer reverse terms, TF/DF/frequency, positive-length field populations, corpus counts and deterministic search arithmetic. Preserve metadata canonicalization, source field absence versus empty arrays/values, original value order, IDs and source strings. Positions must retain exact value boundaries, ordinals, repeated terms, v1/v2 tags, `positionLength`, optional original UTF-16 offsets and all retained-entry/occurrence/term counters. Preserve payload encounter order wherever native directory/trace order makes it observable; do not introduce an unrelated canonical sort.
4. **Scope analysis correctly.** Use the receiver's selected analyzer and one whole-operation work scope. Raw source is analyzed; normalized dictionary terms never reenter the raw analyzer. Token reuse/fusion may remove duplicate analysis only where equivalence of the selected actual implementation is established and the occurrence/source semantics remain exact. A manifest string does not prove arbitrary implementation handles are pure or interchangeable.
5. **Keep whole-operation and participant budgets.** Decode, integrity, validation/admission, construction, sidecars, finalization and required precommit checks all join the same outer restore budget. Keep cumulative per-participant and selected-analyzer work ceilings across every internal chunk; do not reset them after each append. Retained-state bounds apply as state grows and to the finished state. Final checks cannot be moved outside the measured/bounded operation solely to obtain success. Removing redundant copies reduces actual work; reducing charges while executing the same work is not the intended optimization.
6. **Verify coherence before publication.** Validate all input records and every selected representation under its existing protocol. Core and source/position structures, counts, revision/analyzer headers and prefix order must agree when sealed. Construction-time invariants can establish coherence without inventing a redundant full reanalysis pass; any check that remains necessary must be charged and stoppable. Independent tests must compare exact complete source/index/sidecar outputs, not merely a top-20 result count. Native v1 wire shape, codec/index/ranking identities and later native validation/export must continue to work.
7. **Publish once.** Build the final rebased core/participant root and response before the last precommit check. Use the existing FIFO adapter publication with the same configuration pointer, expected prior root and exactly `old.revision + 1`. There is no yield, callback, stop check, allocation or possible failure after the successful publication point. A later abort/dispose cannot revoke a committed receipt. Empty restore and revision exhaustion retain their existing semantics.
8. **Abandon cleanly.** Invalid data, work/retention refusal, participant/analyzer failure, abort, deadline and disposal must discard unpublished reconstruction, close active child generators/handles and release staging ownership while preserving the first typed outcome. The old root and its selected sidecars remain authoritative. The engine must remain usable for later queued/read/write operations unless it was disposed.
9. **Keep adapters honest.** Worker elapsed transport/admission time continues to consume the admitted deadline. Explicit authoritative worker failure, committed reconciliation and unobserved/lost reply remain distinct. IndexedDB selected generation/conflict and `OUTCOME_UNKNOWN` behavior must not be converted into blind retries or assumed rollback. The builder need not introduce a new persistence layer or transport protocol.

## Participant compatibility boundary

The current registration layer captures and binds supplied trusted `initialize`/`prepare` functions. Codec IDs and worker-registration strings are data declarations; they do not prove the functions are the first-party source/positions implementations. Generic participant callbacks currently receive one record and successive private revisions during source rebuild. Calling every arbitrary callback once with all 10k records, silently bypassing it, or manufacturing a larger public mutation batch would change observable callback/context/budget semantics.

RX-8008 must choose and document a compatible private strategy. A first-party bulk fast path needs explicit implementation provenance or an equivalent private opt-in that survives trusted capture; a declarative codec string alone is insufficient. Unsupported codecs must continue to fail explicitly. Accepted registrations outside that fast path need a bounded compatibility route preserving their original behavior and cumulative budgets; they may still refuse. No selected state may be silently dropped. A private optional seam is an ordinary implementation choice if it preserves the public registration contract and package/import boundaries; expanding that public contract is a separate load-bearing choice.

This requirement does not prescribe a new brand registry, new public add-on role or persistence format. The smallest verified mechanism should be selected after actual phase/copy/analysis evidence shows which work must be removed. A generic bulk core stage alone can be evaluated, but it must not claim sidecar-copy savings that it does not implement.

## Coexistence and memory contract

Preparation necessarily permits the encoded string, decoded graph/body text, authoritative old root, private new core and private source/position state to coexist. A producer retained by a reproduction harness can add another independent root; a worker transport can add strings/structured clones in another realm. These references must be identified explicitly in measurements. An observer that stores every intermediate root would itself create retention and cannot be used as ordinary-memory evidence.

The proposed builder must remain bounded by existing admitted limits and release superseded intermediate builder ownership promptly. It should avoid retaining an additional full copied corpus or every historical private root merely for convenience. No streaming-decoder rewrite is required by this slice; retaining the already bounded decoded payload is allowed and must be disclosed. Encoded UTF-8 bytes, UTF-16 code units, logical records/entries and copied-key counts are not heap bytes. A sampled process `heapUsed`/RSS maximum is an observed sample, not a continuous peak or engine-only retained heap. Inspector/CDP worker samples and Node samples are separate configurations and must not be subtracted to invent transport overhead. Forcing GC or sampling hooks belongs in separate explicitly intrusive diagnostic collection, not ordinary timing.

## Status and unresolved implementation details

Source inspection establishes the repeated-transaction mechanism and the existing safety boundaries. It does not establish the exact measured contribution of copying, tokenization, codec work, participant ceilings or host delay in a particular refusal; RX-8007 diagnostic artifacts must establish that. Concrete fast-path eligibility/provenance, builder reuse, budget attribution and any token fusion remain RX-8008 implementation decisions within this contract. Measurements may show that one representation still cannot meet an unchanged ceiling; that is a real limitation, not permission to omit validation or state.
