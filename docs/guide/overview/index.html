Getting started

Raveldex adds search to data you already have. Tell it which fields to search, add your records and use the matching IDs to look up titles, URLs or other details in your application.

Install the package

The packages are currently unpublished and supplied as local .tgz files. In a new application directory, run these commands to create a package, enable ESM imports and install core. Replace the absolute path with the file you received or built:

npm init -y
npm pkg set type=module
npm install --offline --ignore-scripts --no-audit --no-fund /absolute/artifacts/core/vmitsaras-raveldex-0.1.0-rc.0.tgz

You can now import @vmitsaras/raveldex in that application. Core and the English analyzer require Node 22 or later; the Astro integration requires Node 22.12 or later. In a browser application, let your existing bundler resolve the imports. See compatibility for optional feature requirements.

Smallest core example

Save the following as search.mjs beside your application’s package.json, then run node search.mjs. It indexes a single document and searches for atomic.

import { createRaveldex } from '@vmitsaras/raveldex';

const engine = createRaveldex({
  schema: { text: { title: { boost: 2 }, body: {} } },
});
try {
  await engine.add({
    id: 'guide:updates',
    text: { title: 'Atomic updates', body: 'Replace one complete record.' },
  });
  const result = await engine.search('atomic');
  console.log(result.total); // 1
  console.log(result.hits[0].id); // guide:updates
} finally {
  await engine.dispose();
}

The example prints 1 and guide:updates: one document matched, and that is its ID. It then disposes the engine.

A few details matter when you add more records:

  • boost: 2 gives matches in the title more weight than matches in the body.
  • total counts every matching record; hits contains the requested page of IDs and scores.
  • Keep your display data in your application and look it up by ID.
  • Plain string searches require every complete term. atomic updates matches the title above; atom does not. Use a prefix query to match the beginning of a word.

Update your collection

Use the method that matches the change you want to make:

  • addMany adds a batch of new records.
  • replace replaces one complete record.
  • remove deletes records by ID.
  • clear empties the collection.

Await an update before searching when the results need to include it. Each successful change creates a new collection revision, and each search result tells you which revision it used. See records, mutations and query shapes.

Add a search interface

For a complete project to adapt, choose a browser or Astro inline starter. Each includes explicit sample content, source snippets, a topic filter, paging, CSS, loading/retry and cleanup. The browser starter builds an engine from its records; Astro builds static search artifacts and loads them on demand. Both use the current local tarballs.

For search behind a button, choose a documentation modal starter. The browser and Astro projects include cancelable first-open loading, real page/heading links, retry, query preservation and owned-engine cleanup. Replace their explicit authored content and adjust the theme CSS.

Both galleries provide complete project downloads and a short edit/build/preview CSS walkthrough. Keep the starter’s source/snippet/facet or section registrations aligned with its UI options; these are explicit optional capabilities. The adoption checklist lists browser requirements, ownership and the remaining checks to run after replacing data or styles.

The native DOM UI adds a labeled search field, results and pagination to an element you provide. Import its CSS separately. You still own the engine: remove the UI with destroy() before disposing that engine.

If you want phrases, snippets or highlights, choose the required source or position providers when creating the engine. These keep the original text or word locations that core alone does not store. For static Astro pages, follow the Astro guide.

Build tarballs from a source checkout

You only need this step if you are building the packages yourself. With repository access, Node 24 and npm, run the following from the repository root. It compiles the code once and creates matching core, English and Astro tarballs:

export RAVELDEX_REPOSITORY="$(pwd -P)"
export RAVELDEX_ARTIFACTS="$(mktemp -d "${TMPDIR:-/tmp}/raveldex-artifacts.XXXXXX")"
npm ci
npm run build
mkdir "$RAVELDEX_ARTIFACTS/core"
npm pack --ignore-scripts --pack-destination "$RAVELDEX_ARTIFACTS/core"
node scripts/pack-english.mjs --output "$RAVELDEX_ARTIFACTS/english"
node scripts/pack-astro.mjs --output "$RAVELDEX_ARTIFACTS/astro"

The files are written beneath $RAVELDEX_ARTIFACTS, in core/, english/ and astro/. Each pack output directory must be new. You can now install those files in a separate application.

Keep both shell variables set when following the Astro example. Install the matching core tarball alongside either optional package. The Astro build hook also needs astro@7.3.2.
