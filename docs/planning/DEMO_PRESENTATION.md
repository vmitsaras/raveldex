# Modern consumer demos

The owner selected modernization of all five consumer examples after the header
modal. This includes the gallery pages, their real installed previews and all
eight downloadable browser/Astro starters. Preserve the existing functionality,
sample records, IDs, routes, labels used to operate the controls and native
results. This is presentation work, not a new search API or retrieval strategy.

## Direction

Use the header modal as the visual reference: neutral white surfaces, restrained
gray backgrounds/borders, system typography, blue links/focus, readable spacing
and consistent control sizes. Keep the purpose of each interface clear. Show the
live example before detailed installation/reference prose. Avoid decorative
eyebrows, dense technical introductions, nested cards and heavy borders. Keep
dark and forced-color support where already offered. Style loading, empty,
error/retry and disabled controls with the same care as populated results.

Every standalone starter must remain self-contained. Theme its real public
component with existing properties and styling hooks; do not substitute static
mock results, introduce dependencies or import an external shared demo theme.
Keep semantic HTML, native keyboard models, visible focus, reduced motion,
composition, state/URL replay and UI-before-owner cleanup. No core or public UI
API change is selected.

## Work and ownership

- Inline/modal worker owns presentation files in the four matching starter
  directories. Dropdown worker owns dropdown starter presentation. Directory/
  cards worker owns their three matching starter directories. These writes are
  disjoint; workers do not build shared output or edit planning/generated files.
- Parent owns the shared gallery presentation, five gallery sources, build input
  inventory, all planning/evidence, integration and final verification.
- An independent read-only reviewer checks the combined result after integration.
  No nested delegation or remote delivery is included.

## Acceptance and checks

1. All five galleries prioritize the live example and make the full-page preview,
   family switcher and complete starter downloads easy to find.
2. All eight standalone projects have coherent, modern presentation and usable
   search, result links, states and narrow layouts without changing native
   results, capabilities or lifecycle contracts.
3. Browser/Astro themes remain equivalent where both exist; exact source/archive
   generation, root/subdirectory builds and independent result/focus checks pass.
4. Inspect actual desktop/320px renders across all five families. Exercise modal
   loading/open/close, dropdown handoff, directory filtering/URL state and cards
   layouts/density/images. Check existing keyboard/composition/recovery, dark,
   forced-color and reduced-motion cases at the affected layer.
5. Run one complete candidate verification, regenerate Pages with that build,
   run the complete site regressions and retain actual identities and limitations.
   Human AT, physical input, actual zoom and owner visual acceptance remain
   distinct from browser automation and screenshots.

Preserve the existing uncommitted header-modal implementation. No commit/push,
publication, deployment, tag/release or GitHub mutation is authorized here.
