## Known behavior and practical limits

`basic-v1` is lexical NFKC/lowercase analysis with exact AND plain strings. It supplies no stemming, semantic paraphrase, accent stripping, automatic final-word prefix, typo tolerance, infix or query-string language. In [RX-4001's frozen 76-query documentation evaluation](https://github.com/vmitsaras/raveldex/blob/main/docs/evaluation/RX-4001.md), all eight natural questions returned empty; vocabulary/word-form differences also missed intended answers. This small, incompletely labelled English technical corpus is not a general relevance guarantee or an overall winner against the companion comparator. Optional source/position/mixed phrase strategies preserve the same membership/order/native scores for their tested equivalent configurations.

The 10,000-document ceiling is a bound, not a guarantee that every permitted document collection fits every operation. Core admission, dictionary/posting, structure, work, encoded-size, queue and deadline limits also apply. In RX-4001, three 10,000-record source rebuilds rejected `WORK_LIMIT_EXCEEDED` while preserving prior state. Its browser worker restores rejected `DEADLINE_EXCEEDED`; storage loads returned two authoritative deadline errors and one `OUTCOME_UNKNOWN`. A later query observing prior receiver state does not retrospectively turn an unknown load outcome into confirmed rollback or success. Later intrusive RX-4002 large source rebuilds also retain actual deadline refusals. Batches can build a collection that a single whole-source restore cannot rebuild within the same per-operation budget. Prefer native snapshots only within their separately qualified exact runtime, or design explicit application recovery around the refusal.

The fixed core measured in RX-4001 is **55,345 minified bytes / 16,829 gzip bytes**, 1,469 gzip bytes above the unchanged **15 KiB planning target**. This miss remains disclosed under the repository's reviewed target policy. Optional graph sizes overlap and cannot be summed into an application total. Candidate packaging changes do not establish a runtime size reduction; the final candidate check records its actual selected graph. See [cost method and observations](https://github.com/vmitsaras/raveldex/blob/main/docs/evaluation/RX-4001-cost-method.md).

Transport failure can leave mutation/restore outcomes unknown. Reconcile within the surviving session/receipt window and keep authoritative application source for explicit new-owner recovery. The native UI currently presents worker transport errors through generic `INTERNAL_ERROR` text, while the adapter retains its actual typed error separately. This is a disclosed presentation limitation. No hidden fallback engine, automatic retry, persistence or recovery obscures outcomes.

The recorded Safari/VoiceOver flows include result reading/editing, facets, empty/error/retry, worker recovery, Inspector and teardown. The [physical-session reconciliation](https://github.com/vmitsaras/raveldex/blob/main/docs/evidence/RX-4002-native-events-20261027.md#physical-session-and-at-disposition) binds built-in keyboard/trackpad, recorded 400% Safari zoom and the named 16-inch MacBook Pro / Apple M5 Pro / 24 GB built-in-display scope; dead-key battery/Automatic power context remains explicit. No physical paint/latency, larger interactive workload or NVDA qualification is claimed.

## Memory evidence means its measured quantity

RX-4002 completes its finite retained/peak/component/process requirements through separate methods. Selected-data reachability/graph cuts, process RSS, browser main/worker realm readings, old/candidate root coexistence and cleanup have their own scopes. The final continuation adds 36 selected valid codec windows and preserves invalid/null attempts and rejected operations. Managed occupied extents come from an explicitly modified, calibrated Node/V8 allocation mode and include host/harness work; its timing/Unicode build profile does not qualify normal Node or browser runtime behavior universally.

Repeated actual Chrome 153.0.8010.12 native worker-message observations report requested wire-capacity high-waters of **115,400 bytes at 1,000 records** and **1,016,016 bytes at 10,000**. These are tracked native buffer extents/frontiers, separate from worker heap and physical/global memory. Unknown receiver routes, complete physical payload-copy totals, stopped forced-allocator controls and stronger global claims remain unqualified. Encoded bytes, sampled heap maxima, logical work counts and animation-frame timing are not substitutes for the quantities they do not measure. See the [completed method and independent review](https://github.com/vmitsaras/raveldex/blob/main/docs/evidence/RX-4002-gc-shrink-20261028.md) and [memory-method record](https://github.com/vmitsaras/raveldex/blob/main/docs/evaluation/RX-4002-memory-method.md).

## Reporting and support expectations

Use the [repository issue tracker](https://github.com/vmitsaras/raveldex/issues) for a reproducible candidate defect. Include the installed version/tarball identity, exact runtime/browser/OS, selected entrypoints/providers, reduced schema/records/query, expected versus actual result and typed error/receipt. For UI/AT reports, distinguish key actions, DOM focus and owner-heard speech, with exact settings where known. Redact application source and identifiers before sharing Inspector diagnostics or snapshots. No paid service, telemetry or automatic remote reporting is built into the candidate, and no response-time/SLA is promised.

Deferred N5 ideas are not missing candidate prerequisites. Publication, release tags and a public package announcement remain the owner's separate decision after the [release recommendation](../release/CANDIDATE.md).
