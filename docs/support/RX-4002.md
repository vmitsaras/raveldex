## Memory and resource scope

The [memory method](../evaluation/RX-4002-memory-method.md) defines the measured realm/process, harness baseline, garbage collection, cleanup, repetitions and instrumentation. Measured reachable self-size, recorded-graph node-cut effects, process heap/RSS and observed maxima retain their own meanings. The offline node cuts use existing dumps and remove every alias to a selected node; they do not establish actual V8 collection or allocation peaks. Encoded bytes and logical work/object counts remain separate. A scope that the method cannot isolate stays Blocked; it receives no guessed allocation total.

The separate [headless Chrome continuation](../evidence/RX-4002-memory-browser.md) observes actual main/worker isolate heap fields and statistical allocation profiles for source-phrase worker build, replacement, source export and receiving reindexing at admitted 1,000/10,000 sizes. It retains deadline refusals with prior-state verification. These observations do not qualify Safari/Firefox memory, native browser snapshots, exact exclusive component retention, simultaneous peaks, combined process memory or hidden clone-buffer ownership/copy counts. The owner’s accepted Safari/VoiceOver/input flows are separate evidence.

The [observer-held root continuation](../evidence/RX-4002-memory-collection.md) adds actual root-release observations after public disposal. Its descendant-byte experiment exposes incompatible objects under the same snapshot ID; all corresponding byte interpretations remain Blocked and quarantined. Root WeakRefs, snapshot graph arithmetic, statistical profiles and transport shapes retain distinct meanings. Completion is judged against the actual contracts, not an extra mathematical “every VM byte” requirement; broader staging/codec allocation peaks and separately measured transport work/peak copies still require evidence. The [actual mutation continuation](../evidence/RX-4002-memory-mutation.md) now binds old/candidate/shared state at native precommit and listed root/document cleanup for core, source/phrase and positions/offsets at both admitted sizes. Its one-dump graph quantities are distinct from allocation peaks, collector retention and browser memory.

The [native codec continuation](../evidence/RX-4002-memory-codec.md) directly observes source-phrase native encoding chunks, string backing, decoded objects and receiving reuse at both sizes. It uses one paused intrusive producer/receiver run per size, independent same-snapshot reconstruction and listed-object cleanup checks. Its state/codec membership and string-node quantities do not establish synchronous allocation high-water or physical product transport copies.

The [correlated transport continuation](../evidence/RX-4002-memory-transport.md) observes actual named native serialization/deserialization elapsed intervals in six fresh Chrome 156 processes, separately from worker heap. It preserves all source-restore deadline refusals and prior-state checks. Serialization-named wrapper/type dump aggregates do not identify per-message native buffers or peak physical copies, so the existing peak-copy requirement remains Blocked. This does not replace the historical Chrome 155 observations or qualify total adapter CPU/cost.

All resource experiments stay at or below 10,000 admitted records and the unchanged work/deadline/transport ceilings. Typed bounded refusals remain operation outcomes. A successful 10,000-record build does not promise that every subsequent snapshot/recovery/query combination succeeds under the same ceilings. The 15 KiB gzip target remains unchanged and its existing miss remains visible.
